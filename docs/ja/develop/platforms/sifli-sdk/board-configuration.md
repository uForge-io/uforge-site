# ボード設定 { #board-configuration }

ボード設定は、ファームウェアの設定を実際のハードウェアに合わせるためのもので、Flash配置、PSRAM、ピン、ディスプレイインターフェース、オーディオ経路、クロック、電源レール、既定の周辺機器を扱います。

SiFli-SDKでは、`--board=<board_name>`が最も重要なビルド入力です。この値によって、サンプルが使用するボードサポートパッケージが選ばれます。

デュアルコアボードでは、コアのサフィックスを省略すると、デフォルトでHCPUの構成が選択されます。LCPU向けにビルドするにはボード名に`_lcpu`を付け、HCPUを明示するには`_hcpu`を付けます。選択したコアがサンプルでサポートされていることも確認してください。

## ボード選択によって変わり得る項目 { #what-the-board-name-controls }

選択したボードによって、次の項目が変わる場合があります。

- チップとパッケージのバリアント。
- FlashとPSRAMの配置。
- HCPU/LCPUのビルドターゲット。
- ピン多重化と周辺機器の利用可否。
- UARTのダウンロード設定。
- ディスプレイとタッチの設定。
- オーディオコーデックの経路。
- Bluetoothの設定。
- パーティションテーブルと起動時の前提条件。

## 実務上のルール { #practical-rules }

- 製品のマーケティング名からボード名を推測しない。
- ZephyrやArduinoのボード名をSiFli-SDKに流用しない。
- GPIO、ADC、PWM、I2C、SPI、ディスプレイのリソースを選ぶ際は、ボードの回路図または開発キットのページを確認する。
- 同じボード向けの最も近いSDKサンプルから始める。
- ボードを切り替えた後はクリーンビルドする。

## ボード立ち上げチェックリスト { #board-bring-up-checklist }

- [ ] チップのバリアントとパッケージを確認する。
- [ ] FlashとPSRAMの種類、容量、構成を確認する。
- [ ] 電源と充電器の動作を確認する。
- [ ] このボードで使用するクロック源と周波数を確認する。該当する場合は48 MHzと32.768 kHzも確認する。
- [ ] ダウンロード用UARTとログ用UARTを確認する。
- [ ] ディスプレイとタッチのインターフェースを確認する。
- [ ] オーディオを使う場合、その経路を確認する。
- [ ] 起動ピンとリセット動作を確認する。
- [ ] パーティション配置を確認する。

手元にあるハードウェアとボード設定が一致するまでは、アプリケーションのデバッグを始めないでください。

SiFli-SDKではSDKの識別子を`--board`に指定してください。製品名はビルド識別子として使えません。

## カスタムボードへ移植する場合 { #when-porting-to-a-custom-board }

最も近い開発キットまたはモジュールの設定を基に、次の項目を変更します。

1. FlashとPSRAMの設定。
2. ピン多重化。
3. コンソール／ダウンロード用UART。
4. ディスプレイ／タッチ／オーディオのリソース。
5. 電源と充電器の前提条件。
6. パーティション配置。
7. 製品固有の周辺機器。

変更ごとに、その機能を動かす最小構成のサンプルで検証してください。
