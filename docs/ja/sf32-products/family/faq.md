# SF32 FAQ { #sf32-faq }

## 製品の選定 { #choosing-a-product }

### どのSF32ファミリーを選べばよいですか？ { #choosing-a-family }

まず、次の重要な選定条件を整理してください。

- **表示解像度:** 必要な画素数、表示インターフェース、更新速度、フレームバッファー容量。
- **Bluetoothモード:** BLEのみか、BLEとClassic Bluetoothのデュアルモードか。
- **GPIO数:** インターフェースとメモリーへの割り当て後に使用できるピン数。
- **パッケージ寸法:** フットプリント、ピンピッチ、PCB実装要件。
- **電源:** バッテリーまたは安定化電源、動作電圧範囲、I/Oレベル。
- **オーディオ機能:** マイクチャンネルを含むADC/DAC、I2S、PDMの要件。

ファミリー番号だけでなく、具体的な型番を比較してください。番号が大きい製品が必ずしも最適とは限りません。これらの要素はすべて[製品選定ツール](../product-selector.md)の絞り込み条件です。条件を設定して、候補となる型番を絞り込んでください。

[ファミリー比較](SF32_family.md) · [製品選定ツール](../product-selector.md)

### チップ、モジュール、開発ボードのどれを使うべきですか？ { #chip-or-modules }

開発ボードはプラットフォームの評価とファームウェアの検証に使います。モジュールを製品用キャリア基板に実装すれば、RF、水晶振動子、メモリーの配線作業を減らせます。開発コスト全体の削減にも役立ちます。比較的少量生産の製品では、モジュール内部の部品調達をモジュールメーカーに委ねられます。また、地域によってはモジュールのRF認証が役立つ場合があります。コスト、寸法、設計自由度の利点が、回路図、レイアウト、RF設計を自社で担う負担を上回るなら、チップ単体設計を選びます。どちらを選んでも完成品の検証は必要です。モジュールは提供開始に合わせて順次掲載します。

[製品計画](product-planning.md)

### どの開発ボードから始めればよいですか？ { #choosing-a-board }

対象ファミリー向けのLCD評価ボードから始めてください：[SF32LB52-DevKit-LCD](../devkits/SF32LB52-DevKit-LCD.md)、[SF32LB56-DevKit-LCD](../devkits/SF32LB56-DevKit-LCD.md)、[SF32LB57-DevKit-LCD](../devkits/SF32LB57-DevKit-LCD.md)（N32R16メモリー版）、[SF32LB58-DevKit-LCD](../devkits/SF32LB58-DevKit-LCD.md)（N16R32N1版）。SF32LB52xには、小型の[SF32LB52-DevKit-Core-3p3](../devkits/SF32LB52-DevKit-Core-3p3.md)、[SF32LB52-DevKit-Nano](../devkits/SF32LB52-DevKit-Nano.md)、[SF32LB52-DevKit-ULP](../devkits/SF32LB52-DevKit-ULP.md)（ウェアラブル向け低消費電力評価）もあります。ボードのメモリー構成が対象型番と一致するか確認してください。全ボードの一覧はSiFli公式のボード型番ガイドにあります。

[製品選定ツール](../product-selector.md) · [公式ボード型番ガイド](https://wiki.sifli.com/en/board/devkit_guide.html)

### チップとモジュールの型番はどう読みますか？ { #reading-part-numbers }

ファミリーの接頭辞だけでなく、注文コード全体を確認してください。チップのコードはデバイス、パッケージ、メモリー構成を区別し、モジュールの接尾辞は実装されたストレージとメモリーを示します。命名規則の例と旧来の例外を確認し、注文可能な構成を供給元に確認してください。

[SF32命名規則](SF32_namingrule.md)

## メモリーと仕様 { #memory-and-specifications }

### SRAM、PSRAM、Flashの違いは何ですか？ { #memory-types }

SRAMとPSRAMは実行時データを保持しますが、電源が失われるとデータを保持できません。データ保持モードへの対応はデバイスによって異なります。チップ内SRAMと外付けまたはパッケージ内蔵のPSRAMでは、アクセス経路、帯域幅、消費電力が異なります。Flashはファームウェアやアセットを保存する不揮発性メモリーです。Flashを増やしても作業用RAMの不足は解消しません。

[メモリーの種類](../../learn/architecture/psram-and-memory-types.md)

### アプリケーションに必要なメモリー容量はどう見積もりますか？ { #sizing-memory }

作業用RAMは、OS、スタック、ヒープ、グラフィックスバッファー、オーディオ、その他の並行タスクに必要な容量を見積もります。基本的なフレームバッファー容量は、幅 × 高さ × ピクセル当たりのバイト数 × バッファー数で算出し、行ストライドのアラインメントと追加の描画バッファーも考慮してください。ファームウェア、フォント、画像、オーディオ、ファイル、OTAイメージ用の不揮発性容量は別に見積もり、想定負荷でのピーク使用量を測定してください。

[グラフィックス概要](../../learn/graphics/overview.md) · [製品計画](product-planning.md)

### NOR、NAND、eMMCはどう選びますか？ { #choosing-storage }

起動経路、必要容量、アクセスパターン、ソフトウェア対応を基準に選びます。NORは一般にコード保存やランダム読み出しに使われます。NANDでは、消去ブロック、ECC、不良ブロックを適切に管理する必要があります。eMMCにはストレージ管理コントローラーが内蔵されています。ここで紹介するモジュールではSPI-NANDとQSPI-NANDは同じストレージ選択肢を指しており、製品間の不一致ではありません。対象デバイスのブートローダー、ドライバー、ファイルシステムが対応しているか確認してください。

[メモリーの種類](../../learn/architecture/psram-and-memory-types.md) · [モジュール接尾コード](SF32_namingrule.md#module-naming)

### ファミリーに記載された機能はすべての型番で使えますか？ { #family-versus-sku }

いいえ。ファミリー概要は複数の型番の機能をまとめている場合があります。メモリー、電源条件、使用可能なピン、外部インターフェースはSKU、パッケージ、多重化に依存します。チップにある周辺機能がモジュールやボードから引き出されているとは限りません。型番別表、データシート、ピン配置と必要機能のSDK対応を確認してください。

[ファミリー比較](SF32_family.md) · [製品選定ツール](../product-selector.md)

## 用途への適合 { #application-fit }

### ディスプレイに合うデバイスはどう選びますか？ { #choosing-a-display }

まずパネルの電気的インターフェースとタイミングを確認し、解像度、画素形式、目標リフレッシュレート、フレームバッファー容量、帯域幅を照合します。最大解像度だけでは滑らかな表示を保証できません。必要なグラフィックスアクセラレーションとパネルドライバーを確認し、想定するメモリー構成で代表的な画面やアニメーションを試してください。

[デバイスごとのインターフェースマトリクス](../../learn/graphics/display-controller.md#per-device-interface-matrix) · [ディスプレイコントローラー](../../learn/graphics/display-controller.md) · [グラフィックス概要](../../learn/graphics/overview.md)

### オーディオとマイクの対応はどう確認しますか？ { #audio-and-microphones }

アナログオーディオにはADC/DACのチャンネル数、デジタルオーディオ機器にはI2S、デジタルマイクにはPDMの対応を確認します。一つのPDMインターフェースで最大二つのマイクチャンネルを扱えますが、インターフェース数とマイク数は同じではありません。使用できるチャンネル数は、ピンの引き出し、多重化、ドライバー、基板配線にも依存します。インターフェース数を単純に合算せず、目的の構成で確認してください。

[オーディオ概要](../../learn/audio/overview.md) · [用語集](../../about/glossary.md)

### BLE、Classic Bluetooth、または両方に対応する製品はどれですか？ { #bluetooth-modes }

SF32LB55xはBLEのみです。SF32LB52x、SF32LB56x、SF32LB57x、SF32LB58xはデュアルモードBluetoothに対応します。ただし無線機能があっても、すべてのSDK構成で全プロファイル、コーデック、機能が使えるとは限りません。必要なプロファイルと検証済みサンプルを確認してください。BLE対応だけではClassic BluetoothオーディオやBLE Audioへの対応は判断できません。

[ファミリー比較](SF32_family.md) · [Bluetooth概要](../../learn/bluetooth/overview.md)

### 外付けWi-Fiデバイスは必要ですか？ { #wifi }

ここに掲載しているSF32製品にはWi-Fi無線機能が内蔵されていません。選定ツールのWi-Fi項目は、SDIOを使う外付け構成を示します。外付けデバイスには、適切な電源、ピン、ドライバー、ネットワークソフトウェアも必要です。SDIOに対応しているだけでは、Wi-Fiが動作することの証明にはなりません。

[製品選定ツール](../product-selector.md)

### 実際に使えるGPIOはいくつありますか？ { #usable-gpios }

対象のパッケージとメモリー構成を基準に、必要なインターフェースとボード機能に割り当てるピンを差し引きます。モジュールではチップの一部のピンだけが外部に出ています。SF32LB57x BGA112の追加MPI3／静的出力ピンは用途が制限され、自由に割り当てられるGPIOではありません。公称ピン数をそのままアプリケーション用GPIO数にしないでください。

[ファミリーGPIO注記](SF32_family.md) · [SF32LB57xの型番](../chips/SF32LB57x.md)

## 供給と製品計画 { #availability-and-product-planning }

### モジュールの規制表示は自社製品にとって何を意味しますか？ { #module-markings }

モジュールページのラベル一覧で対象型番を確認し、該当する承認文書と組み込み条件を入手してください。FCC識別番号やCEマークが印字されていても、それだけで完成品が認証の対象になるとは限りません。アンテナ、キャリア基板、筐体を変更する場合は、適用条件に照らして確認してください。

[52モジュールの表示](../modules/SF32LB52-MOD-1.md#regulatory-markings) · [56モジュールの表示](../modules/SF32LB56-MOD.md#regulatory-markings) · [58モジュールの表示](../modules/SF32LB58-MOD.md#regulatory-markings)

### 別のメモリー構成やモジュールを依頼できますか？ { #custom-configurations }

対象チップまたはモジュール、ストレージとPSRAMの容量、インターフェース、アンテナ要件、予定数量、希望日程を添えてμForge.ioにお問い合わせください。設計確定前に、実現性、SDK対応、最小注文数量、納期を確認してください。古い資料に記載された構成が現在入手できるとは限りません。SF32LB58-MOD-E4R32N1は、メモリーチップの供給不足により現在入手できません。

[μForge.ioへのお問い合わせ](../../about/contact.md) · [58モジュールの供給状況](../modules/SF32LB58-MOD.md#storage-interfaces-and-module-variants)

### 供給状況とサンプルの入手先はどう確認しますか？ { #samples-and-documentation }

対象製品ページの購入先と資料へのリンクを参照し、供給元には完全な注文コードと必要な改版を伝えてください。現在の供給状況、メモリー構成、アンテナ方式、納期を確認します。可能であれば対応する評価ボードから始め、最終的な設計根拠にはファミリー概要ではなく対象型番の公式資料を使ってください。
