# 전원 관리 { #power-management }

전원 관리는 동작하는 프로토타입을 웨어러블 제품에 필요한 수준으로 끌어올립니다. SF32의 전력 최적화 작업은 클럭 구성, 슬립 모드, 디스플레이 동작, Bluetooth 연결 간격, 센서 인터럽트, 애플리케이션 아키텍처에 걸쳐 있습니다.

개별 코드 조각만 보고 전력 최적화를 판단하지 마십시오. 부팅, 유휴, 연결 상태의 유휴, 디스플레이 켜짐, 오디오 동작, 센서 웨이크업, OTA, 종료와 같은 제품 시나리오에서 측정하십시오.

## 실무 워크플로 { #practical-workflow }

1. 수정하지 않은 SDK 예제를 측정합니다.
2. 서브시스템을 한 번에 하나씩 활성화합니다.
3. 초기 측정 중에는 디스플레이, Bluetooth, 오디오, 스토리지, 센서 활동을 서로 분리합니다.
4. 폴링 대신 인터럽트 기반 웨이크업을 사용합니다.
5. 모드별, 제품 시나리오별로 소비 전류를 기록합니다.

## 유용한 시작점 { #useful-starting-points }

- SDK 전원 예제.
- CPU 사용률 프로파일링.
- RT-Thread 셸 점검.
- 보드 수준의 전류 측정.

## 측정 참고 사항 { #measurement-notes }

모든 측정에 다음을 함께 기록하십시오.

- 보드와 리비전.
- 전원 공급원과 측정 지점.
- 펌웨어 브랜치와 빌드.
- 디스플레이 상태.
- Bluetooth 상태.
- 센서 상태.
- 로깅 레벨.
- 평균 전류, 피크 전류, 측정 구간.

## 흔한 전력 문제 { #common-power-problems }

<div align="center"><em>표: 흔한 전력 문제</em></div>

<div align="center" markdown>

| 증상 | 가능한 원인 |
|:--------|:-------------|
| 유휴 전류가 너무 높음 | 폴링 루프, 로깅, 디스플레이 전원 레일, 또는 켜진 채로 남은 주변 장치 클럭. |
| 슬립 진입 실패 | 활성 타이머, 열려 있는 디바이스, 대기 중인 작업, 또는 처리되지 않은 웨이크업 소스. |
| Bluetooth 전류 스파이크 | 연결 간격, 스캔 윈도우, 오디오 경로, 또는 재전송. |
| 디스플레이가 소비 전력의 대부분을 차지함 | LCD 백라이트 전력 소모, 화면에 표시되는 AMOLED 콘텐츠, 리프레시 정책, 또는 부분 업데이트 전략. |
| 측정값이 크게 변동함 | 테스트 구성, 배터리 상태, USB 전원 경로, 또는 로깅 부하가 변경됨. |

</div>
