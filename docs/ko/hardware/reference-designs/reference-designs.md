# 레퍼런스 디자인 { #reference-designs }

레퍼런스 디자인은 제품 기획과 구현을 연결합니다. 재사용할 수 있는 하드웨어·소프트웨어 기준 구성에는 시작 하드웨어, 소프트웨어 버전, 설계 파일의 제공 여부, 브링업 증빙, 재사용 시 주의 사항이 명시되어야 합니다. 이 페이지의 개발 경로는 기준 구성을 마련하고 검증하는 데 도움을 줍니다. 다만 여기에 경로가 소개되어 있다고 해서 회로도, BOM, 양산 적합성 검증 패키지가 정식 릴리스된 것은 아닙니다.

[제품 계획하기](../../sf32-products/family/product-planning.md)로 초기 후보 목록을 만든 다음, 아래에서 가장 가까운 여정을 선택하여 보드 검증과 제품 리스크 감소를 진행하십시오.

## 레퍼런스 디자인과 프로젝트 { #reference-designs-and-projects }

**"어떤 재사용 가능한 기술 기준 구성을 출발점으로 삼을 수 있습니까?"**에 답하려면 레퍼런스 디자인을 사용하십시오. **"특정 제품을 이 기준 구성에서 출발해 어떻게 통합하고 출시 결정을 내릴 수 있습니까?"**에 답하려면 [프로젝트](../../projects/index.md)를 참고하십시오.

## 사용 가능한 여정 { #available-journeys }

현재 커넥티드 웨어러블 여정은 검증 워크플로이며, 정식 릴리스된 레퍼런스 보드 패키지는 아닙니다. 고정된 보드·SDK 리비전 조합, 설계 파일 릴리스, 측정값을 포함한 적합성 검증 기록은 아직 공개되지 않았습니다. 결과를 재현 가능한 것으로 취급하기 전에 제품에 맞는 기준 구성을 정하고 기록하십시오.

<div align="center" markdown>

| 여정 | 제품 중점 | 하드웨어 기준 구성 | 소프트웨어 기준 구성 | 검증 중점 |
|:--------|:--------------|:------------------|:------------------|:--------------------|
| [커넥티드 웨어러블](connected-wearable-journey.md) | 디스플레이, BLE, 센서 입력을 갖춘 소형 배터리 구동 제품. | SF32LB52-DevKit-LCD 또는 적합한 대체 보드에서 시작한 다음, 선택한 칩이나 모듈을 기반으로 맞춤형 보드를 설계합니다. | SiFli-SDK `hello_world` 및 제품에 필요한 예제. | 디스플레이, Bluetooth, 센서 동작, 절전 및 웨이크업, 복구, 양산 설계 증빙. |

</div>

## 여정 사용 방법 { #how-to-use-a-journey }

1. 여정의 제품 중점과 선택한 하드웨어가 설계 제약에 맞는지 확인합니다.
2. 제품에 맞게 변경하기 전에 명시된 보드에서 소프트웨어 기준 구성을 재현합니다.
3. 정확한 보드, SDK 버전, 예제, 빌드/플래시 명령, 시리얼 로그를 프로젝트 기록과 함께 보관합니다.
4. 변경한 모든 디스플레이, 메모리 디바이스, 배터리 경로, RF 설계, 인클로저, 인터페이스에 대해 제품별 검증을 추가합니다.
5. 선택한 가이드와 체크리스트, AVL 결정, 복구 방식, 남은 리스크를 정리하고, 그 결과를 [양산 설계](../design-for-production.md) 검토 자료로 활용하십시오.

## 새 여정 추가하기 { #adding-a-new-journey }

개발 경로를 재현 가능한 레퍼런스 기준 구성으로 제시하기 전에 대상 제품과 독자, 지원 하드웨어·소프트웨어 버전, 사전 요건, 소스 저장소, 마일스톤, 검증 기준, 측정값, 제품에 적용할 때 필요한 인계 사항을 문서화하십시오. 아직 기획 단계라면 그 상태를 분명히 밝히고, 기준 구성이 검증을 마친 것처럼 보이지 않도록 부족한 증빙을 나열하십시오.

재사용 가능한 레퍼런스 경로보다 넓은 범위의 제품별 개발 전 과정을 다룬다면 [프로젝트](../../projects/index.md)를 참고하십시오. 프로젝트 문서는 하드웨어 기준 구성, 설계 파일, 양산 자료를 중복해서 다루지 말고 관련 레퍼런스 디자인으로 연결해야 합니다.
