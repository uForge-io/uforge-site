# Примеры { #examples }

Начинайте с готовых примеров. Обычно разработка прошивки SF32 идёт быстрее, если адаптировать работающий пример для нужной платы, а не создавать каждую подсистему с нуля.

Самый маленький пример не всегда лучший. Выберите тот, в котором уже реализована наиболее сложная часть продукта: профиль Bluetooth, дисплейная панель, аудиотракт, файловая система, OTA, USB, режим энергопотребления или AI-ускоритель.

## Как выбрать пример { #how-to-choose-an-example }

Выбирайте в следующем порядке:

1. Подберите плату.
2. Подберите фреймворк.
3. Подберите пример для самой сложной периферии.
4. Подберите необходимое промежуточное ПО.
5. Учтите ограничения по энергопотреблению и памяти.

Например, для продукта с Bluetooth-аудио лучше взять пример, близкий к аудио- и Bluetooth-функциям, а не простой `hello_world`, даже если последний легче понять.

## Порядок адаптации { #adaptation-workflow }

1. Соберите и прошейте пример без изменений.
2. Сохраните успешную команду сборки, имя платы, команду прошивки, последовательный порт и журнал.
3. Внесите одно изменение для продукта.
4. Повторно соберите и протестируйте.
5. Сделайте commit или зафиксируйте изменение до добавления следующей подсистемы.

В первый час такой порядок медленнее, а после первой серьёзной ошибки — значительно быстрее.

## Какие данные сохранять { #evidence-to-keep }

Для каждого примера, который становится основой продукта, фиксируйте:

- Ветку SDK или версию пакета.
- Имя платы или FQBN.
- Обязательные параметры конфигурации.
- Требуемые выводы и периферию.
- Ожидаемый вывод последовательного порта.
- Известные ограничения.
- Объём используемой памяти, если он известен.
- Команду восстановления.

## Правило выбора примера { #example-selection-rule }

Выберите пример, соответствующий наиболее ограниченному компоненту продукта:

- Для продуктов Bluetooth начните с примера ближайшего профиля.
- Для устройств с дисплеем начните с примера дисплейной системы и LVGL.
- Для устройств с питанием от аккумулятора начните с примера низкого энергопотребления.
- Для продуктов с OTA начните с процесса обновления и разметки разделов.

Затем добавляйте остальные подсистемы по одной.

## Рекомендуемый порядок изучения { #suggested-learning-path }

Если вы только начинаете работу с SDK, пройдите раздел [Знакомство с периферией](../../getting-started/tutorials/beginner.md). Когда отдельная периферия заработает стабильно, переходите к разделу [Объединение подсистем](../../getting-started/tutorials/intermediate.md). Раздел [Проверка готовности изделия](../../getting-started/tutorials/advanced.md) пригодится для измерения энергопотребления, работы с OTA, запуска пользовательского дисплея, анализа сбоев, нескольких подключений Bluetooth и разработки собственных драйверов. В обзорах тем объясняются архитектура и компромиссы, связанные с этими примерами.
