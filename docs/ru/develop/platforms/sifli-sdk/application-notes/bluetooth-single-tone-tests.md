# Проверка отдельных RF-операций Bluetooth { #run-bluetooth-single-item-rf-tests }

Проверка отдельных RF-операций — низкоуровневая функция SDK для настройки платы, предварительных испытаний на соответствие требованиям FCC/CE и поочередной проверки несущей частоты или параметра модуляции. Это не функция продукта и не замена сигнальным испытаниям BQB.

## Подготовка DUT и инструмента { #prepare-the-dut-and-tool }

Подготовьте испытуемое устройство (DUT), ПК, USB-кабель для передачи данных (не только для зарядки), RF-коаксиальный кабель и тестер радиосвязи или анализатор спектра. Для модулированных тестов BLE/BT обеспечьте доступ к `VBAT`, `GND` и сигналам TX/RX UART1. Для теста с одной несущей (CW) на SF32LB55x также выведите TX/RX UART3. Распиновка по умолчанию:

<div align="center" markdown>

<em>Таблица: Распиновка UART по умолчанию для модулированных тестов и тестов с одной несущей</em>

| Устройство/корпус | UART1 TX/RX для модулированных тестов | UART управления одной несущей (CW) |
|---|---|---|
| SF32LB52x | PA19 / PA18 | UART1 |
| SF32LB551 | PA49 / PA51 | UART3 (PB45 / PB46) |
| SF32LB555 / SF32LB557 | PA17 / PA19 | UART3 (PB45 / PB46) |
| SF32LB56xU (QFN) | PA17 / PA18 | UART1 |
| SF32LB56xV (BGA) | PA34 / PA30 | UART1 |
| SF32LB57x | PA19 / PA18 | UART1 |
| SF32LB58x | PA32 / PA31 | UART1 |

</div>

Распиновка UART1 у SF32LB55x зависит от номера модели. Для модулированных тестов BLE/BT подключите UART1 к ПК со скоростью 1 000 000 бод. Для теста с одной несущей на SF32LB55x вместо неё используйте UART3 (PB45/PB46); остальные перечисленные семейства используют UART1. Если конфигурация выводов проекта отличается, руководствуйтесь фактической распиновкой. Подключите RF-порт к прибору коаксиальным кабелем, учитывайте потери в кабеле и указывайте, проводилось измерение по кабелю или в эфире.

!!! note "Область применимости по семействам"
    В таблице UART сведены распиновки по умолчанию для нескольких семейств и корпусов. Приведённые далее схема и снимки экрана `SiFli_RfTool` взяты из руководства для SF32LB52x. Выберите в программе фактическое семейство микросхемы и проверьте распиновку UART целевого проекта.

!!! warning "В официальных руководствах расходится распиновка UART SF32LB58x"
    В [Bluetooth Individual RF Test Guide](https://docs.sifli.com/projects/sdk/latest/en/sf32lb58x/app_note/bt_individual_test_guide.html) для UART1 TX/RX указаны PA32/PA31, а в [общем RF Test Guide](https://docs.sifli.com/projects/sdk/latest/en/sf32lb58x/app_note/rf_test_guide.html) для RF-отладки указаны PA31/PA32. Перед подключением проверьте путь тестирования в целевой прошивке и pinmux платы. Не считайте эти зависящие от руководства и противоречащие друг другу назначения взаимозаменяемыми.

## Переход в режим RF-тестирования { #enter-rf-test-mode }

1. Включите DUT и не переводите его в спящий режим.
2. Отправьте команду FinSH `bt_cm uart_dut` из SiFli_Trace.
3. Проверьте шестнадцатеричный ответ `04 0E 04 XX 03 0C 00`.
4. Отключите терминал; SiFli_RfTool будет использовать тот же UART для управления HCI.

## Передача сигнала BLE или Classic BT { #transmit-a-ble-or-classic-bt-signal }

1. Запустите `SiFli_RfTool.exe`, выберите семейство микросхемы и режим BLE non-signaling или BT non-signaling, укажите COM-порт UART1 и подключитесь на скорости 1 000 000 бод.
2. Для BLE задайте Frequency, Data Length, payload и PHY, затем нажмите Start TX. Перед изменением канала или PHY остановите передачу.
3. Для Classic BT задайте Frequency, Data Length и Packet Type, затем нажмите Start TX. Перед изменением параметров пакета остановите передачу.
4. На тестере задайте те же канал, тип пакета, полезную нагрузку и PHY. Если тестера радиосвязи нет, форму сигнала можно проверить анализатором спектра.

В исходных материалах SDK приведены опорные уровни TX для платы LB52x HDK, но эти значения относятся только к данной плате. Используйте их лишь как ориентир при отладке и измерьте реальную плату продукта.

## Приём сигнала и расчёт чувствительности { #receive-and-calculate-sensitivity }

Перед переходом в RX остановите TX. Задайте канал и нажмите Start RX; перед изменением канала остановите RX. Для приёма BLE настройте тестер в Direct Test Mode, укажите PHY и канал, передайте 1 500 пакетов и вычислите:

```text
PER = (1500 - received_packets) / 1500 × 100%
```

Также запишите RSSI. Для приёма Classic BT используйте форму сигнала GPRF-генератора CMW500, например DH1/2-DH1/3-DH1, и зафиксируйте число принятых и ошибочных пакетов, количество бит, BER и RSSI. BLE и Classic BT используют общий RF-блок; не запускайте их одновременно.

## Настройка теста с одной несущей и измерительных приборов { #single-carrier-and-instrument-setup }

Перед переключением на тест с одной несущей (CW) остановите текущую операцию. Для SF32LB55x перенесите подключение DUT к ПК с UART1 на UART3 (PB45/PB46), выберите соответствующий COM-порт в SiFli_RfTool и установите скорость 1 000 000 бод. Для остальных перечисленных семейств используйте UART1. Задайте частоту несущей и мощность TX, запустите передачу и проверьте выходной сигнал анализатором спектра или измерителем мощности.

Для измерения модулированного сигнала TX BLE/BT с помощью тестера выберите режим приёма StandAlone (Non Signaling) и задайте те же канал, тип пакета, полезную нагрузку и PHY, что и в SiFli_RfTool. При измерении приёма DUT настройте тестер радиосвязи как источник сигнала: для BLE используйте параметры DTM, для Classic BT — форму сигнала GPRF.

Если программа или последовательное соединение перестали отвечать, закройте SiFli_RfTool, выключите и снова включите DUT, дождитесь загрузки и подключитесь повторно. В протоколе сохраните версию программы, идентификатор прошивки, микросхему/корпус, выводы UART, ревизию платы, канал, PHY/тип пакета, мощность, потери в кабеле, настройки прибора и исходные результаты.
