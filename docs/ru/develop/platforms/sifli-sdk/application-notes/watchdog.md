# Настройка сторожевого таймера { #configure-the-watchdog }

Документация SiFli-SDK описывает сторожевые таймеры на двух уровнях: аппаратные блоки, доступные через HAL, и драйвер RT-Thread, используемый приложениями. Названия экземпляров, область сброса и варианты тактирования зависят от семейства; сверьтесь с таблицей и подтвердите поведение по конфигурации и документации целевой версии SDK.

<div align="center" markdown>

<em>Таблица: документированные возможности сторожевых таймеров по семействам</em>

| Семейство | Возможности watchdog по HAL | Тактирование по руководству HAL |
|---|---|
| SF32LB52x | Руководство HAL описывает отдельные watchdog для HCPU и LCPU, которые могут вызвать прерывание или сбросить свою подсистему, а также системный IWDT, сбрасывающий весь чип. | В описании счётчика используется тактирование 32K; отдельная опция выбора тактового источника для 52x не указана. |
| SF32LB55x | WDT1 для HCPU и WDT2 для LCPU могут вызывать прерывания; аппаратный сброс ограничен соответствующей подсистемой. Системный IWDT не вызывает прерываний, но может сбросить весь чип. | Можно выбрать RC10K или 32K LXT. |
| SF32LB56x / SF32LB58x | Согласно руководству HAL, WDT1/WDT2 дополнительно могут сбросить весь чип. | Используется RC10K, а не низкочастотный тактовый источник 32K. |

</div>

!!! warning "Область применения руководства по watchdog для RT-Thread"
    [Руководство по использованию watchdog](https://docs.sifli.com/projects/sdk/latest/en/sf32lb52x/app_note/watchdog.html) опубликовано по пути `sf32lb52x`, однако в тексте явно указано SF32LB55X. Приведённые ниже таймаут по умолчанию 30 секунд, обслуживание из потока IDLE, поведение в режимах сна и последовательность сброса на уровне приложения относятся к описанной там конфигурации 55x, а не являются общей гарантией для всех семейств SF32. Сверяйте их с документацией целевого семейства и сформированной конфигурацией.

## Включение и настройка сторожевого таймера { #enable-and-configure-the-watchdog }

В каталоге проекта запустите `sdk.py menuconfig` и включите сторожевой таймер в настройках драйверов устройств RT-Thread. Название пункта меню может различаться в разных версиях SDK; сверьтесь с документацией для целевого семейства и перед сборкой проверьте созданный файл `rtconfig.h`.

В указанном руководстве по использованию watchdog показаны две отдельные настройки:

- `RTOS → On-chip Peripheral Drivers → Enable Watchdog Timer` включает аппаратный сторожевой таймер микросхемы.
- `RTOS → RT-Thread Components → Device Drivers → Using Watch Dog device drivers` включает драйвер RT-Thread.

Для конфигурации 55x, описанной в указанном руководстве, задокументирован таймаут по умолчанию 30 секунд. В меню драйвера параметр `(30) Watch Dog timeout (NEW)` позволяет выбрать другое значение. Проверьте значение по умолчанию для целевого семейства в `menuconfig` и сохраните сформированную конфигурацию вместе с образом прошивки.

На рисунках показаны расположение пункта меню и поле таймаута из указанного руководства. Путь URL и семейство, названное в тексте, не совпадают, поэтому используйте рисунки только как иллюстрацию; фактические путь к меню и значение по умолчанию проверьте по выводу `menuconfig` своего проекта.

## Правила обслуживания сторожевого таймера { #feeding-policy }

Система обслуживает сторожевой таймер из потока `IDLE` RT-Thread. Если ни один поток приложения не выполняется непрерывно дольше заданного таймаута, дополнительный код в приложении не требуется.

Если высокоприоритетный поток должен работать непрерывно дольше таймаута, обслуживайте сторожевой таймер из этого потока с помощью:

```c
rt_hw_watchdog_pet();
```

Не добавляйте безусловный цикл обслуживания сторожевого таймера, который маскирует зависание планировщика или взаимную блокировку. Точка обслуживания должна подтверждать, что контролируемая задача выполняет свою работу без зависания.

## Работа в режимах сна и поведение при сбросе { #sleep-and-reset-behavior }

- При переходе в `Standby` или `Hibernate` сторожевой таймер отключается и снова включается после выхода из режима сна.
- В остальных режимах сна сторожевой таймер продолжает работать: систему нужно вывести из сна и обслужить таймер до истечения таймаута.
- HCPU использует системный сторожевой таймер. При истечении таймаута перезапускается весь чип.
- LCPU использует сторожевой таймер подсистемы LCPU. При истечении таймаута сначала возникает прерывание, а обработчик прерывания инициирует программный перезапуск всего чипа.

## Порядок проверки { #validation-sequence }

1. Запишите семейство чипа, ревизию SDK, таймаут, компонент, отвечающий за обслуживание сторожевого таймера, и режим сна.
2. Убедитесь, что при штатной нагрузке выполнение доходит до предусмотренной точки обслуживания сторожевого таймера.
3. Намеренно остановите обслуживание и проверьте, какие части системы сбрасываются и как проходит последующая загрузка.
4. Повторите проверку во всех поддерживаемых режимах сна, особенно в `Standby` и `Hibernate`.
5. Сохраните наблюдения после сброса и диагностические данные при загрузке вместе с результатами проверки восстановления продукта.
