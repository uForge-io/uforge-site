# Обзор раздела «Начало работы» { #getting-started }

Для устройств SF32 доступно несколько вариантов разработки. Сейчас официальные средства для первого запуска — SiFli-SDK и CodeKit. Поддержка платы SF32LB52 DevKit LCD в основном проекте Zephyr доступна начиная с версии Zephyr v4.3.0. OpenSiFli также предлагает бета-пакет ArduinoCore-zephyr и разрабатывает поддержку Rust для SF32LB52. Для MicroPython пока нужны официальные образы прошивки и инструкции для конкретных плат; без них нельзя подготовить полноценное проверенное руководство.

Сведения о рекомендуемом процессе разработки и текущем статусе каждой платформы см. в разделе [Обзор раздела «Разработка»](../develop/index.md). Используйте таблицу ниже только для выбора отправной точки: основным источником сведений о поддерживаемых платах и ограничениях служит страница соответствующей платформы.

## Что понадобится { #what-you-need }

Сначала выберите плату, поддерживаемую нужным программным путём. Подключение для прошивки и последовательной связи зависит от платы и фреймворка:

- Отладочная плата SF32, например [SF32LB52-DevKit-LCD](../sf32-products/devkits/SF32LB52-DevKit-LCD.md).
- Кабель с поддержкой передачи данных и интерфейс для прошивки/последовательной связи, указанный для этой платы и фреймворка. Для SF32LB52-DevKit-LCD в [инструкциях SiFli по подключению](https://docs.sifli.com/projects/sdk/latest/en/sf32lb52x/quickstart/get-started.html) для последовательной загрузки используется USB-to-UART; не путайте его с отдельным USB-разъёмом для USB-функций.
- Компьютер под управлением Windows, macOS или Linux.
- Терминал последовательного порта, настроенный для консоли платы, чтобы просматривать загрузочные журналы и вывод примеров.

!!! tip "Используйте кабель для передачи данных"
    Кабели USB, предназначенные только для зарядки, часто становятся причиной проблем при первом запуске. Если плата включается, но последовательный порт не появляется, попробуйте заведомо исправный кабель для передачи данных и подключите его напрямую к USB-порту компьютера.

## Рекомендуемый первый запуск { #recommended-first-run }

Если вы впервые работаете с платой SF32, начните с [SiFli-SDK](sifli/getting-started-sifli-sdk.md). Это эталонный программный стек для SF32 и наиболее надёжная отправная точка, чтобы проверить плату, кабель, последовательный порт, процедуру прошивки и инструментарий.

После успешного запуска `hello_world` можно перейти к другой платформе, совместимой с конкретным оборудованием. Так у вас останется заведомо рабочая конфигурация, к которой можно вернуться, если последующие эксперименты вызовут проблемы.

## Признаки успешного запуска { #what-success-looks-like }

К концу руководства по началу работы у вас должно быть выполнено следующее:

- Собран или загружен первый пример.
- Пример записан на плату.
- Открыта консоль последовательного порта.
- Получен ожидаемый вывод: например, загрузочный журнал, `hello_world`, приглашение оболочки или баннер REPL.
- Зафиксированы название платы, последовательный порт и команда прошивки, с которой всё заработало.

Сохраните эти сведения в заметках проекта. Когда начнёте изменять примеры, они помогут быстрее восстановить рабочую конфигурацию.

## Перейти к руководствам { #continue-with-tutorials }

Как только вы сможете повторить успешный первый запуск, переходите к [обзору практических руководств](tutorials/overview.md). Это следующий этап обучения: сначала работа с одной периферийной подсистемой, затем объединение нескольких подсистем и, наконец, проверка проекта на соответствие требованиям изделия.

## Когда переходить к разделу «Разработка» { #when-to-move-to-develop }

Цель раздела «Начало работы» достигнута, когда вы можете повторить заведомо успешный первый запуск. Раздел [«Разработка»](../develop/index.md) служит постоянным инженерным справочником по зрелости платформ, инструментам, прошивке и отладке, архитектуре прошивки и интеграции изделия. После первого запуска обратитесь к [справочнику по инструментам CodeKit](../develop/tools/codekit.md), чтобы разобраться в его роли в повседневной разработке; эта страница посвящена именно первому запуску.

## Что проверить перед выбором пути разработки { #before-choosing-a-development-path }

Прежде чем выбирать вариант разработки, убедитесь, что документация охватывает нужную плату и версию ПО. В частности, проверьте, есть ли в ней:

- Публичная матрица поддержки и уровня зрелости по каждой плате для SiFli-SDK, CodeKit, Zephyr, Arduino и MicroPython.
- Точный идентификатор платы для каждого поддерживаемого варианта разработки.
- Инструкции по прошивке и загрузке для Windows, macOS и Linux.
- Ожидаемый вывод последовательного порта для каждого первого примера.
- Инструкции по восстановлению после неудачной прошивки или использования недействительного образа.
- Известные ограничения каждой платформы, особенно для Bluetooth, дисплея, хранилища, USB и режимов низкого энергопотребления.
- Примечания к выпускам с указанием совместимых версий SDK, CodeKit, пакетов, образов прошивки и поддержки плат.

Не считайте, что вариант разработки, доступный для одной платы, подходит для всех плат SF32. Проверяйте конкретную плату и используемую версию ПО.
