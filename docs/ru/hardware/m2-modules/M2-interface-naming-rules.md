# Правила наименования интерфейса μForge M2 { #forge-m2-interface-naming-rules }

## Базовая спецификация { #base-specification }

Этот документ задаёт обозначения, используемые в предлагаемой системе интерфейсов модулей μForge. Это правила наименования, а не опубликованный электрический или механический стандарт.

В этих правилах **M2** обозначает обязательный общий базовый интерфейс для модулей, использующих данную систему. Это требование не означает, что все существующие модули μForge или SiFli реализуют M2. Распиновка, электрические и механические требования M2 ещё разрабатываются и здесь не определены.

Прежде чем заявлять о совместимости M2 с M.2 E-key, опубликованное определение M2 должно задать механический интерфейс, распиновку, электрические ограничения, обязательные и необязательные сигналы, требования к плате-носителю и правила соответствия. Текущее [определение интерфейса M2](M2-interface-definition.md) — черновик: само обозначение M2 не подтверждает ни электрическую совместимость с M.2, ни возможность взаимозаменяемого использования модуля с разными платами-носителями.

## Спецификации расширений { #extension-specifications }

Дополнительные возможности объединены в спецификации расширений **M2xY**. Обозначения задают функциональные категории, но не гарантируют, что конкретный модуль реализует все функции категории.

**Формат наименования:**

> **M2xY**

Где:

- **M2** — спецификация базового интерфейса
- **x** — разделитель расширения
- **Y** — категория расширения

## Категории расширений { #extension-categories }

<div align="center"><em>Категории расширений M2</em></div>

<div align="center" markdown>

| Спецификация | Описание |
|:-------------|:---------|
| **M2xM** | Мультимедиа: в будущем предусматриваются RGB-дисплеи, камеры DVP, цифровые микрофоны и расширенные аудиофункции. |
| **M2xA** | Аналоговые функции: будущие возможности точного аналогового ввода-вывода и сбора данных. |
| **M2xN** | Сети: будущая поддержка Ethernet, CAN и промышленных сетей. |
| **M2xH** | Высокоскоростные интерфейсы: будущие интерфейсы с высокой пропускной способностью. |
| **M2xP** | Питание: будущие возможности управления питанием и интерфейсов ввода-вывода с большими токами. |

</div>

Описания в таблице показывают предполагаемую область применения категорий, а не окончательные электрические требования.
**Статус источников:**
- **M2 / M2xM:** В связанном черновике говорится, что локальная книга с предложением содержит карты контактов, однако файл не включён в этот репозиторий и ссылка на него отсутствует; эти карты остаются только предложением.
- **M2xN / M2xA:** В черновике приведены сводки по этим расширениям, но исходные данные карт контактов для их проверки не найдены; сводки остаются неподтверждёнными.
- **M2xH / M2xP:** Зарезервированные обозначения без назначенных контактов.

## Обозначение модуля { #module-declaration }

Модуль, использующий эти правила, указывает **M2** как базовый интерфейс и может перечислить одно или несколько реализованных расширений. Документация также должна указывать фактические разъёмы, дополнительные функции и взаимоисключающие режимы.

Примеры обозначений, а не список конфигураций уже выпущенных модулей:

- **M2**
- **M2 + M2xM**
- **M2 + M2xA**
- **M2 + M2xM + M2xN**

## Принципы проектирования { #design-principles }

- Цель разработки **M2** — сохранять стабильность и обратную совместимость по мере развития системы. Совместимость необходимо проверять по применимым редакциям спецификаций и фактической реализации.
- Каждое расширение **M2xY** имеет собственную функциональную область. Разные обозначения не означают, что все функции могут работать одновременно или что их назначения контактов независимы.
- Расширения дополняют базовый интерфейс, не изменяя и не заменяя его.
- Модули объявляют поддерживаемые возможности, перечисляя реализованные спецификации M2xY.

Перед выбором разъёма или заявлением о совместимости выполните проверки, описанные на странице [Стандарты интерфейсов модулей](interface-standards-overview.md).
