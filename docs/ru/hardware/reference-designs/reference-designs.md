# Референсные решения { #reference-designs }

Референсные решения связывают планирование изделия с реализацией. Повторно используемая аппаратная и программная база должна указывать исходное оборудование, версию ПО, доступные проектные файлы, результаты первичного запуска и ограничения повторного использования. Представленные здесь пути разработки помогают сформировать и проверить эту базу; само включение в раздел не подтверждает выпуск утверждённой схемы, BOM или пакета квалификации для серийного производства.

Сначала используйте [планирование продукта](../../sf32-products/family/product-planning.md), чтобы составить предварительный список вариантов. Затем выберите наиболее подходящий путь разработки, чтобы организовать проверку на плате и снизить риски изделия.

## Референсные решения и проекты изделий { #reference-designs-and-projects }

Референсное решение отвечает на вопрос: **«С какой повторно используемой технической базы можно начать?»** Раздел [Проекты](../../projects/index.md) отвечает на вопрос: **«Как провести конкретное изделие от этой базы через интеграцию к решениям о выпуске?»**

## Доступные пути разработки { #available-journeys }

Текущий маршрут «Подключённое носимое устройство» описывает процесс валидации, а не опубликованный комплект материалов по референсной плате. Для этого маршрута пока не опубликованы ни фиксированная пара ревизий платы и SDK, ни комплект проектных файлов, ни протокол квалификационных измерений. Определите и зафиксируйте эти исходные данные для своего изделия, прежде чем считать результаты воспроизводимыми.

## Как пользоваться путём разработки { #how-to-use-a-journey }

1. Убедитесь, что сценарий применения, описанный в маршруте, и выбранное оборудование соответствуют ограничениям вашего изделия.
2. До адаптации воспроизведите программную базу на указанной плате.
3. Сохраните в проектной документации точное название платы, версию SDK, пример, команду сборки и прошивки, а также журнал последовательного порта.
4. Добавьте отдельную проверку для каждого изменённого дисплея, устройства памяти, пути питания от аккумулятора, решения по RF, корпуса или интерфейса.
5. Передайте результаты в раздел [Разработка для серийного производства](../design-for-production.md), приложив выбранное руководство, контрольный список, решения по AVL, способ восстановления и список оставшихся рисков.

## Добавление нового пути разработки { #adding-a-new-journey }

Прежде чем представлять путь разработки как воспроизводимую референсную базу, укажите целевое изделие и аудиторию, поддерживаемые версии аппаратной части и ПО, предварительные требования, исходный репозиторий, этапы, критерии проверки, измерения и передачу результатов для адаптации изделия. Если это пока процесс планирования, явно укажите его статус и недостающие подтверждения, не создавая впечатления, что база уже прошла квалификацию.

Для сквозной разработки конкретного изделия, выходящей за рамки повторно используемой базы, используйте раздел [Проекты](../../projects/index.md). Проект изделия должен ссылаться на соответствующее референсное решение, а не дублировать его аппаратную базу, проектные файлы или материалы для серийного производства.
