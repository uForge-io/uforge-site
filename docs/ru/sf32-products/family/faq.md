# FAQ по SF32 { #sf32-faq }

## 1. Выбор продукта { #choosing-a-product }

### 1.1. Какое семейство SF32 выбрать? { #choosing-a-family }

Начните с ключевых критериев выбора:

- **Разрешение дисплея:** Нужное число пикселей, интерфейс, частота обновления и память кадрового буфера.
- **Режим Bluetooth:** Только BLE либо двухрежимный BLE и Classic Bluetooth.
- **Число GPIO:** Доступные выводы после назначения интерфейсов и памяти.
- **Размер корпуса:** Площадь, шаг выводов и требования к монтажу PCB.
- **Питание:** Батарея или стабилизированный источник, рабочий диапазон напряжения и уровни I/O.
- **Аудиофункции:** Требования к ADC/DAC, I2S и PDM, включая микрофонные каналы.

Сравнивайте конкретные микросхемы, а не только номера семейств: больший номер не обязательно лучше подходит для изделия. В инструменте [«Подбор компонентов SF32»](../product-selector.md) можно задать фильтр по каждому из этих критериев и получить список подходящих моделей.

[Сравнение семейств](SF32_family.md) · [Подбор компонентов SF32](../product-selector.md)

### 1.2. Использовать микросхему, модуль или отладочную плату? { #chip-or-modules }

Отладочная плата подходит для оценки платформы и проверки прошивки. Модуль сокращает объём работ с RF, кварцевым резонатором и разводкой памяти на несущей плате, что также может снизить общие затраты на разработку. При небольших объёмах выпуска модуль избавляет от необходимости самостоятельно закупать и обеспечивать поставки входящих в него компонентов; его RF-сертификация может быть особенно полезна в некоторых регионах. Выбирайте вариант на отдельной микросхеме, если стоимость, размеры или гибкость оправдывают самостоятельную разработку схемы, разводки и RF. Оба пути требуют проверки конечного изделия. Новые модули будут добавляться по мере их появления.

[Планирование изделия](product-planning.md)

### 1.3. С какой отладочной платы начать? { #choosing-a-board }

Начните с отладочной платы LCD, ориентированной на дисплей, для вашего семейства микросхем: [SF32LB52-DevKit-LCD](../devkits/SF32LB52-DevKit-LCD.md), [SF32LB56-DevKit-LCD](../devkits/SF32LB56-DevKit-LCD.md), [SF32LB57-DevKit-LCD](../devkits/SF32LB57-DevKit-LCD.md) (вариант памяти N32R16) или [SF32LB58-DevKit-LCD](../devkits/SF32LB58-DevKit-LCD.md) (вариант N16R32N1). Для SF32LB52x есть также компактные платы: [SF32LB52-DevKit-Core-3p3](../devkits/SF32LB52-DevKit-Core-3p3.md), [SF32LB52-DevKit-Nano](../devkits/SF32LB52-DevKit-Nano.md) и [SF32LB52-DevKit-ULP](../devkits/SF32LB52-DevKit-ULP.md) (оценка низкого энергопотребления для носимых устройств). Убедитесь, что вариант памяти платы соответствует целевой модели; полный список плат приведён в официальном руководстве SiFli по моделям плат.

[Подбор компонентов SF32](../product-selector.md) · [Официальное руководство по моделям плат](https://wiki.sifli.com/en/board/devkit_guide.html)

### 1.4. Как читать заказные коды микросхем и модулей? { #reading-part-numbers }

Читайте полный код, а не только префикс семейства. Код микросхемы различает устройство, корпус и память; суффиксы модуля описывают установленный накопитель и память. Используйте примеры и исторические исключения руководства и уточняйте у поставщика доступную для заказа конфигурацию.

[Правила обозначения SF32](SF32_namingrule.md)

## 2. Память и характеристики { #memory-and-specifications }

### 2.1. Чем отличаются SRAM, PSRAM и Flash? { #memory-types }

SRAM и PSRAM хранят рабочие данные и теряют их при отключении питания; режимы сохранения данных зависят от устройства. Встроенная SRAM и внешняя либо размещённая в одном корпусе PSRAM различаются путём доступа, пропускной способностью и энергопотреблением. Flash — энергонезависимое хранилище прошивки и ресурсов. Увеличение Flash не компенсирует нехватку рабочей RAM.

[Типы памяти](../../learn/architecture/psram-and-memory-types.md)

### 2.2. Сколько памяти нужно приложению? { #sizing-memory }

Заложите RAM для ОС, стеков, кучи, графических буферов, аудио и параллельных задач. Размер базового кадрового буфера равен ширина × высота × байт на пиксель × число буферов; учитывайте выравнивание шага строки и дополнительные буферы рендеринга. Отдельно рассчитайте энергонезависимую память для прошивки, шрифтов, изображений, аудио, файлов и OTA-образов. Измерьте пиковое использование при целевой нагрузке.

[Обзор графики](../../learn/graphics/overview.md) · [Планирование изделия](product-planning.md)

### 2.3. Когда выбирать NOR, NAND или eMMC? { #choosing-storage }

Выбирайте с учётом требуемого способа загрузки, ёмкости, характера доступа и поддержки ПО, а не по одной только ёмкости. NOR часто используется для кода и произвольного чтения; NAND требует управления блоками стирания, ECC и дефектными блоками; eMMC содержит контроллер управления накопителем. В этих описаниях SPI-NAND и QSPI-NAND означают один вариант памяти, а не расхождение продуктов. Проверьте загрузчик, драйвер и файловую систему для конкретной микросхемы.

[Типы памяти](../../learn/architecture/psram-and-memory-types.md) · [Суффиксы модулей](SF32_namingrule.md#module-naming)

### 2.4. Каждая микросхема поддерживает все функции семейства? { #family-versus-sku }

Нет. Обзор семейства может объединять возможности нескольких моделей. Память, питание, доступные выводы и интерфейсы зависят от SKU, корпуса и мультиплексирования. Периферия микросхемы может не быть выведена на модуле или плате. Проверьте таблицу вариантов, даташит, распиновку и поддержку нужной функции в SDK.

[Сравнение семейств](SF32_family.md) · [Подбор компонентов SF32](../product-selector.md)

## 3. Соответствие задачам приложения { #application-fit }

### 3.1. Как выбрать микросхему для дисплея? { #choosing-a-display }

Сначала проверьте электрический интерфейс панели и её тайминги, затем разрешение, формат пикселя, целевую частоту обновления, кадровую память и пропускную способность. Максимальное разрешение само по себе не гарантирует плавность. Уточните графическое ускорение и драйвер панели, затем проверьте типовые экраны и анимацию на выбранной памяти.

[Матрица интерфейсов по устройствам](../../learn/graphics/display-controller.md#per-device-interface-matrix) · [Контроллер дисплея](../../learn/graphics/display-controller.md) · [Обзор графики](../../learn/graphics/overview.md)

### 3.2. Как проверить поддержку аудио и микрофонов? { #audio-and-microphones }

Для аналогового тракта проверьте каналы ADC и DAC, для цифровых аудиоустройств — I2S, для цифровых микрофонов — PDM. Один интерфейс PDM может передавать до двух микрофонных каналов; число интерфейсов не равно числу микрофонов. Доступные каналы также зависят от выводов, мультиплексирования, драйверов и разводки. Проверяйте нужную конфигурацию, а не складывайте числа интерфейсов.

[Обзор аудио](../../learn/audio/overview.md) · [Глоссарий](../../about/glossary.md)

### 3.3. Какие продукты поддерживают BLE, Classic Bluetooth или оба режима? { #bluetooth-modes }

SF32LB55x поддерживает только BLE; SF32LB52x, SF32LB56x, SF32LB57x и SF32LB58x предлагают двухрежимный Bluetooth. Возможности радио не гарантируют все профили, кодеки и функции в любой конфигурации SDK. Проверьте нужный профиль и испытанный пример; наличие BLE не подтверждает аудио Classic Bluetooth или BLE Audio.

[Сравнение семейств](SF32_family.md) · [Обзор Bluetooth](../../learn/bluetooth/overview.md)

### 3.4. Нужен ли внешний Wi-Fi-модуль? { #wifi }

Каталогизированные здесь продукты SF32 не содержат встроенного радиоблока Wi-Fi. Фильтр Wi-Fi обозначает внешний путь через SDIO. Внешнему устройству также нужны совместимые питание, выводы, драйверы и сетевое ПО; наличие SDIO само по себе не доказывает работоспособность решения.

[Подбор компонентов SF32](../product-selector.md)

### 3.5. Сколько GPIO реально доступно? { #usable-gpios }

Исходите из конкретного корпуса и памяти, затем вычитайте выводы, занятые нужными интерфейсами и функциями платы. Модуль выводит лишь часть контактов микросхемы. У SF32LB57x BGA112 дополнительные выводы MPI3/статического выхода имеют ограниченные функции и не являются свободно назначаемыми GPIO. Не считайте заявленное число выводов гарантированным бюджетом приложения.

[Примечания о GPIO семейств](SF32_family.md) · [Варианты SF32LB57x](../chips/SF32LB57x.md)

## 4. Доступность и планирование изделия { #availability-and-product-planning }

### 4.1. Что означает маркировка модуля для моего изделия? { #module-markings }

По сводке маркировки на странице модуля определите варианты с указанными обозначениями и запросите применимые документы об одобрении и условия интеграции. Напечатанный идентификатор FCC или знак CE сам по себе не доказывает, что одобрение распространяется на готовое изделие. Изменения антенны, несущей платы или корпуса нужно проверять по применимым условиям.

[Маркировка модуля 52](../modules/SF32LB52-MOD-1.md#regulatory-markings) · [Маркировка модуля 56](../modules/SF32LB56-MOD.md#regulatory-markings) · [Маркировка модуля 58](../modules/SF32LB58-MOD.md#regulatory-markings)

### 4.2. Можно ли заказать другую конфигурацию памяти или модуля? { #custom-configurations }

Сообщите μForge.io нужную микросхему или модуль, объём накопителя и PSRAM, интерфейсы, требования к антенне, объём выпуска и сроки. До фиксации проекта уточните реализуемость, поддержку SDK, минимальный заказ и срок поставки. Конфигурация в старом документе не гарантирует доступность сейчас; SF32LB58-MOD-E4R32N1 больше не поставляется из-за дефицита микросхем памяти.

[Связаться с μForge.io](../../about/contact.md) · [Доступность модуля 58](../modules/SF32LB58-MOD.md#storage-interfaces-and-module-variants)

### 4.3. Как уточнить доступность и получить образцы? { #samples-and-documentation }

Используйте ссылки на покупку и документацию со страницы продукта и сообщайте поставщику полный заказной код и нужную ревизию. Подтвердите текущую доступность, память, антенну и срок поставки. По возможности начните с поддерживаемой оценочной платы и опирайтесь в окончательном проекте на официальные документы конкретной микросхемы, а не обзор семейства.
