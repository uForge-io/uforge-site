# 博客首篇文章 [2026-07-31] { #the-first-blog-2026-07-31 }

这是本博客的第一篇文章，正好借此机会把 μForge.io 的目标讲清楚。

评估一款新微控制器时，工程师不应该还要东拼西凑：这里查数据手册，那里翻 wiki，再到论坛里找帖子。μForge.io 汇集了思澈科技（SiFli）SF32 超低功耗微控制器家族的相关资料。该系列面向可穿戴设备、智能显示终端等 AIoT 产品，以及其他电池供电的联网产品，提供具备 Bluetooth 连接和图形处理能力的不同选型。我们把通常分散在数据手册、wiki 和 PDF 中的参考资料，按照产品实际开发流程重新组织：选型、验证、集成到设计中，再到产品交付。更完整的介绍请参见[关于](../../about/index.md)。

## 为什么是 SF32，为什么是现在 { #why-sf32-right-now }

我们决定为之建立整个文档平台，主要出于两个原因。

第一是架构形态的多样性。SF32 并非只是提高 CPU 速度、增加 Flash 容量。整个系列涵盖单核器件、异构双核设计和面向多媒体的三核平台。图形加速与硬件解压缩能力对不同处理器配置形成补充，具体组合因系列而异。这为产品团队提供了多种方案，可根据应用性能、常开任务和集成成本之间的权衡进行选择。

第二个原因是开发资料可以直接查阅。开发者可以在 [OpenSiFli 的 GitHub 组织](https://github.com/OpenSiFli)中查看 SDK 源码，也可以查阅[思澈科技（SiFli）的 wiki](https://wiki.sifli.com/)和 [SDK 文档](https://docs.sifli.com/)，从功能介绍进一步了解实现细节。μForge.io 的职责是把这些资料组织起来，为评估 SF32 的开发者提供一条实用的学习与验证路径。

## 过去一个月完成的工作 { #whats-happened-over-the-past-month }

我们将最初的构想逐步落地，建成了一个可用的文档网站。本站基于 [Zensical](https://zensical.org/) 构建。感谢 Zensical 团队打造这款静态网站生成器。在撰写具体页面之前，我们多次调整网站整体结构，力求按照工程师实际开展项目的思路组织内容，而不是照搬组织架构或某家厂商现有的文档目录。确认结构后，我们覆盖了 SF32LB52x、SF32LB55x、SF32LB56x、SF32LB57x 和 SF32LB58x 五个芯片家族的产品介绍、对比数据和硬件设计指南，并补充了对应的模组和开发板信息。我们上线了交互式产品选型工具，可以按供电方式、内存、显示和接口需求筛选芯片和模组，而不必手动对照五份数据手册。我们还建立了入门指南与教程路径、学习板块的架构深度文章（STAR-MC1、PSRAM 与内存类型、PTM），以及从原理图设计到硬件交付的产品化指导。

## 接下来的计划 { #whats-next }

当前的重点是覆盖范围和准确性：扩充硬件设计指南和检查清单，并持续对照思澈科技（SiFli）官方文档的更新进行核实。再往后，会有更多参考设计、开发和教程板块中的实操示例，以及根据实际采购问题不断打磨的产品选型工具。
