# 用語集 { #glossary }

μForge.io全体で使われる略語や用語をまとめたクイックリファレンスです。組み込み・無線分野の一般用語と、SF32プラットフォームに固有のSiFliの名称を扱います。各項目から、詳しい説明があるページを参照できます。この用語集は用語を調べるためのものであり、各ページの文脈に代わるものではありません。

## アーキテクチャと処理 { #architecture-and-processing }

* **MCU** — **Microcontroller Unit（マイクロコントローラー）。** CPUコア、メモリー、プログラム可能な入出力周辺機能を統合した集積回路です。汎用OSではなく、専用の軽量なファームウェアを実行する用途に最適化されています。
* **SoC** — **System on Chip（システムオンチップ）。** コンピューターシステムに必要な回路や部品を一つの半導体チップ上に集積したものです。本サイトでは、SF32製品はアプリケーションプロセッサ向けの完全なOS環境ではなく、マイクロコントローラー向けのファームウェアを対象としているため、MCUに分類しています。
* **Arm Cortex-M33** — SF32のアプリケーションコアとBluetoothコアに採用されている、32ビットのArmv8-M Mainlineプロセッサーアーキテクチャです。Armv8-M Mainlineは、従来のCortex-M3/M4に対し、信頼されたコードやデータをそれ以外からハードウェアで分離するTrustZoneセキュリティ拡張をオプションでサポートします。ただし、TrustZoneの有無はシリコン実装ごとの構成によって決まり、すべてのCortex-M33に備わる機能ではありません。現在のSF32LB52xからSF32LB58xまでの製品では、TrustZoneは有効化されていません。詳しくは、下記のSTAR-MC1と[SF32LB52xチップページ](../sf32-products/chips/SF32LB52x.md)を参照してください。
* **STAR-MC1** — Arm Chinaが提供する、構成可能なArmv8-M Mainline準拠の組み込みCPU IPです。対応するSF32デバイスでは、Cortex-M33クラスのアプリケーションプロセッサーとして使用されています。CU、SP、SEの各構成では、キャッシュ、TCM、XIPU、TrustZoneの対応状況が異なります。SF32製品で利用できる機能は、デバイスごとに確認してください。SiFliの資料では、文脈に応じて「Arm Cortex-M33 STAR-MC1」または「Arm Cortex-M33」と表記されます。[STAR-MC1アーキテクチャページ](../learn/architecture/star-mc1.md)を参照してください。
* **CDE** — **Custom Datapath Extension（カスタムデータパス拡張）。** 特定の処理を高速化するためのArmカスタム命令機構です。Arm ChinaのSTAR-MC1資料では、CDEの例としてCRC32が示されています。個々のSF32製品での対応状況とソフトウェアサポートは、デバイスごとに確認してください。
* **DSP** — **Digital Signal Processor / digital signal processing（デジタル信号プロセッサー／デジタル信号処理）。** Cortex-M33コアに備わる拡張機能で、音声処理やセンサーフュージョンなど、演算量の多い処理に使用されます。
* **MPU** — **Memory Protection Unit（メモリー保護ユニット）。** コードがアクセスできるメモリー領域を制限するハードウェア機構です。障害の分離やセキュリティに利用されます。
* **HAL** — **Hardware Abstraction Layer（ハードウェア抽象化レイヤー）。** チップの具体的なバリアントに依存しない一貫したAPIを通じて、SDKから周辺機能を利用できるようにする層です。
* **AI / MLアクセラレーター** — 人工知能（AI）や機械学習（ML）の処理を高速化するハードウェアです。小規模なニューラルネットワークの推論などに使われます。対応状況はデバイスごとに異なるため、製品セレクターと対象製品のデータシートで確認してください。

## 無線接続 { #wireless-connectivity }

* **BLE** — **Bluetooth Low Energy（低消費電力Bluetooth）。** 多くのSF32ウェアラブル製品やIoT製品の基盤となる、低消費電力のBluetooth無線方式です。
* **Wi-Fi** — 無線LAN技術です。SF32製品の資料に外付けWi-Fiへの対応が明記されている場合、SDIOインターフェースを介して接続します。設計を確定する前に、対象製品、基板上の配線、電源、ソフトウェアの対応状況を確認してください。
* **デュアルモードBluetooth** — 同一の無線でBLEとClassic Bluetooth（BR/EDR）の両方をサポートすることです。Classic BluetoothまたはLE Audioによる音声ストリーミングと、低消費電力の制御チャネルを併用する製品などで使われます。SF32LB52x/56x/57x/58xが対応し、SF32LB55xはBLEのみ対応します。
* **GAP** — **Generic Access Profile（汎用アクセスプロファイル）。** デバイスの役割、アドバタイジング、接続確立を管理するBluetoothのレイヤーです。BLEアプリケーションの基盤となります。
* **GATT** — **Generic Attribute Profile（汎用属性プロファイル）。** サービスとキャラクタリスティックの構造、およびBLEデバイスが公開するデータの交換方法を定めるBluetoothのレイヤーです。
* **Sibles** — 標準のGAPレイヤー上に構築された、SiFli-SDKのGATTサービスフレームワークです。多くのSF32 Bluetooth製品では、GATTデータベースを一から構築するのではなく、既存のSiblesベースのサンプルを出発点にします。[Bluetoothの概要](../learn/bluetooth/overview.md)を参照してください。
* **LE Audio** — LC3コーデックやAuracastブロードキャストオーディオを含む、新しいBluetooth Low Energyオーディオ規格です。Classic Bluetoothのオーディオプロファイルとは異なります。SF32LB52x/56x/57x/58xが対応し、SF32LB55xは対応していません。[BluetoothオーディオとLE Audio](../learn/bluetooth/processor.md)を参照してください。
* **OTA** — **Over-The-Air（無線経由のファームウェア更新）。** 有線接続ではなく、通常はBLEなどの無線リンクを介してデバイスのファームウェアを更新することです。
* **DFU** — **Device Firmware Update（デバイスファームウェア更新）。** デバイスのファームウェアを更新する仕組みやプロトコルの一般的な分類です。Bluetooth経由のOTA更新では、通常DFUの仕組みが使われます。

## グラフィックスとディスプレイ { #graphics-and-display }

* **ePicasso** — SF32ファミリー向けにSiFliが独自開発した2D/2.5Dグラフィックスアクセラレーションエンジンです。画像のコピー、ブレンディング、拡大縮小、回転、レイヤー合成などのピクセル処理をアプリケーションCPUからオフロードします。[ePicasso 2D / 2.5D グラフィックスエンジン](../learn/graphics/epicasso-gpu.md)を参照してください。
* **eZip** — SiFli独自のロスレス画像・汎用圧縮形式です。対応するSF32デバイスでは、ハードウェアでデコードできます。画像ではPNGをわずかに上回る圧縮率が得られるとSiFliは説明しています。汎用データの圧縮率は元データによって異なります。圧縮データはデコード前にバスを通るため、eZipはPSRAMやNOR Flashなどの外部メモリーからの転送帯域を削減できます。
* **TurboPixel** — 対応するSF32製品で使われる、固定圧縮率の非可逆フレームバッファー形式です。extDMAがレンダリング済みビットマップをTurboPixelに圧縮し、ディスプレイコントローラーが展開することで、PSRAMの帯域幅と容量を節約します。[TurboPixelフレームバッファー圧縮ページ](../learn/graphics/turbopixel.md)を参照してください。
* **LVGL** — **Light and Versatile Graphics Library（軽量で多機能なグラフィックスライブラリー）。** 多くのSF32製品でアプリケーションのUIに使われる、オープンソースの組み込みUIフレームワークです。ePicassoによる描画アクセラレーションと組み合わせて動作します。
* **HMI** — **Human-Machine Interface（ヒューマンマシンインターフェース）。** 画面、タッチ、ボタンなど、デバイス上のユーザーインターフェースを設計分野として指す略語です。
* **RGB / DPIディスプレイインターフェース** — ピクセルの色情報を対応するパネルまたはディスプレイコントローラーへ直接送るパラレルインターフェースです。正式名称は**DPI（Display Pixel Interface）**で、「RGBインターフェース」は基板設計で一般的に使われる略称です。通常、ピクセルクロック、水平・垂直同期信号、複数のパラレル色情報線を使います。シリアル方式より多くのGPIOを使用し、パラレル配線にも注意が必要です。対象パッケージのピン数とパネルのタイミング要件を確認してください。
* **MIPIディスプレイインターフェース** — MIPI Allianceの規格で定められたディスプレイインターフェースです。対応する高帯域幅パネルに使用されます。
* **EPD** — **Electronic Paper Display（電子ペーパーディスプレイ）。** 低消費電力の反射型画面によく使われる表示技術です。
* **JDIディスプレイインターフェース** — 対象のSF32デバイスで対応が明記されている場合に、JDI / Sharp Memory-in-Pixelディスプレイを接続するためのインターフェースです。

## オーディオ { #audio }

* **ADC / DAC** — **Analog-to-Digital / Digital-to-Analog Converter（アナログ／デジタル変換器）。** オーディオ機能を内蔵するSF32製品の入力フロントエンドと出力経路を指します。専用のオーディオADC/DACはSF32LB52x/56x/57x/58xで利用でき、SF32LB55xには搭載されていません。
* **PDM** — **Pulse-Density Modulation（パルス密度変調）。** オーディオ対応SF32製品でI2Sとともにサポートされる、一般的なデジタルマイクインターフェースです。PDMインターフェースの数とマイクの数は同じではありません。通常、1つのインターフェースに最大2個のデジタルマイクを接続でき、クロックを共有します。片方は立ち上がりエッジ、もう片方は立ち下がりエッジを使って左右のチャンネルを識別します。仕様を確認・比較するときは、マイク数ではなくPDMインターフェース数を基準にしてください。
* **I2S** — **Inter-IC Sound。** コーデック、DAC、その他のオーディオ周辺機器を接続する標準的なデジタルオーディオインターフェースです。

## 電源と信頼性 { #power-and-reliability }

* **PMU** — **Power Management Unit（電源管理ユニット）。** SF32チップに内蔵され、電圧調整（BUCK/LDO出力）を担うブロックです。設計によっては、追加の電源レールを確保するために外付けのSiFli PMIC（例：SF30147C）と組み合わせます。
* **PMIC** — **Power Management IC（電源管理IC）。** MCU内蔵PMUの供給範囲を超える電源レールを追加するための、専用外付けチップです。
* **LDO** — **Low-Dropout regulator（低ドロップアウトレギュレーター）。** リニア方式の電圧レギュレーターで、SF32製品では内蔵PMUの出力段の一つです。
* **BUCK** — スイッチング方式（非リニア）の電圧レギュレーターです。大きな電流を扱う場合、一般にLDOより効率が高く、SF32のPMUにも内蔵されています。
* **TRNG** — **True Random Number Generator（真性乱数生成器）。** 物理的な熱雑音を利用するハードウェアエントロピー源で、暗号鍵の生成やセキュリティ機能に使われます。
* **PSA** — **Platform Security Architecture（プラットフォームセキュリティアーキテクチャ）。** Armのセキュリティフレームワークおよび認証制度です。一部のSF32チップの資料には **PSA Certified Level 1** と記載されています。認証の有無とレベルは、シリーズ全体に一律に当てはめず、対象の型番に対応する公式資料で確認してください。

## ストレージとメモリー { #storage-and-memory }

* **SRAM** — **Static RAM（スタティックRAM）。** アプリケーションコードやデータの実行に使う、高速なオンチップ作業メモリーです。
* **PSRAM** — **Pseudo-Static RAM（疑似スタティックRAM）。** オンチップSRAMを補う大容量の外部メモリーです。SF32モジュールではSystem-in-Packageとして搭載されることが多く、グラフィックスバッファーや大規模なアプリケーションに使われます。
* **NOR / NAND Flash** — ファームウェアやアセットの保存に使われる2種類の不揮発性フラッシュメモリーです。NORはランダム読み出しが速く、XiP（Execute-in-Place、フラッシュ上での直接実行）によく使われます。NAND / SD-NANDはランダムアクセス速度と引き換えに高密度化でき、画像、フォント、ログなどの大容量データの保存に適しています。
* **OPI / QPI / QSPI** — **Octal/Quad Peripheral（またはSerial Peripheral）Interface（8線／4線周辺機器インターフェース）。** フラッシュやPSRAMのインターフェースにおけるピン数と帯域幅の区分です。Quadはデータ線4本、Octalは8本を表し、実現可能なメモリー帯域幅に影響します。
* **eMMC** — **Embedded MultiMediaCard。** 大容量ストレージを備えるSF32設計で使われる、NANDフラッシュを管理するストレージインターフェースです。

## 周辺機器とインターフェース { #peripherals-and-interfaces }

* **GPIO** — **General-Purpose Input/Output（汎用入出力）。** 単純な信号、ボタン、LED、ソフトウェアによるビットバンギング方式のインターフェースに使う、設定可能なデジタルピンです。
* **I/O** — **Input/Output（入出力）。** デバイスがシステムの他の部分とデータや制御信号をやり取りするためのピンや周辺信号を指す一般的な用語です。
* **UART** — **Universal Asynchronous Receiver/Transmitter（汎用非同期送受信機）。** コンソールやデバッグ出力、単純な1対1通信に使う標準シリアルインターフェースです。
* **SPI** — **Serial Peripheral Interface（シリアル周辺機器インターフェース）。** ディスプレイ、フラッシュ、センサーなどの高速周辺機器に使う同期式シリアルバスです。
* **I2C** — **Inter-Integrated Circuit。** センサーや低速周辺機器の設定によく使われる、複数デバイスを接続できる同期式シリアルバスです。
* **SDIO** — **Secure Digital Input Output。** 外付けWi-Fiデバイスを接続するために、対応が明記されたSF32設計で使われるホストインターフェースです。
* **DCMI** — **Digital Camera Module Interface（デジタルカメラモジュールインターフェース）。** 対応するイメージセンサーを接続するパラレルカメラインターフェースです。
* **FreeIO** — SiFliの柔軟なGPIO割り当て機能です。対応信号を、対象デバイスで定められた制約の範囲内で適切なGPIOに割り当てられます。
* **PTM** — **Peripheral Task Machine（周辺タスクマシン）。** 対応デバイスで周辺タスクを決定論的に処理するためのSiFliのハードウェア機能です。
* **RTC** — **Real-Time Clock（リアルタイムクロック）。** メインのアプリケーションクロックドメインとは独立して動作を続けたり、システムを起床させたりできる時刻管理用周辺機器です。

## ハードウェアと製造 { #hardware-and-manufacturing }

* **QFN** — **Quad Flat No-lead package（クワッド・フラット・ノーリード・パッケージ）。** SF32製品で使われるチップパッケージの一種です。ピン数と外形寸法（例：QFN68）で表します。
* **BGA** — **Ball Grid Array package（ボール・グリッド・アレイ・パッケージ）。** デバイス底面に半田ボールを配置するパッケージです。小型化と多ピン化に適しますが、BGA向けのPCB引き出し配線と実装工程が必要です。
* **BOM** — **Bill of Materials（部品表）。** プリント基板アセンブリー（PCBA）の製造に必要な部品、受動部品、機構部品を項目別に記載した正式な一覧です。SiFli推奨の部品やモジュールを優先する大きな理由の一つは、BOMの複雑さを抑えられることです。
* **EDA** — **Electronic Design Automation（電子設計自動化）。** 回路図入力、SPICEシミュレーション、PCBレイアウトを行うソフトウェアの総称です。SF32専用のフットプリントやシンボルについては、[SF32 EDA ツールライブラリ](../hardware/cad-components/eda-tool-libraries.md)を参照してください。
* **AVL** — **Approved Vendor List（承認ベンダーリスト）。** 水晶振動子、レギュレーター、フラッシュなど、SF32ハードウェア設計の電気的許容範囲に照らして検証された、SiFliの認定セカンドソース部品リストです。[SF32 承認ベンダーリスト](../hardware/cad-components/sifli-approved-vendor-list.md)を参照してください。
* **EVB** — **Evaluation Board（評価ボード）。** カスタムハードウェアを製作する前に、設計の立ち上げと検証を行うためにSiFliが提供するSF32リファレンス／開発ボードです。
* **FAE** — **Field Application Engineer（フィールドアプリケーションエンジニア）。** 公開資料だけでは解決できないハードウェア設計上の疑問に対応する、SiFliの技術サポート担当者です。

## ソフトウェアとツール { #software-and-tools }

* **SiFli-SDK** — SF32製品向けのSiFli標準ファームウェア開発キットです。量産ファームウェアの多くが、このリファレンス／ベンダーSDKを基盤としています。
* **SiFli CodeKit** — SiFli-SDK開発向けのVS Code拡張機能です。コマンドラインツールチェーンを直接操作せずに、プロジェクトの作成、設定、ビルド、書き込み、モニターを進められます。
* **RTOS** — **Real-Time Operating System（リアルタイムオペレーティングシステム）。** SF32ファームウェアで一般に使われるOSの分類です。決定論的なスケジューリングと低いオーバーヘッドを特徴とし、SiFli-SDK独自のRTOS統合やZephyrを通じて利用できます。
* **sftool** — SF32開発ボード向けのSiFli製コマンドライン書き込み／復旧ツールです。起動できなくなったボードの復旧にも使えます。
