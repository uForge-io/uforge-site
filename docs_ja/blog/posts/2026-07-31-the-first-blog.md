# 最初のブログ記事 [2026-07-31] { #the-first-blog-2026-07-31 }

これはこのブログの最初の投稿なので、μForge.ioが何のためにあるのかを率直にお伝えするのに良い機会です。

新しいマイクロコントローラーを評価するエンジニアが、複数のデータシートやWiki、フォーラムの投稿をたどって全体像を組み立てなければならない、という状況は避けるべきです。μForge.ioは、SiFliの超低消費電力マイクロコントローラーSF32ファミリーに関する情報を整理し、この課題を解消します。SF32は、ウェアラブルやスマートディスプレイなど、バッテリー駆動のコネクテッド製品向けに、Bluetooth接続とグラフィックス機能を備え、AIoTを見据えて設計されています。データシート、Wiki、PDFに分散している資料を、実際の製品開発の流れ、つまり部品選定、動作確認、設計への組み込み、出荷に沿って整理しています。詳しくは[μForge.ioについて](../../about/index.md)をご覧ください。

### なぜ今、SF32なのか { #why-sf32-right-now }

SF32を中心にドキュメントプラットフォームを構築する価値があると考えた理由は二つあります。

一つ目はアーキテクチャの幅広さです。SF32は、CPUを高速化してFlashを増やしただけの製品ではありません。ファミリーには、シングルコア、異種デュアルコア、トライコアのマルチメディアプラットフォームがあります。グラフィックスアクセラレーションとハードウェア伸長処理が各プロセッサー構成を補完し、その組み合わせはファミリーによって異なります。製品チームは、アプリケーション性能、常時稼働する処理、統合コストのバランスに応じて構成を選べます。

二つ目は公開性です。SDKのソースコード、ハードウェアアプリケーションノート、設計ガイドは、OpenSiFliのGitHub組織やSiFliのWiki・ドキュメントを通じて公開されており、多くのマイクロコントローラーベンダーにはない開かれた環境が整っています。一方、ESP32やSTM32などのエコシステムと比べると、SF32はすでに採用しているチーム以外にはまだ十分に知られていません。情報は公開されていますが、エコシステム全体にはまだ広く浸透していないのが現状です。だからこそ、エコシステムの成熟を待つのではなく、今こうしたドキュメントを整える意味があります。

### この1か月で起きたこと { #whats-happened-over-the-past-month }

この1か月で、最初の構想から[Zensical](https://zensical.org/)を使った実用的なドキュメントサイトを形にしました。これを可能にした静的サイトジェネレーターを開発したZensicalチームにも感謝します。個々の記事を書き始める前に、サイト全体の情報設計を何度も見直しました。組織図やベンダーの既存ドキュメントの構成をなぞるのではなく、エンジニアが実際にプロジェクトを進める流れに沿って情報を整理することを目指しました。構成が固まった後、SF32LB52x、SF32LB55x、SF32LB56x、SF32LB57x、SF32LB58xの各チップファミリーについて、製品紹介、比較データ、ハードウェア設計ガイドを整え、関連するモジュールと開発ボードも紹介しました。5つのデータシートを一つずつ照合しなくても、電源、メモリー、ディスプレイ、インターフェースの要件からチップやモジュールを絞り込める、インタラクティブな製品セレクターも公開しました。さらに、入門からチュートリアルへ進む導線、学習セクションのアーキテクチャ解説（STAR-MC1、PSRAMとメモリーの種類、PTM）、回路図から量産までを見据えた製品化ガイダンスも用意しました。

### 次にすること { #whats-next }

まずは情報の網羅性と正確性を高めます。ハードウェア設計ガイドとチェックリストを拡充し、SiFliの公式ドキュメントが更新されるたびに内容を照合します。その後は、リファレンスデザインや開発・チュートリアルの実践例を増やし、実際の調達に関する質問を踏まえて製品セレクターも継続的に改善していく予定です。
