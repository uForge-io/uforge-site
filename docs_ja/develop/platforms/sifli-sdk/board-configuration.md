# ボード設定 { #board-configuration }

ボード設定は、ファームウェアの設定を実際のハードウェアに合わせるためのもので、Flash 配置、PSRAM、ピン、ディスプレイインターフェース、オーディオ経路、クロック、電源レール、既定の周辺機器を扱います。

SiFli-SDK では、`--board=<board_name>` が最も重要なビルド入力です。この値によって、サンプルが使用するボードサポートパッケージが選ばれます。

デュアルコアボードでは、コアのサフィックスを省略すると、デフォルトで HCPU の構成が選択されます。LCPU 向けにビルドするにはボード名に `_lcpu` を付け、HCPU を明示するには `_hcpu` を付けます。選択したコアがサンプルでサポートされていることも確認してください。

## ボード選択によって変わり得る項目 { #what-the-board-name-controls }

選択したボードによって、次の項目が変わる場合があります。

- チップとパッケージのバリアント。
- Flash と PSRAM の配置。
- HCPU/LCPU のビルドターゲット。
- ピン多重化と周辺機器の利用可否。
- UART のダウンロード設定。
- ディスプレイとタッチの設定。
- オーディオコーデックの経路。
- Bluetooth の設定。
- パーティションテーブルと起動時の前提条件。

## 実務上のルール { #practical-rules }

- 製品のマーケティング名からボード名を推測しない。
- Zephyr や Arduino のボード名を SiFli-SDK に流用しない。
- GPIO、ADC、PWM、I2C、SPI、ディスプレイのリソースを選ぶ際は、ボードの回路図または開発キットのページを確認する。
- 同じボード向けの最も近い SDK サンプルから始める。
- ボードを切り替えた後はクリーンビルドする。

## ボード立ち上げチェックリスト { #board-bring-up-checklist }

- [ ] チップのバリアントとパッケージを確認する。
- [ ] Flash と PSRAM の種類、容量、構成を確認する。
- [ ] 電源と充電器の動作を確認する。
- [ ] このボードで使用するクロック源と周波数を確認する。該当する場合は 48 MHz と 32.768 kHz も確認する。
- [ ] ダウンロード用 UART とログ用 UART を確認する。
- [ ] ディスプレイとタッチのインターフェースを確認する。
- [ ] オーディオを使う場合、その経路を確認する。
- [ ] 起動ピンとリセット動作を確認する。
- [ ] パーティション配置を確認する。

手元にあるハードウェアとボード設定が一致するまでは、アプリケーションのデバッグを始めないでください。

## SDK ボード名の例 { #sdk-board-name-example }

<div align="center"><em>表: SF32LB52-DevKit-LCD_N16R8 の SDK ボード名</em></div>

<div align="center" markdown>

| 名称の種類 | 識別子 |
|:-----------|:-------|
| ボードモデル | `SF32LB52-DevKit-LCD_N16R8` |

</div>

SiFli-SDK では SDK の識別子を `--board` に指定してください。製品名はビルド識別子として使えません。

## カスタムボードへ移植する場合 { #when-porting-to-a-custom-board }

最も近い開発キットまたはモジュールの設定を基に、次の項目を変更します。

1. Flash と PSRAM の設定。
2. ピン多重化。
3. コンソール／ダウンロード用 UART。
4. ディスプレイ／タッチ／オーディオのリソース。
5. 電源と充電器の前提条件。
6. パーティション配置。
7. 製品固有の周辺機器。

変更ごとに、その機能を動かす最小構成のサンプルで検証してください。
