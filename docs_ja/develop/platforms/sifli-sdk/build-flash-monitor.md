# ビルド、書き込み、シリアル出力の確認 { #build-flash-monitor }

このページでは、SiFli-SDK の日常的な開発手順として、環境の有効化、`scons` によるビルド、ボードへの書き込み、ログの確認を順に説明します。

## SDK 環境を有効にする { #activate-the-sdk }

使用する SDK バージョンに対応した[公式インストールガイド](https://docs.sifli.com/projects/sdk/latest/en/sf32lb52x/quickstart/install/index.html)に従って開発環境をインストールしてください。ビルド前に、新しいターミナルを開くたびに SDK のルートディレクトリで export スクリプトを実行し、環境を有効化してください。

=== "macOS / Linux"

    ```bash
    cd ~/OpenSiFli/SiFli-SDK
    . ./export.sh
    ```

=== "Windows"

    ```powershell
    cd C:\OpenSiFli\SiFli-SDK
    .\export.ps1
    ```

export スクリプトは、現在の SDK 作業ツリーに対応する環境を実行中のターミナルに読み込みます。インストールや環境管理の手順は SDK のバージョンによって異なる場合があるため、使用中のバージョンに対応する公式ガイドを参照してください。

## ビルド { #build }

サンプルプロジェクトのディレクトリから実行します。

```bash
scons --board=<board_name> -j8
```

ホストマシンに合わせて `-j` の値を設定してください。ボード名にコアの指定がない場合、SDK はデフォルトで HCPU を選択します。たとえば `sf32lb52-lcd_n16r8` の出力先は `build_sf32lb52-lcd_n16r8_hcpu/` です。ビルド時に確定したボードとコアの組み合わせに対応する出力ディレクトリを使用してください。ボード識別子にコアが含まれている場合は、`_hcpu` を重ねて付けないでください。

## クリーンビルド { #clean-rebuilds }

ボードを切り替える場合や大きな設定変更を行う場合、または不審なビルド成果物を調査する場合は、クリーンビルドを行ってください。サンプルプロジェクトのディレクトリで SCons のクリーンオプションを実行します。

```bash
scons -c
```

ビルドターゲットと生成された一時ファイルおよびオブジェクトファイルを削除します。その後、対象のボード設定で再ビルドしてください。

## Flash 書き込み { #flash }

たとえば `sf32lb52-lcd_n16r8` の HCPU ターゲットでは、ビルドで生成された UART ダウンロードスクリプトを使用します。

=== "macOS / Linux"

    ```bash
    ./build_sf32lb52-lcd_n16r8_hcpu/uart_download.sh
    ```

=== "Windows"

    ```powershell
    build_sf32lb52-lcd_n16r8_hcpu\uart_download.bat
    ```

OpenSiFli は、シリアルインターフェース経由で SiFli SoC と通信するオープンソースのコマンドラインツール [`sftool`](https://github.com/OpenSiFli/sftool) も公開しています。ドキュメントには、Flash の書き込み、読み出し、消去に加え、チップのリセット制御も記載されています。対応チップ、ストレージ種別、コマンドオプションは、ツールの README で確認してください。

## シリアル出力を確認する { #monitor }

ボードとサンプルに合わせて設定したシリアルターミナルを使います。シリアルログには、起動時の出力、RT-Thread の起動メッセージ、アプリケーションの出力、またはシェルプロンプトが表示されます。

次の情報を記録してください。

- ボード名。
- シリアルポート。
- ボーレート。
- ビルドコマンド。
- Flash 書き込みコマンド。
- SDK ブランチまたはリリース。

<div align="center" markdown>

| 手順 | 目的 |
|:-----|:-----|
| 有効化 | 現在のターミナルに SDK 環境を読み込む。 |

| 出力確認 | 起動とアプリケーションの動作を確認する。 |

## 対応するサンプルから始める { #start-from-a-matching-example }

プロジェクトを新規作成する場合や大幅に変更する場合は、ボードと重要なサブシステムに最も適した[SDK サンプル](../../examples/index.md)を選んでください。まずサンプルを変更せずにビルドして書き込み、シリアル出力を確認します。その後、ボード名、SDK リリース、コマンド、期待される出力を、変更後のプロジェクトと併せて記録してください。

[CodeKit](../../tools/codekit.md)を使う場合も、同じ検証記録を残し、エディターでの操作を SDK のコマンドで再現できることを確認してください。

## トラブルシューティング { #troubleshooting }

<div align="center"><em>表: トラブルシューティング</em></div>

<div align="center" markdown>

| 症状 | 確認項目 |
|:-----|:---------|
| ビルドツールが見つからない | 現在のターミナルで `export.sh` / `export.ps1` を再実行する。 |
| ボード名が不明 | SDK の対応ボード資料を確認する。 |
| ダウンロードスクリプトがポートを開けない | シリアルターミナルを閉じ、USB-to-UART ケーブル／コネクターを確認する。 |
| Flash 書き込みが開始しない | ボードの説明書に記載されたダウンロード手順に従ってください。`sf32lb52-lcd_n16r8` の場合は、シリアルポートを選択してからボードを再起動し、2 秒以内に Enter キーを押してダウンロードを開始します。ほかのボードでは各ボード固有の手順に従い、電源、選択したポート、UART 接続も確認してください。 |
| シリアル出力が読めない | ボーレートを確認し、充電専用ではなくデータ通信に対応した USB ケーブルで UART に接続する。 |

</div>

## 引き継ぎチェックリスト { #handoff-checklist }

プロジェクトを別の開発者に引き継ぐ前に、次の情報を含めてください。

- SDK ブランチまたはコミット。
- ボード名。
- セットアップ／インストールのメモ。
- ビルドコマンド。
- Flash 書き込みコマンド。
- モニター設定。
- 起動時に期待される最初のログ行。
- 復旧コマンド。
