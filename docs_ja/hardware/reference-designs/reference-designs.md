# リファレンス設計 { #reference-designs }

リファレンス設計は、製品企画から実装へ進むための出発点です。再利用可能なハードウェア／ソフトウェアの基準構成には、出発点となるハードウェア、ソフトウェアのバージョン、入手可能な設計ファイル、立ち上げ時の証跡、再利用上の制約を明記する必要があります。ここに示す設計の道筋は、その基準構成の構築と検証に役立ちます。ただし、掲載されていること自体が、回路図、BOM、量産向けの適合性検証資料のリリースを意味するわけではありません。

まず[製品を計画する](../../sf32-products/family/product-planning.md)を使って候補を絞り込み、続いて製品に最も近い設計の道筋を選び、ボード検証と製品リスク低減を進めてください。

## リファレンス設計とプロジェクト { #reference-designs-and-projects }

リファレンス設計は **「再利用できる技術的な基準構成は何か」** に答えます。[プロジェクト](../../projects/index.md)は **「その基準構成から、特定製品を統合し、リリース判断までどう進めるか」** に答えます。

<div align="center"><em>表: リファレンス設計とプロジェクトの違い</em></div>

<div align="center" markdown>

| 項目 | リファレンス設計 | プロジェクト |
|:-----|:-----------------|:-------------|
| 主な役割 | 再利用可能な技術的な基準構成。 | 特定製品の統合とリリース判断を進める道筋。 |
| 主な証跡 | ハードウェア／ソフトウェアの基準構成、設計ファイルまたはその入手方法、立ち上げ結果、再利用上の制約。 | 製品上の判断、依存関係、製品に合わせた調整工程、検証ゲート、リリース証跡。 |
| 再利用の想定 | 複数の製品で基準構成を採用し、必要に応じて変更する。 | 1つの製品を完成させるために使い、製品固有の変更を管理する。 |
| 相互参照 | 採用するプロジェクトへのリンクを含む。 | 該当する場合、出発点となるリファレンス設計へリンクする。 |

</div>

## 利用可能な設計の道筋 { #available-journeys }

現在のコネクテッド・ウェアラブルのページは、検証の進め方を示すもので、リリース済みのリファレンスボード設計パッケージではありません。ボードとSDKの固定されたリビジョンの組み合わせ、設計ファイルのリリース、実測による適合性検証記録は、まだ公開されていません。結果を再現可能な基準構成として扱う前に、それらの基準構成を製品ごとに確立し、記録してください。

## 設計の道筋を利用する { #how-to-use-a-journey }

1. 設計の道筋の対象製品と選定済みハードウェアが、設計上の制約に適合することを確認します。
2. 変更を加える前に、指定されたボード上でソフトウェアの基準構成を再現します。
3. 使用したボード名、SDKバージョン、サンプル、ビルド／書き込みコマンド、シリアルログをプロジェクト記録に残します。
4. ディスプレイ、メモリーデバイス、バッテリー経路、RF設計、筐体、インターフェースを変更した場合は、それぞれに製品固有の検証を追加します。
5. 選定したガイド、チェックリスト、AVLの判断、復旧方法、残存リスクを含む結果を[量産に向けた設計](../design-for-production.md)へ引き継ぎます。

## 新しい設計の道筋を追加する { #adding-a-new-journey }

再現可能なリファレンスの基準構成として紹介する前に、対象製品と読者、対応するハードウェア／ソフトウェアのバージョン、前提条件、ソースリポジトリ、マイルストーン、検証基準、測定結果、製品に合わせた調整への引き継ぎを明記してください。まだ計画段階のワークフローである場合は、その状態と不足している証跡を明示し、基準構成が検証済みであるかのように表現しないでください。

再利用可能な基準構成の範囲を超える、製品単位のエンドツーエンドの開発については、[プロジェクト](../../projects/index.md)を利用してください。プロジェクトでは、ハードウェアの基準構成、設計ファイル、量産資料を重複して記載せず、関連するリファレンス設計へリンクします。
