# 学習の概要 { #learn-overview }

**学習**セクションでは、ファームウェアやハードウェアの方針を後から変えにくくなる前に、サブシステムやアーキテクチャを検討できます。各ページでは、SF32の構成要素がどう連携するかに加え、汎用CPUの処理をグラフィックスエンジン、無線コントローラ、AIアクセラレータなどの専用ハードウェアに任せる場面を説明します。また、グラフィックス、無線、オーディオ、AI、メモリを一つの製品に統合し、消費電力の要件も満たすために、何を検証すべきかも扱います。

開発ボードの初回動作確認には[SF32開発の始め方](../getting-started/index.md)、手順に沿って試すには[チュートリアル](../getting-started/tutorials/overview.md)、ソフトウェアの開発手順やサンプルには[開発](../develop/index.md)、部品選定と量産設計には[SF32ファミリー](../sf32-products/family/SF32_family.md)を参照してください。

## ページを組み合わせて使う { #use-the-pages-together }

実際の製品では、複数のサブシステムが関わるのが一般的です。ディスプレイ、BLE、マイクを搭載し、バッテリーのエネルギー予算が限られるウェアラブル機器では、これらを独立した機能として扱えません。画面のリフレッシュはメモリアクセス量と動作時間に、Bluetoothのスケジューリングはウェイクアップ頻度に、オーディオとAIはバッファやレイテンシに影響し、それぞれの判断が製品全体の消費電力予算を左右します。

各ページを設計の一連の流れに沿って活用してください。

1. 最も重要な製品要件と選択したデバイスを出発点にします。必要なディスプレイ、Bluetooth、AI、オーディオ、メモリ、低消費電力の機能が、そのデバイスについて実際に文書化されていることを確認します。
2. アプリケーション統合の前に、各プロセッサの役割とメモリの割り当てを決めます。ワーキングセット、フレームバッファ、モデル、オーディオバッファの配置を計画し、レイテンシが重要な処理で使うコードやデータは適切な低レイテンシメモリに配置します。専用ハードウェアは、その能力と統合上の制約が製品に適合する場合にのみ使用します。
3. 主要なサブシステムの概要から、詳細な実装ページへ進みます。Bluetooth、メモリ、低消費電力へのリンクは、単なる補足情報ではなく、設計上の依存関係を確認するために参照してください。
4. 想定するハードウェア上で、組み合わせ全体を検証します。[開発](../develop/index.md)にあるワークフローと、関連する学習ページで挙げられている測定方法を使い、機能的な挙動、レイテンシ、帯域幅、RF挙動、電力をまとめてテストします。
