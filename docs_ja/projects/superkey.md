# SuperKey多機能マクロキーボード { #superkey-multifunction-macro-keyboard }

## SuperKeyとは { #what-is-superkey }

[SiFliSparks/SuperKey](https://github.com/SiFliSparks/SuperKey) は、ディスプレイを備えた多機能マクロキーボードのSF32LB52ベースのリファレンス実装です。オープンソースのファームウェアはRT-ThreadとLVGL v9上で動作し、128 × 128のGC9107 LCD 3枚、RGB LED 3個、物理キー4個、ロータリーエンコーダー、SHT30温湿度センサーを制御します。また、複合USB HID/CDCデバイスとしてコンピューターに接続します。

SuperKeyは単なるショートカットキーパッドではありません。1つの動作するリファレンスに次の機能を統合しています。

- USB HIDによるキーボードおよびメディア制御の出力。
- USB CDCまたは1 Mbps UARTを介した、PCの性能、天気、設定、電源状態データの取得。
- 性能モニター、天気、時計、ユーティリティ、音楽、カスタムキー割り当てを表示する3画面UI。
- ホストデータの収集、機能設定、ファームウェア更新を行うコンパニオンアプリ [SuperKeyHub](https://github.com/SiFliSparks/SuperKeyHub)。
- オープンな [sf32-keyboard設計](https://oshwhub.com/sifli/sf32-keyboard)による再現可能なハードウェア。

## SF32による実装の利点 { #why-the-sf32-implementation }

SuperKeyはグラフィックス、複数ディスプレイ、複合USBデバイス、キーとエンコーダー、センサー、RGB効果、ファイルシステム、オプションのオーディオを必要とします。SF32LB52では、これらのリアルタイム処理をMCU上で実行できるため、コンパニオンアプリが起動していなくても、デバイスはUIを起動して基本的なHID動作を提供できます。PCのテレメトリーやインターネット上のデータなど、デスクトップOS側で扱うのが適切な処理はホストアプリに任せます。

この分担は、デスクトップコントローラー、ワークフローキーボード、ステータスパネル、小型HMIに適しています。一方で、明確な依存関係も生じます。高度なデータ表示にはコンパニオンアプリ、ドライバー、外部APIが必要です。ファームウェアとホストアプリのバージョン互換性を保つ必要があり、USB接続の喪失、ホストのスリープ、設定の破損についても個別に復旧試験を行う必要があります。

## 目標、対象範囲、開始条件 { #outcome-scope-and-entry-criteria }

**目標:** バージョンを固定したSuperKeyを再現し、HID、CDC、3画面UI、入力、センサー、スリープからの復旧を検証します。そのうえで、ビルド、通信、回帰試験の証拠を製品レビューに引き継げる状態を保ちながら、動作を1種類だけ変更します。

オープンPCBが量産可能であることや、すべてのPCテレメトリー情報、天気サービス、シリアルブリッジ、USBホスト、OSバージョンに互換性があることを、このページは立証するものではありません。株価、天気、性能データは、SuperKeyHubのバージョン、サードパーティAPI、システム権限、ホストのハードウェアに依存する場合があります。

開始前に、次のものを用意してください。

- オープン設計を基に組み立てたSuperKeyハードウェア。GC9107 LCD 3枚、キー、エンコーダー、USBデータ接続を含みます。
- 主に文書化された手順を実施するためのWindows 10/11 PC。SuperKeyHubのリポジトリーはWindowsとmacOSをサポート対象としていますが、選択したOSで書き込み、CDC通信、復旧まで検証してください。
- ファームウェアと互換性のあるバージョンのSuperKeyHub。
- SiFli-SDK環境、再帰的にチェックアウトしたSDKサブモジュール、動作確認済みの書き込み／復旧接続。
- 天気機能を使う場合は、有効なQWeather API Key、API Host、都市設定。
- USB認識、シリアルログ、キー動作、画面状態、スリープ復旧を記録するテスト記録。

## サポート対象の基準構成を選ぶ { #choose-a-supported-baseline }
上流のリリース一覧にはファームウェア [v1.4.2](https://github.com/SiFliSparks/SuperKey/releases/tag/v1.4.2) があり、固定した出発点として利用できます。参照資料からは対応するSuperKeyHubの版を特定できません。Hubのリリースまたはコミットを選び、v1.4.2と組み合わせてテレメトリー、設定、DFUを検証し、バージョン番号だけで互換性を推定せず、テスト済みの組み合わせを記録してください。

<div align="center"><em>表: SuperKeyの基準構成選択</em></div>

<div align="center" markdown>

| 基準構成要素 | 推奨する開始点 | 重要な制約 |
|:-----------------|:--------------|:-----------|
| ファームウェア | SuperKey v1.4.2、またはチームで検証したコミット | ファームウェアとホストプロトコルのバージョンを一致させる必要があります |
| コンパニオン | v1.4.2との互換性を検証したSuperKeyHubのリリースまたはコミット | 参照資料では固定の組み合わせを確認できないため、選択したOSでCDCデータ、設定、DFUを検証する |
| ビルドターゲット | `sf32lb52-superkey`。ボードファイルは`app/boards`にあります | 汎用SF32LB52開発ボード用のターゲットではありません |
| 通信 | まず複合USB HID + CDCを検証し、使用する場合は1 Mbps UARTも別途検証 | 「USBとして認識された」だけでは、HIDとCDCの両インターフェースが機能する証拠にはなりません |
| 更新 | コンパニオンからのCDC DFUと、有線の書き込み／復旧経路を維持 | 中断、バージョン不一致、復旧を検証するまでは、フィールド更新手段とは見なせません |

</div>

SuperKeyの上流CIでは次のターゲットを使用しています。ローカルで実行する前にSiFli-SDK環境をインストールして有効にしてください。

```bash
git clone --recursive https://github.com/SiFliSparks/SuperKey.git
cd SuperKey/SiFli-SDK
./install.sh
. ./export.sh
cd ../app/project
scons --board=sf32lb52-superkey --board_search_path="../boards" -j8
```

WindowsではSiFli-SDK用のPowerShellインストールスクリプトと環境設定スクリプトを使用してください。並列ビルド数は変更できますが、ビルド記録にはボード名、ボード検索パス、サブモジュールのリビジョンを残してください。

```mermaid
flowchart LR
    U["ユーザー\nキーとロータリーエンコーダー"] --> F["SF32LB52ファームウェア\nRT-Thread + LVGL v9"]
    F --> D["GC9107 LCD 3台\nRGB LED、SHT30、オプションのオーディオ"]
    F -->|"USB HID\nキーボードとメディアイベント"| P["Windows / macOSホスト"]
```

障害は、デバイスのハードウェア／ディスプレイ、HID入力、CDC／UARTデータチャネル、コンパニオン／システム権限、外部データサービスの5つの領域に分けて考えてください。天気パネルが空白でも、直ちにファームウェア障害とは限りません。APIキー、API Host、都市設定、データ送信に原因がある可能性があります。

## 段階1 — 未変更のリファレンス基準構成を確立する { #stage-1-establish-the-untouched-reference-baseline }

**目標:** コードを変更する前に、リファレンス全体の経路が動作することを確認します。

1. 上流の組み立て資料に従い、LCDケーブルの向き、スイッチ、エンコーダー、筐体、USBコネクターを確認し、PCBとファームウェアのリビジョンを記録します。
2. 互換性のあるSuperKeyHubをインストールします。デバイスの認識を確認してから、HIDとCDCを個別にテストします。
3. 天気情報の認証情報、ポート、1 Mbpsのシリアル通信を設定します。コンパニオンなしの動作を記録してから接続し、データ送信を有効にします。
4. 3画面の切り替え、キー割り当て、メディア制御、エンコーダー、SHT30データ、LED効果、テレメトリー更新1サイクルを確認します。
5. コールドスタートして再試験します。UIの写真、コンパニオンログ、デバイスログ、バージョン照会の結果を保存します。

**保存する証拠:** ハードウェアリビジョン、ファームウェアタグ／コミット、SDKコミット、コンパニオンのバージョン、OS、ポートとAPIの設定、USB認識、ログ、画面、入力の記録。

**ゲート1の終了条件:** 2回のコールドスタートでHID入力、CDCデータ更新、3画面の操作が完了し、ログまたは観測可能な状態から各障害領域を区別できること。

## 段階2 — 障害と復旧の境界を検証する { #stage-2-validate-fault-and-recovery-boundaries }

**目標:** デスクトップ環境でよく起きる中断が、再書き込みを要するデモ機の状態につながらないことを確認します。

<div align="center"><em>表: SuperKeyの障害・復旧試験</em></div>

<div align="center" markdown>

| テスト | 方法 | 合格を示す証拠 |
|:-------|:-----|:---------------|
| コンパニオンなし | SuperKeyHubを終了してデバイスを再起動 | ローカルUIとHIDは動作し、コンパニオン依存の値は古い値または利用不可と分かる状態になる |
| CDC切断 | データ送信中にUSBを抜き差しするか、ポートを変更 | デバイスがハングせず、再接続後にバージョン照会とデータ送信が復旧する |
| ホストのスリープ | `power_mode sleep/normal`を有効にして、ホストのスリープ／復帰を1サイクル実行 | LCD、LED、バックライト、センサーが意図どおり停止／再開し、その後のデータ更新も復旧する |
| バージョン不一致 | 管理された環境で互換性のないコンパニオン／ファームウェアの組み合わせを試す | 互換性のない更新を適用せず、動作を拒否するか診断可能なエラーを表示する |
| API障害 | 無効な天気設定を使うか、ネットワークを切断 | 天気機能の障害がHID、CDC、ローカルUI、復旧に影響しない |
| DFU中断 | 復旧可能な試験機で更新を中断 | 維持している有線書き込み経路で既知のイメージを復元できる |

</div>

**ゲート2の終了条件:** 該当する各障害について、文書化されていない手動修復を必要とせず、再現可能な検出・復旧結果が得られていること。

## 段階3 — 再現可能なソースの基準構成を整える { #stage-3-build-a-reproducible-source-baseline }

**目標:** 別のエンジニアがクリーンなチェックアウトから段階2を再ビルド、書き込み、再試験できるようにします。

1. 再帰的にクローンし、SuperKeyとSiFli-SDKの両方のコミットを記録します。
2. `sf32lb52-superkey`と`../boards`の検索パスを指定してクリーンビルドします。
3. ビルドログ、メモリー／パーティション出力、書き込みスクリプト、生成イメージ、シリアルログを保存します。
4. 2台目のPCまたはビルドディレクトリを削除した環境で再ビルドし、同じハードウェアに書き込んで主要な回帰試験を繰り返します。

**ゲート3の終了条件:** 未追跡ファイル、古い成果物、手動で差し替えたバイナリーに依存せず、段階2に合格するイメージを生成できること。

## 段階4 — 製品の変数を1つずつ変更する { #stage-4-adapt-one-product-variable-at-a-time }

**目標:** 合格済みのリファレンスを維持しながら、変更の影響範囲を検証します。

<div align="center"><em>表: SuperKeyの変更を段階的に進める順序</em></div>

<div align="center" markdown>

| 変更の種類 | 最初に試す変更 | 必要な回帰試験 |

## 段階5 — 製品化準備のレビュー { #stage-5-product-readiness-review }

カスタムハードウェアやパイロット生産の前に、チームは次の質問に答える必要があります。

- 製品がSuperKeyHub、管理者権限、サードパーティの天気サービスに依存し続けるか。依存先の責任者は誰か。
- ファームウェア、コンパニオン、プロトコルのバージョンをどう管理し、互換性のない組み合わせをどう防ぐか。
- 対象PC、USBハブ、ケーブル、スリープポリシー、セキュリティソフトの組み合わせのうち、どれを試験したか。
- 3画面、USBデータ、LED、センサー、オプションのオーディオを同時に動作させたときのメモリー使用量、温度、消費電流はどうか。
- 電源断やストレージ破損後に、設定、キー割り当て、更新状態をどう復旧するか。
- オープンPCB、筐体、フォント、アイコン、音楽、サードパーティAPIのライセンスは予定する配布形態を許可しているか。

**ゲート5の終了条件:** 残る各リスクに担当者、証拠、対応方針が割り当てられ、「続行／保留／中止」の判断が記録されていること。
