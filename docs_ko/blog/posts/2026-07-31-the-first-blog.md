# 첫 번째 블로그 글 [2026-07-31] { #the-first-blog-2026-07-31 }

이 블로그의 첫 번째 글이므로, μForge.io가 무엇을 위한 것인지 분명하게 밝히려 합니다.

새로운 마이크로컨트롤러를 평가하는 엔지니어가 웹 곳곳에 흩어진 데이터시트, 위키 페이지, 포럼 글을 일일이 이어 붙여 전체 그림을 파악해야 해서는 안 됩니다. μForge.io는 SiFli의 SF32 초저전력 마이크로컨트롤러 제품군에 관한 정보를 한곳에 모았습니다. Bluetooth 연결과 그래픽 기능을 갖춘 이 디바이스는 웨어러블, 스마트 디스플레이, 그 밖의 배터리 구동 커넥티드 제품 같은 AIoT 제품을 대상으로 합니다. 보통 데이터시트, 위키, PDF에 흩어져 있는 레퍼런스 자료를 실제 제품 개발 경로, 즉 부품 선택, 동작 검증, 설계 통합, 출시에 맞춰 정리합니다. 더 자세한 설명은 [μForge.io 소개](../../about/index.md)를 참조하십시오.

### 지금 SF32인 이유 { #why-sf32-right-now }

SF32를 중심으로 문서 플랫폼 전체를 구축할 만한 이유는 두 가지입니다.

첫째는 아키텍처의 폭입니다. SF32는 플래시 용량이 더 큰 빠른 CPU에 그치지 않습니다. 이 제품군은 싱글 코어 디바이스, 이기종 듀얼 코어 설계, 트라이 코어 멀티미디어 플랫폼에 걸쳐 있습니다. 이러한 프로세서에 그래픽 가속과 하드웨어 압축 해제 기능이 더해지며, 구체적인 조합은 제품군마다 다릅니다. 덕분에 제품 팀은 애플리케이션 성능, 상시 동작 작업, 통합 비용 사이에서 균형을 잡는 다양한 방법을 선택할 수 있습니다.

둘째는 생태계가 보기 드물게 개방적이라는 점입니다. SDK 소스, 하드웨어 애플리케이션 노트, 설계 가이드는 OpenSiFli의 GitHub 조직과 SiFli의 자체 위키 및 문서를 통해 공개되어 있으며, 이는 많은 마이크로컨트롤러 업체가 따라오지 못하는 수준의 접근성입니다. ESP32나 STM32 같은 생태계와 비교하면 SF32는 이미 사용 중인 팀 밖에서는 아직 거의 알려지지 않았습니다. 자료는 정말로 개방되어 있지만 플랫폼의 인지도는 아직 높지 않습니다. 생태계가 스스로 따라잡기를 기다리지 않고 지금 이 문서를 정리하는 것이 유용한 이유입니다.

### 지난 한 달 동안 있었던 일 { #whats-happened-over-the-past-month }

처음의 구상에서 출발하여 [Zensical](https://zensical.org/)로 구축한 동작하는 문서 사이트까지 만들었습니다. 이를 가능하게 한 정적 사이트 생성기를 만들어 준 Zensical 팀에 감사드립니다. 개별 페이지를 쓰기 전에, 조직도나 벤더의 기존 문서가 아니라 엔지니어가 프로젝트에 접근하는 방식을 반영하도록 사이트 구조를 반복해서 다듬었습니다. 구조가 자리를 잡은 뒤에는 SF32LB52x, SF32LB55x, SF32LB56x, SF32LB57x, SF32LB58x 칩 제품군을 다루는 콘텐츠를 만들었습니다. 소개, 비교 데이터, 하드웨어 설계 가이드는 물론 해당 모듈과 개발 보드에 관한 정보도 포함됩니다. 전력, 메모리, 디스플레이, 인터페이스 요구 사항으로 칩과 모듈을 걸러 주는 대화형 제품 선택기도 공개하여, 데이터시트 다섯 개를 직접 대조해야 하는 수고를 덜었습니다. 이제 사이트에는 시작하기와 튜토리얼 경로, Learn의 아키텍처 심층 분석(STAR-MC1, PSRAM과 메모리 유형, PTM), 회로도 단계에서 출시 하드웨어까지 설계를 끌고 가기 위한 양산 준비 가이드가 포함되어 있습니다.

### 다음 계획 { #whats-next }

당장의 중점은 커버리지와 정확성입니다. 하드웨어 설계 가이드와 체크리스트를 확충하고, SiFli의 공식 문서가 업데이트되는 대로 그에 맞춰 콘텐츠를 계속 검증합니다. 그 이후에는 더 많은 레퍼런스 디자인, Develop과 튜토리얼의 더 많은 실제 예제, 그리고 실제 소싱 질문이 들어오는 대로 제품 선택기의 지속적인 개선을 기대하셔도 좋습니다.
