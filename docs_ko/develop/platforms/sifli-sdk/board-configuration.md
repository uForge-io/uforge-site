# 보드 설정 { #board-configuration }

보드 설정은 펌웨어를 실제 하드웨어와 연결합니다. 플래시 레이아웃, PSRAM, 핀, 디스플레이 인터페이스, 오디오 경로, 클럭, 전원 레일, 기본 주변 장치가 여기에 해당합니다.

SiFli-SDK에서 `--board=<board_name>` 값은 가장 중요한 빌드 입력입니다. 이 값은 예제가 사용하는 보드 지원 패키지를 선택합니다.

듀얼 코어 보드에서 코어 접미사를 생략하면 기본적으로 HCPU 설정이 선택됩니다. LCPU용으로 빌드하려면 보드 이름에 `_lcpu`를 붙이고, HCPU를 명시적으로 선택하려면 `_hcpu`를 사용합니다. 선택한 코어를 예제가 지원하는지 확인하십시오.

## 선택한 보드가 영향을 줄 수 있는 항목 { #what-the-board-name-controls }

선택한 보드는 다음에 영향을 줄 수 있습니다.

- 칩 및 패키지 변형(variant).
- 플래시 및 PSRAM 레이아웃.
- HCPU/LCPU 빌드 타깃.
- 핀 먹스와 주변 장치 사용 가능 여부.
- UART 플래싱 설정.
- 디스플레이 및 터치 설정.
- 오디오 코덱 라우팅.
- Bluetooth 설정.
- 파티션 테이블과 부트 관련 가정.

## 실무 규칙 { #practical-rules }

- 마케팅 이름으로 보드 이름을 추측하지 마십시오.
- Zephyr나 Arduino의 보드 이름을 SiFli-SDK에 복사하지 마십시오.
- GPIO, ADC, PWM, I2C, SPI 또는 디스플레이 리소스를 선택할 때는 보드 회로도나 개발 키트 페이지를 열어 두십시오.
- 같은 보드에 대해 가장 가까운 SDK 예제에서 시작하십시오.
- 보드를 전환한 후에는 클린 빌드를 수행하십시오.

## 보드 브링업 체크리스트 { #board-bring-up-checklist }

- [ ] 칩 변형과 패키지를 확인합니다.
- [ ] 플래시와 PSRAM의 종류, 용량, 설정을 확인합니다.
- [ ] 전원 소스와 충전기 동작을 확인합니다.
- [ ] 해당하는 경우 48 MHz와 32.768 kHz를 포함하여, 이 보드가 사용하는 클럭 소스와 주파수를 확인합니다.
- [ ] 플래싱 UART와 로그 UART를 확인합니다.
- [ ] 디스플레이 및 터치 인터페이스를 확인합니다.
- [ ] 사용하는 경우 오디오 경로를 확인합니다.
- [ ] 부트 핀과 리셋 동작을 확인합니다.
- [ ] 파티션 레이아웃을 확인합니다.

보드 설정이 눈앞의 하드웨어와 일치할 때까지는 애플리케이션 디버깅을 시작하지 마십시오.

## SDK 보드 이름 예시 { #sdk-board-name-example }

<div align="center"><em>표: SF32LB52-DevKit-LCD_N16R8 SDK 보드 이름</em></div>

<div align="center" markdown>

| 이름 유형 | 식별자 |
|:----------|:-----------|
| 보드 모델 | `SF32LB52-DevKit-LCD_N16R8` |
| SiFli-SDK `--board` 값 | `sf32lb52-lcd_n16r8` |

</div>

`--board`에는 SiFli-SDK 식별자를 사용하십시오. 제품 이름은 빌드 식별자가 아닙니다.

## 커스텀 보드로 포팅할 때 { #when-porting-to-a-custom-board }

가장 가까운 개발 키트 또는 모듈 설정에서 시작한 뒤 다음 항목을 변경합니다.

1. 플래시 및 PSRAM 설정.
2. 핀 먹스.
3. 콘솔/플래싱 UART.
4. 디스플레이/터치/오디오 리소스.
5. 전원 및 충전기 가정.
6. 파티션 레이아웃.
7. 제품별 주변 장치.

각 변경은 해당 기능을 확인할 수 있는 가장 작은 예제로 검증하십시오.
