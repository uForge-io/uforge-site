# SF32 승인 업체 목록 { #sf32-approved-vendor-list }

## 이 목록의 용도 { #what-this-list-is-for }

**승인 업체 목록(AVL)**은 SF32 설계에 대한 SiFli의 부품 인증 내역을 기록합니다. V0.3에는 패시브 크리스털, buck 인덕터, NOR/NAND 플래시, SD-NAND, LCD 드라이버 하나가 등재되어 있으며, 터치 컨트롤러 시트에는 항목이 없습니다. 후보 부품과 세컨드 소스를 고르는 데 사용하고, 선택한 정확한 부품은 사용자의 PCB에서 펌웨어, 인클로저, 생산 공정, 공급망과 함께 검증하십시오. AVL에 등재되었다고 해서 제품 수준의 검증이 면제되지는 않습니다.

이 페이지는 SiFli 공식 AVL 스프레드시트인 **`SIFLI-MCU-AVL-认证表`, V0.3 (2026-01-21)**을 바탕으로 직접 작성했습니다. 추가 부품이 인증되면서 AVL은 바뀔 수 있으며, 이 페이지는 라이브 데이터베이스가 아니라 날짜가 명시된 V0.3 릴리스를 반영합니다. 이번 검토는 V0.3의 내용만 확인한 것이며, 등재된 부품이 이후 AVL 리비전에서도 계속 승인 상태인지는 확인하지 않았습니다. BOM을 확정하기 전에 최신 원본 파일을 확인하십시오.

!!! note "이 목록 사용 방법"
    원본은 크리스털과 buck 인덕터에 대한 일반 요구 사항을 제공하고, 나머지 표는 주로 개별 부품 데이터를 기록합니다. 명시된 요구 사항은 추가 후보를 걸러내는 데 사용하되, 등재된 모든 부품이 모든 일반 한계를 만족한다고 가정하지 마십시오. 원본의 불일치 사항은 아래에 표시했습니다. 플래시 기록 도구 지원처럼 원본의 모든 행에서 비어 있는 열은 검증된 지원으로 오해되지 않도록 생략했습니다. 상세 표에서 대시(—)는 일반적으로 V0.3이 해당 필드의 값을 제공하지 않는다는 뜻입니다. 다만 NOR 플래시 DTR 클럭 셀에서는 원본의 명시적인 "미지원" 항목을 나타냅니다. 아래 NOR 플래시 참고를 확인하십시오.

BOM 결정은 부품 번호 하나를 골라 넘어가지 말고 다음 세 단계로 진행하십시오.

1. **요구 사항을 기준으로 후보를 선정합니다.** 용량, 전압 레일, 패키지와 부품 분류별 요구 사항(크리스털은 부하 커패시턴스, 인덕터는 DCR/Isat, 플래시는 SDR/DTR 클럭)을 회로도와 전력 예산에 맞춥니다.
2. **데이터시트의 대표 수치에는 드러나지 않는 제약을 확인합니다.** 제품의 동작 및 보관 환경에 대한 온도 범위, 펌웨어가 기대하는 정확한 Manufacturer/JEDEC ID, 같은 계열의 부품이 아니라 해당 부품 자체에서 OTA, 파일 시스템, 플래싱 툴 지원이 실제로 검증되었는지를 확인합니다.
3. **양산에 들어가기 전에 실제 하드웨어에서 검증합니다.** 자체 보드에서 Standby/동작 전류를 측정하고, 최종 PCB와 인클로저에서 크리스털 RF 캘리브레이션을 다시 확인하며, 단일 업체 품목마다 세컨드 소스를 하나 이상 확보합니다.

## 크리스털 { #crystal-oscillators }

AVL은 48 MHz 시스템 크리스털과 32.768 kHz RTC 크리스털을 다룹니다. 클럭 소스 요구 사항은 해당 SF32 디바이스의 설계 가이드를 따르고, 그다음 부하 커패시턴스, 주파수 허용 오차, ESR, 시작 동작, 전력 예산을 기준으로 선택하십시오. 아래의 인증 표는 모든 SF32 제품에 공통으로 필수인 단일 클럭 구성을 정하지 않습니다.

!!! tip "RF 캘리브레이션 열의 의미"
    **CBANK_SEL**은 SiFli의 인증 데이터에 보고된 트림 설정입니다. **TX Ch39 주파수 오프셋**은 원본의 테스트 레이블과 세 온도 지점의 결과를 그대로 유지합니다. 워크북은 Bluetooth 모드나 테스트 주파수를 명시하지 않으므로, 이것이 BLE 광고 채널 39나 특정 중간 대역 채널을 뜻한다고 가정하지 마십시오. 결과를 비교하거나 트림 설정을 보드에 적용하기 전에 테스트 구성과 캘리브레이션 절차를 확인하십시오. 일반 요구 사항은 ESR ≤30 Ω이지만 TKD 행 세 개는 ESR ≤40 Ω으로 등재되어 있습니다. 이 원본 불일치도 확인이 필요합니다.

크리스털 표의 추가 전류 수치에는 기준 조건과 전체 테스트 구성에 대한 문서가 없습니다. 이 값은 크리스털 단독의 공급 전류가 아니므로, 후보를 비교하거나 시스템 전력 예산에 값을 사용하기 전에 측정 정의를 확인하십시오.

워크북은 모든 부품에 대해 세 개의 개별 테스트 온도(−35°C, 25°C, 105°C)에서 32.76 kHz를 보고합니다. 이 표시 정밀도는 ppm 수준의 정확도나 연속적인 온도 범위에서의 성능을 보증하지 않습니다. 위의 백분율 값은 원본 헤더가 `TX_CH39_Freq_offset(KHz)`인 열에 나타나지만, 형식으로 보면 듀티 사이클 측정값으로 보입니다. 듀티 사이클 한계로 사용하기 전에 SiFli에 그 의미를 확인하십시오. 또한 105°C 테스트 지점이 등재된 −40°C~+85°C 동작 범위를 넓혀 주지는 않습니다. ## NOR 플래시 { #nor-flash }

V0.3에는 4 Mb에서 256 Mb까지 NOR 플래시 부품 44개가 용량별로 묶여 등재되어 있습니다. 클럭 값은 등재된 메모리 디바이스의 사양이며, 모든 SF32 디바이스나 보드에서의 동작 속도를 보증하지 않습니다. 정확한 설계에 맞게 읽기 명령 지원, 컨트롤러 한계, 타이밍, 드라이버 식별을 확인하십시오. 원본은 16진수 식별 값을 “Manufacture ID”로 표기하지만 여기에는 디바이스 식별 필드가 포함되어 있으므로, 제조사 바이트만 비교하지 말고 기대하는 전체 응답을 비교하십시오. 동작 및 Standby 전력을 계산할 때는 문서화된 동작 조건에서의 전류 값을 사용하십시오.

## SPI-NAND 플래시 { #spi-nand-flash }

V0.3에는 512 Mb와 1 Gb의 SPI-NAND 부품 18개가 등재되어 있습니다. 호환되는 드라이버와 소프트웨어 스택이 있으면 파일 또는 데이터 스토리지로 사용할 수 있으며, FatFS, FlashDB, LittleFS가 그 예이지만 호환성은 선택한 부품에서 검증해야 합니다. NAND의 페이지 접근, ECC, 불량 블록 관리는 NOR의 직접 XIP 접근과 다릅니다. 워크북은 등재된 모든 부품의 **Golden Block**을 `block0`으로 기록하지만, 보증 조건이나 이를 사용하는 펌웨어 루틴은 명시하지 않습니다. 이러한 가정은 디바이스 및 SDK 문서와 대조해 확인하십시오.

GD5F1GM7RE와 GD5F1GM7UE의 경우 원본은 페이지당 `2048+64` 바이트이면서 블록당 `128K+8K` 바이트로 등재합니다. 스페어 영역 수치는 페이지에서 블록으로 단순 계산한 값과 일치하지 않습니다. 두 값을 아래에 그대로 보존했으니, 드라이버를 구성하기 전에 정확한 디바이스 데이터시트로 페이지, 블록, 스페어 영역 구조를 확인하십시오.

플래시 감지를 구현하기 전에 각 부품 데이터시트에서 JEDEC/제조사 ID 시퀀스를 확인하십시오. 옵코드 `0x9F` 이후 반환되는 ID 바이트 수는 업체마다 다릅니다. 일부는 2바이트 디바이스 ID를 `DID1`+`DID2`로 반환하고, 일부는 ID 바이트 하나를 반환합니다. 이러한 차이 때문에 새로운 세컨드 소스 부품을 브링업할 때 "인식되지 않는 플래시" 오류가 발생할 수 있습니다.

### 출처 ID 읽기 시퀀스 { #read-jedec-id-sequences }

워크북에는 다음 세 가지 ID 읽기 형식이 기록되어 있습니다. `MID`는 제조사 ID를, `DID`, `DID1`, `DID2`는 디바이스 ID 필드를 뜻합니다. 이는 원본의 문자열이며 실행 가능한 트랜잭션이 아닙니다. 구현하기 전에 옵코드, 더미/주소 페이즈, 반환 바이트 수, 칩 셀렉트 타이밍을 정확한 디바이스 데이터시트와 대조해 확인하십시오. 부품 표의 16진수 ID가 모두 제조사 ID 바이트 하나인 것은 아닙니다.

| F35SQA512M, F35UQA512M, W25N01GW, W25N01GV, F35SQA001G, TC58CYG0S3HRAIJ | `9F+dummy(8bit)+MID+DID1+DID2` |
| DS35M12B, DS35Q12B, GD5F1GM7RE, GD5F1GM7UE, DS35M1GB, DS35Q1GB, FM25SL01 | `9F+dummy(8bit)+MID+DID` |

</div>

## 설계 검토 체크리스트 { #design-review-checklist }

회로도나 BOM을 확정하기 전에 선택한 각 AVL 부품을 실제 제품 설계에 비추어 검토하십시오.

- [ ] 정확한 부품 번호, 패키지, 온도 등급, 주문 접미사가 승인된 행과 일치하거나 명시적인 엔지니어링 승인 경로가 있습니다.
- [ ] 전압 범위가 보드에서 사용하는 SF32 IO 레일, 플래시 레일, 디스플레이 레일 또는 전원 컨버터 레일과 일치합니다.
- [ ] 패키지, 랜드 패턴, 높이, 조립 제약이 PCB 라이브러리와 제조 공정에 맞습니다.
- [ ] 펌웨어가 해당 부품을 올바르게 식별할 수 있습니다. 해당하는 경우 JEDEC/제조사 ID 또는 동등한 런타임 프로브를 사용합니다.
- [ ] 부팅, 플래싱, OTA, 파일 시스템, 디스플레이 또는 터치 드라이버 동작을 정확한 부품에서 검증했습니다.
- [ ] 저전력 전류를 AVL이나 부품 데이터시트의 값을 그대로 옮기지 않고 실제 하드웨어에서 측정했습니다.
- [ ] 크리스털 주파수 오프셋, CBANK_SEL 동작, RF 캘리브레이션을 최종 PCB, 안테나, 인클로저에서 검증했습니다.
- [ ] 플래시 소거/프로그램/읽기 타이밍을 제품에서 예상되는 전압 및 온도 범위에서 테스트했습니다.
- [ ] 크리스털, 인덕터, 플래시, 디스플레이 패널 같은 고위험 BOM 항목에는 세컨드 소스 후보를 하나 이상 확인했습니다.

이 체크리스트는 의도적으로 "부품이 AVL에 있다"는 기준보다 엄격합니다. AVL은 탐색 범위를 좁혀 줄 뿐이며, 제품 릴리스는 여전히 보드 수준의 증거에 달려 있습니다.

## 소싱 체크리스트 { #sourcing-checklist }

- [ ] 부품 번호와 리비전 접미사를 현재 다운로드 가능한 AVL과 교차 확인합니다. 스프레드시트 스냅샷(이 페이지 포함)은 새 로트가 인증되면서 최신 상태가 아니게 됩니다.
- [ ] 플래시 부품은 브링업 코드가 기대하는 Manufacturer/JEDEC ID가 계열이 아니라 실제 주문한 정확한 부품과 일치하는지 확인합니다. 마케팅 이름은 같아도 서로 다른 ID 바이트를 반환하는 계열이 있습니다.
- [ ] NAND, SD-NAND, 파일 시스템을 뒷받침하는 모든 부품은 실제 하드웨어에서 부팅/플래싱 툴 지원, OTA 업데이트 흐름, 파일 시스템 동작(FatFS/FlashDB/LittleFS)을 검증합니다. 브링업 중 올바르게 읽힌다고 해서 OTA까지 자동으로 검증된 것은 아닙니다.
- [ ] 크리스털은 보드에서 CBANK_SEL과 보고된 TX Ch39 주파수 오프셋을 검증합니다. 워크북은 레퍼런스 레이아웃이나 전체 측정 구성을 명시하지 않으므로, 결과를 비교하기 전에 테스트 모드와 조건을 확인하십시오.
- [ ] 자체 보드에서 Standby, deep-power-down, 동작 읽기 전류를 측정합니다. AVL은 모든 값의 출처나 전체 동작 조건을 보증하지 않으므로 데이터시트와 측정 조건을 확인하십시오.
- [ ] 전기 사양뿐 아니라 패키지와 풋프린트가 PCB 라이브러리 및 조립 역량에 맞는지 확인하십시오.
- [ ] 이 목록에 아직 없는 부품은 BOM에 반영하기 전에 해당 부품 분류의 요구 사항 행에 비추어 인증하고, 인증 데이터를 SiFli와 공유하는 것을 고려합니다.
- [ ] 단일 업체 품목마다 세컨드 소스 후보를 확보합니다. V0.3에는 LCD 드라이버가 하나 등재되어 있고 터치 컨트롤러는 없으므로, 이 스냅샷을 최신 상태로 간주하지 말고 현재 공급 가능 여부와 지원을 확인하십시오.
- [ ] 주요 BOM 동결 전마다 이 목록을 다시 확인합니다. 이 목록은 라이브 데이터베이스가 아니라 스냅샷입니다.
