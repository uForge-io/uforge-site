# 모듈 인터페이스 표준 { #module-interface-standards }

이 절에서는 μForge 모듈 인터페이스를 설명하는 데 사용하는 규칙을 소개합니다. 캐리어 보드 커넥터, 핀 맵, 호환성 주장을 확정하기 전에 먼저 이 절을 읽으십시오. 이 절은 성격이 다른 두 종류의 문서로 연결됩니다. 하나는 공통 용어를 정하는 명명 규칙이고, 다른 하나는 계획에 참고할 수 있지만 선택한 모듈과 제품에 맞게 검증해야 하는 핀 수준 제안입니다.

## 명명과 전기적 호환성 { #what-is-stable-and-what-must-be-verified }

모듈 설명, 회로도, BOM 노트, 제품 문서에서 명명 규칙을 일관되게 사용하십시오. 명명 규칙은 의도한 인터페이스 프로파일을 설명할 뿐, 확정된 전기적 또는 기구적 사양이 아닙니다. 프로파일 이름이나 커넥터 형태가 같다고 해서 모듈과 캐리어 보드 사이의 호환성이 보장되는 것은 아닙니다.

핀 수준 정의는 모든 μForge 모듈이나 SF32 패키지가 할당된 모든 신호, 인터페이스, 동시 사용 조합을 지원한다는 약속이 아닙니다. 설계를 확정하기 전에 선택한 모듈, 칩, 패키지, 하드웨어 설계 가이드를 기준으로 다음 항목을 모두 검증하십시오.

- 커넥터 기구 도면, 키잉, 핀 번호, 조립 제약
- 전원 레일, 전압 도메인, 전류 공급 능력, 시퀀싱
- 인터페이스 사용 가능 여부, 핀 멀티플렉싱, 상호 배타적인 기능
- 신호 무결성, 임피던스, 길이 매칭, ESD, RF 금지 구역 요건
- 디버그, 부트, 복구, 양산 테스트 접근 경로
- 캐리어 보드의 디스플레이, 카메라, 오디오, 스토리지, 무선 보조 기능 요건

## 캐리어 보드 결정 경로 { #carrier-board-decision-path }

1. 모듈을 선택하고 모듈 소개와 하드웨어 설계 가이드를 읽습니다.
2. [M2 인터페이스 명명 규칙](M2%20Interface%20Naming%20Rules.md)을 사용하여 의도한 프로파일을 명확히 합니다.
3. [M2 인터페이스 정의](M2-interface-definition.md)를 사용하여 후보 신호와 공유 충돌을 확인합니다.
4. 사용하는 모든 컨택트를 모듈별 문서와 해당 SiFli 원본 문서에서 확인합니다.
5. 레이아웃을 시작하기 전에 문서 버전, 모듈과 캐리어 보드 리비전, 확인된 예외 사항, 미해결 항목을 회로도 리뷰에 기록합니다.

캐리어 보드 전체 리뷰는 [양산 설계](../design-for-production.md)에서 이어서 진행하십시오. 모듈별 구현 요건은 **하드웨어 설계 가이드** 그룹의 해당 모듈 가이드를 사용하십시오.
