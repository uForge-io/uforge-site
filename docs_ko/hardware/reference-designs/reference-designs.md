# 레퍼런스 디자인 { #reference-designs }

레퍼런스 디자인은 제품 기획과 구현을 연결합니다. 재사용 가능한 하드웨어 및 소프트웨어 기준 구성은 시작 하드웨어, 소프트웨어 버전, 사용 가능한 설계 파일, 브링업 증빙, 재사용 한계를 명시해야 합니다. 여기에 나열된 여정은 이러한 기준 구성을 구성하고 검증하는 데 도움을 주지만, 여정이 포함되어 있다고 해서 릴리스된 회로도, BOM, 양산 인증 패키지가 있다는 뜻은 아닙니다.

[제품 계획하기](../../sf32-products/family/product-planning.md)로 초기 후보 목록을 만든 다음, 아래에서 가장 가까운 여정을 선택하여 보드 검증과 제품 리스크 감소를 진행하십시오.

## 레퍼런스 디자인과 프로젝트 { #reference-designs-and-projects }

**"어떤 재사용 가능한 기술 기준 구성에서 시작할 수 있는가?"** 에 답하려면 레퍼런스 디자인을 사용하십시오. **"특정 제품을 그 기준 구성에서 통합과 릴리스 의사결정까지 어떻게 진행하는가?"** 에 답하려면 [프로젝트](../../projects/index.md)를 사용하십시오.

<div align="center" markdown>

| 항목 | 레퍼런스 디자인 | 프로젝트 |
|:-----|:-----------------|:--------|
| 주요 역할 | 재사용 가능한 기술 기준 구성입니다. | 통합과 릴리스 의사결정에 이르는 제품별 경로입니다. |
| 핵심 증빙 | 하드웨어/소프트웨어 기준 구성, 설계 파일 또는 그 제공 여부, 브링업 결과, 재사용 한계입니다. | 제품 의사결정, 의존성, 적응 단계, 검증 게이트, 릴리스 증빙입니다. |
| 재사용 기대 | 독자가 기준 구성을 채택하고 여러 제품에 맞게 조정할 수 있습니다. | 독자는 하나의 제품 결과를 따라가며, 제품별 변경을 한정된 범위로 적용합니다. |
| 관계 | 이를 채택한 프로젝트로 연결됩니다. | 해당하는 경우, 시작점이 되는 레퍼런스 디자인으로 다시 연결됩니다. |

</div>

## 사용 가능한 여정 { #available-journeys }

현재의 커넥티드 웨어러블 여정은 검증 워크플로이며, 릴리스된 레퍼런스 보드 패키지가 아닙니다. 아직 고정된 보드/SDK 리비전 조합, 설계 파일 릴리스, 측정된 인증 기록을 게시하지 않았습니다. 결과를 재현 가능한 것으로 취급하기 전에 제품에 맞는 기준 구성을 수립하고 기록하십시오.

<div align="center"><em>표: 레퍼런스 디자인 여정</em></div>

<div align="center" markdown>

| 여정 | 제품 중점 | 하드웨어 기준 구성 | 소프트웨어 기준 구성 | 검증 중점 |
|:--------|:--------------|:------------------|:------------------|:--------------------|
| [커넥티드 웨어러블](connected-wearable-journey.md) | 디스플레이, BLE, 센서 입력을 갖춘 소형 배터리 구동 제품입니다. | SF32LB52-DevKit-LCD 또는 적합한 대체 보드를 사용하고, 이어서 선택한 칩 또는 모듈을 기반으로 한 커스텀 보드를 사용합니다. | SiFli-SDK `hello_world`와 제품에 관련된 예제입니다. | 디스플레이, Bluetooth, 센서 동작, sleep/wake, 복구, 양산 설계 증빙입니다. |

</div>

## 여정 사용 방법 { #how-to-use-a-journey }

1. 여정의 제품 중점과 선택한 하드웨어가 설계 제약에 맞는지 확인합니다.
2. 조정하기 전에 명시된 보드에서 해당 소프트웨어 기준 구성을 재현합니다.
3. 정확한 보드, SDK 버전, 예제, 빌드/플래시 명령, 시리얼 로그를 프로젝트 기록과 함께 보관합니다.
4. 변경한 모든 디스플레이, 메모리 디바이스, 배터리 경로, RF 설계, 인클로저, 인터페이스에 대해 제품별 검증을 추가합니다.
5. 선택한 가이드, 체크리스트, AVL 결정, 복구 방식, 남은 리스크를 포함하여 그 결과를 [양산 설계](../design-for-production.md)의 입력으로 사용합니다.

## 새 여정 추가하기 { #adding-a-new-journey }

여정을 재현 가능한 레퍼런스 기준 구성으로 제시하기 전에, 대상 제품과 독자, 지원하는 하드웨어 및 소프트웨어 버전, 사전 요건, 소스 저장소, 마일스톤, 검증 기준, 측정값, 제품 적응 인계 사항을 문서화하십시오. 아직 기획 워크플로 단계라면 그 상태를 명시적으로 표기하고, 기준 구성이 인증된 것처럼 암시하지 말고 부족한 증빙을 나열하십시오.

레퍼런스 경로를 넘어서는 프로젝트 중심의 엔드투엔드 빌드는 [프로젝트](../../projects/index.md)를 사용하십시오. 프로젝트는 하드웨어 기준 구성, 설계 파일, 양산 자료를 중복해서 다루지 말고 관련 레퍼런스 디자인으로 다시 연결해야 합니다.
