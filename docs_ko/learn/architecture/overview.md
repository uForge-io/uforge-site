# 개요 { #architecture-overview }

SF32 디바이스는 프로세서, 메모리, 전용 하드웨어 구성이 서로 다릅니다. 선택한 디바이스에 구현된 블록에 따라, 설계에서 타이밍에 민감하거나 상시 동작해야 하는 작업을 전용 서브시스템 하드웨어에 맡길 수 있습니다. 적합한 가속기가 있는 경우에는 그래픽 처리 같은 작업도 하드웨어에서 실행할 수 있습니다. 이 섹션은 아키텍처 자료를 다섯 가지 엔지니어링 결정을 중심으로 구성합니다. 애플리케이션 코드가 어디에서 실행되는지, 코드와 버퍼가 어디에 위치하는지, 어떤 작업이 무선 컨트롤러에 속하는지, 전용 태스크 엔진이 언제 적합한지, 선택한 디바이스가 필요한 아키텍처 블록과 인터페이스를 제공하는지입니다.

## 실용적인 결정 규칙 { #practical-decision-rule }

다음 순서로 아키텍처를 검토하십시오.

1. 제품 로직, 사용자 인터페이스 동작, 애플리케이션 정책, 일반 드라이버는 애플리케이션 펌웨어에서 구현합니다. 범용 벤치마크가 애플리케이션 성능을 예측해 준다고 가정하지 말고, STAR-MC1 문서를 사용해 선택한 디바이스와 워크로드에서의 프로세서 및 캐시 동작을 평가하십시오.
2. 코드와 데이터를 어디에 둘지 일찍 결정하십시오. UI, 오디오, AI, 연결 기능 워크로드를 확정하기 전에, 지연 시간이 중요한 코드와 데이터를 선택한 메모리 계층의 적절한 수준에 두고 외부 메모리 용량, 인터페이스 대역폭, 전력의 예산을 세우십시오.
3. Bluetooth 컨트롤러 타이밍과 제품 수준 정책을 분리하십시오. Bluetooth 프로세서 자료는 함께 설계해야 하는 컨트롤러, 호스트, 애플리케이션, RF, 저전력 경계를 파악하는 데 도움이 됩니다.
4. 맞춤형 주변 장치 작업은 먼저 기존 타이머, DMA 경로, UART, SPI, I2C, 오디오, 디스플레이 또는 Bluetooth 메커니즘으로 충분한지 확인하십시오. SF32LB57x에서는 요구 사항이 정말로 타이밍에 민감하거나 이러한 표준 블록으로 깔끔하게 표현할 수 없을 때만 PTM을 고려하십시오.

모든 결정에서, 아키텍처 블록이 있거나 사용자가 프로그래밍할 수 있다고 가정하기 전에 선택한 디바이스의 문서화된 기능을 확인하십시오. SF32LB57x 하드웨어 가이드는 16채널 PTM 블록 하나를 문서화합니다. 설계에서 PTM에 의존하기 전에 대상 디바이스의 문서를 확인하십시오.
