# 디스플레이 컨트롤러 { #display-controller }

## 개요 { #overview }

**디스플레이 컨트롤러**(LCDC)는 준비된 픽셀을 선택한 인터페이스를 통해 패널로 전송합니다. 지원되는 디바이스와 구성에서는 출력 중에 TurboPixel 프레임버퍼의 압축을 해제하기도 합니다. LCDC는 단색 배경 위에서 출력 레이어를 제한적으로 알파 블렌딩할 수 있습니다. 문서화된 레이어 구성은 레이어 0과 레이어 1이며, SF32LB52x에서는 레이어 1을 사용할 수 없습니다. 이것은 일반적인 UI 렌더링이나 ePicasso 합성을 대체하지 않습니다. eZip 에셋 디코딩은 별도의 작업으로 유지됩니다.

주요 참고 자료: [SiFli LCDC HAL 문서](https://github.com/OpenSiFli/SiFli-SDK/blob/121aa105565ee6bcbab6a15c1cb3b5571f5cc8e5/docs/source/zh_CN/hal/lcdc.md).

위 링크는 특정 SiFli-SDK 커밋에 고정되어 있습니다. 해당 리비전의 HAL 동작을 문서화한 것이며, 모든 인터페이스, 레이어, 기능을 모든 SF32 디바이스나 패키지, 또는 다른 SDK 버전에서 사용할 수 있다는 근거가 되지는 않습니다. 프로젝트에서 사용하는 정확한 디바이스, 패키지, SDK 릴리스를 확인하십시오.

리소스에서 패널까지의 전체 흐름은 [그래픽 개요](overview.md#sf32-graphics-flow)를 참고하십시오. 이 문서는 컨트롤러, 패널 연결, 드라이버 통합에 초점을 맞춥니다.

패널 인터페이스를 선택하거나, LVGL 플러시 경로를 정의하거나, 새 패널을 하드웨어에서 브링업할 때 이 페이지를 읽으십시오. 컨트롤러 출력 작업을 에셋 디코딩 및 픽셀 합성과 분리하므로, 디스플레이 문제를 올바른 계층에서 격리할 수 있습니다.

## 디스플레이 인터페이스 선택 { #select-the-display-interface }

EPD와 Memory-in-Pixel은 패널 기술 또는 업데이트 동작을 설명하는 용어이며, 서로 바꿔 쓸 수 있는 버스 표준이 아닙니다. EPD 모듈은 외부 컨트롤러에 SPI로 연결될 수 있으며, SF32LB57x에는 LCDC 직접 EPD 모드도 문서화되어 있습니다. JDI에는 신호가 서로 다른 직렬 및 병렬 인터페이스 모드가 있습니다. 디스플레이 범주만 볼 것이 아니라 패널의 전기적 인터페이스와 유지 관리 요구 사항을 맞추십시오.

패널 선택은 대역폭, 버퍼 전략, 핀 사용, 전력, 초기화 복잡도, PCB 위험에 영향을 줍니다. 선택한 디바이스와 패키지에 대해 정확한 인터페이스 목록을 확인하십시오.

<div align="center"><em>디스플레이 인터페이스 및 패널 기술 선택지</em></div>

<div align="center" markdown>

| 인터페이스 또는 패널 유형 | 일반적인 용도 | 설계 참고 사항 |
|:---|:---|:---|
| **3선 / 4선 SPI** | 소형 TFT 또는 AMOLED 패널, 단순한 HMI | 핀 수가 적고 배선이 간단하지만, 전체 화면 애니메이션에는 대역폭이 제한적입니다. |
| **Dual-SPI / Quad-SPI** | 웨어러블 AMOLED 및 소형 디스플레이 | 핀 수를 적당히 유지하면서 기본 SPI보다 대역폭이 높습니다. |
| **8080 MCU 인터페이스** | 병렬 디스플레이 패널 | 직렬 SPI보다 대역폭이 높지만 더 많은 핀을 사용합니다. |
| **RGB / DPI** | 더 크거나 리프레시율이 높은 디스플레이 | 연속 픽셀 스트림이며, 대역폭과 핀 사용량이 높고 타이밍이 더 엄격합니다. |
| **MIPI DSI** | 고밀도 AMOLED 또는 고급 패널 | 적은 핀으로 높은 대역폭을 제공하지만, 초기화와 신호 무결성이 더 복잡합니다. |
| **EPD 패널 기술** | E-paper 및 초저리프레시 디스플레이 | 호스트 인터페이스는 모듈과 컨트롤러에 따라 달라집니다. 정지 이미지는 낮은 패널 전력으로 유지할 수 있으며, 업데이트는 느리고 패널별 파형 및 전원 제어가 필요합니다. |
| **JDI (직렬 또는 병렬)** | 저전력 반사형 패널 | JDI 모드마다 신호가 다릅니다. 선택한 패널의 전기적 인터페이스와 유지 관리 요구 사항을 확인하십시오. |
| **Memory-in-Pixel 패널 기술** | 상시 표시 또는 햇빛 아래에서 읽을 수 있는 UI를 포함한 저전력 반사형 디스플레이 | 픽셀 메모리가 패널에 통합되어 있으며, 리프레시 동작이 TFT/AMOLED와 다릅니다. 패널 데이터시트를 따르십시오. |

</div>

예를 들어 소형 SPI/QSPI 패널은 부분 업데이트에 유리할 수 있지만, RGB/DPI 패널은 지속적인 스캔아웃 대역폭 예산이 필요합니다. 이론상의 처리량만으로 인터페이스를 선택하지 마십시오. 픽셀 포맷, 해상도, 리프레시 동작, 패널 GRAM, 그리고 PSRAM의 다른 사용처를 함께 고려하십시오.

## 디바이스별 인터페이스 매트릭스 { #per-device-interface-matrix }

아래 매트릭스는 제품군 선택을 돕기 위한 것이며 핀 할당표가 아닙니다. 나열된 SF32 제품군 또는 실리콘 변형(variant)에 대해 문서화된 디스플레이 인터페이스를 반영합니다. 대시는 해당 행에 그 인터페이스가 문서화되어 있지 않다는 뜻이며, GPIO로 구동하는 외부 컨트롤러나 보드별 구현의 가능성을 배제하지는 않습니다. 회로도를 확정하기 전에 항상 정확한 오더 코드, 패키지, 핀 멀티플렉싱 설정, SDK 릴리스, 패널 드라이버를 확인하십시오.

<div align="center"><em>SF32 디스플레이 인터페이스 매트릭스</em></div>

<div align="center" markdown>

| SF32 제품군 / 변형 | 문서화된 LCD / 패널 인터페이스 | 패키지 또는 변형 제약 | 실용적인 선택 방향 |
|:---|:---|:---|:---|
| **SF32LB52x** | 3선/4선 SPI, Dual-SPI, Quad-SPI, MCU/8080(MIPI DBI), 직렬/병렬 JDI. SPI로 연결된 EPD. SF32LB52B/D/E/G/J에는 8비트 병렬 EPD 신호 인터페이스도 문서화되어 있습니다. | 나열된 52x 모델은 QFN68L을 사용합니다. 하드웨어 가이드는 52B/D/E/G/J의 신호 할당과 TPS PMIC 제어를 나열하지만, 이것이 LCDC 직접 EPD 모드의 지원을 입증하지는 않습니다. 드라이버와 정확한 변형을 확인하십시오. | 소형 SPI/QSPI, 8080, JDI 설계에 적합합니다. 병렬 EPD의 경우 선택한 변형의 GPIO/타이밍과 TPS 전원 제어 구현을 확인하십시오. |
| **SF32LB55x** | 3선/4선 SPI, Dual-SPI, Quad-SPI, MCU/8080, DPI/RGB, 직렬/병렬 JDI, MIPI DSI 커맨드 모드 | 문서화된 2레인 MIPI DSI 인터페이스는 BGA145/169 패키지에서 사용할 수 있으며, JDI와 MIPI DSI + SPI/DSPI 듀얼 디스플레이 동작은 557VD3A6에만 나열되어 있습니다. 커맨드 모드에는 내부 SRAM/GRAM이 있는 패널 컨트롤러가 필요합니다. | 호환되는 BGA 패키지와 MIPI 커맨드 모드 패널을 사용하는 웨어러블 및 연결형 디스플레이 제품 |
| **SF32LB56xU** | 3선/4선 SPI, Dual-SPI, Quad-SPI, 직렬 JDI | 나열된 U 변형은 QFN68L을 사용합니다. 정확한 오더 코드와 핀 멀티플렉싱 설정을 확인하십시오. | QSPI 대역폭과 적은 핀 수가 우선인 소형 직렬 패널 설계 |
| **SF32LB56xV** | 3선/4선 SPI, Dual-SPI, Quad-SPI, DBI 8080, DPI/RGB, 직렬/병렬 JDI | 나열된 V 변형은 WBBGA175(칩 모델 가이드에서는 BGA175)를 사용합니다. 정확한 오더 코드에 필요한 핀과 보드 배선을 확인하십시오. | 8080, DPI/RGB 또는 병렬 JDI가 필요한 고해상도 또는 고리프레시 설계 |
| **SF32LB57x** | 3선/4선 SPI, Dual-SPI, Quad-SPI, 8비트/16비트 8080/DBI, DPI/RGB, JDI, 직접 EPD | 패키지 옵션에는 QFN68L, QFN80L, BGA112가 있습니다. 정확한 오더 코드, 노출된 핀, 선택한 패널 드라이버 경로를 확인하십시오. | 병렬, 직렬, JDI, EPD 등 폭넓은 디스플레이 요구가 있는 그래픽 중심 설계 |
| **SF32LB58x** | 3선/4선 SPI, Dual-SPI, Quad-SPI, MCU/8080, DPI/RGB, 직렬/병렬 JDI, 2레인 MIPI DSI 커맨드 및 비디오 모드 | 나열된 오더 코드는 BGA256을 사용합니다. 커맨드 모드는 내부 SRAM/GRAM이 있는 패널 컨트롤러를 사용하며, 비디오 모드는 RAM이 없는 패널 컨트롤러도 지원합니다. 모델 가이드에는 듀얼 디스플레이용 MIPI DSI + SPI/DSPI/QSPI도 나열되어 있습니다. 해당 설계의 LCD 컨트롤러와 핀 멀티플렉싱 설정을 확인하십시오. | 듀얼 디스플레이 구성과, 컨트롤러 RAM이 있거나 없는 MIPI DSI 패널을 포함한 고해상도 및 대역폭 요구가 큰 UI 설계 |

</div>

**SF32LB56x**의 경우 U와 V 항목을 서로 바꿔 쓸 수 있는 것으로 취급하지 마십시오. **SF32LB55x**와 **SF32LB58x**의 경우, 정확한 패키지와 해당 DSI 핀, 패널의 레인/모드 요구 사항이 모두 확인되기 전에는 회로도에 MIPI DSI를 확보해 두지 마십시오. 특히 SF32LB55x는 커맨드 모드만 지원하므로 RAM이 없는 비디오 모드 패널은 적합하지 않습니다. EPD 설계에도 패널별 타이밍, 파형, 전원 계획이 필요하며, 인터페이스 이름만으로는 EPD 설계가 완성되지 않습니다.

SiFli 칩 모델 가이드는 DPI/RGB를 SF32LB55x 제품군 수준의 인터페이스로 나열하지만, 오더 코드별 표에서는 나열된 SKU에 DPI를 할당하지 않습니다. 이는 제품군 수준의 근거로만 취급하고, 의존하기 전에 정확한 오더 코드에서 DPI 지원과 핀 사용 가능 여부를 확인하십시오. SF32LB56x의 U/V 구분은 제품군 전체의 HAL 표가 아니라 별도의 하드웨어 애플리케이션 가이드를 따릅니다.

두 SF32LB52x 하드웨어 가이드는 JDI에 관해 서로 일치하지 않습니다. 개요에서는 직렬 JDI를 나열하지만, 상세 JDI 절에서는 병렬 신호 매핑을 보여 줍니다. 매트릭스는 문서화된 두 주장을 모두 유지하지만, 이것이 핀 수준의 보증은 아닙니다. 설계를 확정하기 전에 정확한 변형, LCDC 매핑, SDK/드라이버, 패널 신호를 확인하십시오.

SF32LB52x의 경우 문서화된 8비트 병렬 EPD 신호 인터페이스와 LCDC 직접 EPD 모드를 구분하십시오. SF32LB52B/D/E/G/J 하드웨어 가이드는 병렬 EPD 신호와 TPS PMIC 제어를 나열하며, 이와 별도로 SiFli SDK v2.5.1 릴리스 노트는 SF32LB57x의 LCDC 직접 EPD 지원을 문서화합니다. 52x 설계에서 57x의 LCDC 직접 EPD 경로를 사용할 수 있다고 추론하지 말고, 정확한 변형의 드라이버와 타이밍 구현을 확인하십시오.

인터페이스 출처: [SiFli 칩 모델 가이드](https://wiki.sifli.com/silicon/%E8%8A%AF%E7%89%87%E5%9E%8B%E5%8F%B7%E6%8C%87%E5%8D%97.html), [SF32LB52x 배터리 전원 하드웨어 가이드](https://wiki.sifli.com/hardware/SF32LB520-3-5-7-HW-Application.html), [SF32LB52B/D/E/G/J 하드웨어 가이드](https://wiki.sifli.com/hardware/SF32LB52B-E-G-J-HW-Application.html), [SF32LB55x](https://wiki.sifli.com/hardware/SF32LB55x-HW-Application.html), [SF32LB56xU](https://wiki.sifli.com/hardware/SF32LB56xU-HW-Application.html), [SF32LB56xV](https://wiki.sifli.com/hardware/SF32LB56xV-HW-Application.html), [SF32LB58x](https://wiki.sifli.com/hardware/SF32LB58x-HW-Application.html), [SF32LB57x SDK 지원](https://github.com/OpenSiFli/SiFli-SDK/releases/tag/v2.5.1).

## 컨트롤러, 버퍼, 플러시 경로 { #controller-buffers-and-flush-paths }

LCDC 참조 다이어그램은 보이는 패널 영역, 리프레시 윈도우, 소스 버퍼 영역을 구분합니다. 패널의 열 및 행 오프셋을 일관되게 적용하십시오. 리프레시 윈도우는 소스 버퍼 영역의 일부와만 겹칠 수 있으며, 윈도우 안에서 소스 데이터가 없는 픽셀은 배경색을 사용합니다. 버퍼와 리프레시 윈도우가 같다고 가정하지 말고, 윈도우 좌표, 버퍼 원점, 스트라이드를 함께 확인하십시오.

UI 프레임워크는 변경된 픽셀을 생성하고, 디스플레이 드라이버와 컨트롤러는 이를 패널로 전달합니다. 적절한 경로는 패널에 따라 달라집니다.

- SPI/QSPI 또는 8080 드라이버는 보통 패널 윈도우를 설정하고 변경된 영역만 전송합니다.
- 프레임버퍼를 스캔하는 컨트롤러는 디스플레이 타이밍에 맞춰 메모리에서 픽셀 데이터를 가져옵니다.
- TurboPixel을 지원하는 경로는 압축된 최종 비트맵을 읽어 디스플레이 컨트롤러 단계에서 압축을 해제합니다.

LVGL 설계에서 디스플레이 플러시 콜백은 렌더링과 출력의 경계입니다. 플러시 콜백은 영역을 인식하고, 올바른 DMA 또는 컨트롤러 동작을 시작하며, 프레임워크가 드로우 버퍼를 안전하게 재사용할 수 있을 때에만 완료를 알리는 것이 좋습니다. CPU와 하드웨어가 버퍼를 공유할 때마다 캐시 clean/invalidate 규칙을 명시적으로 유지하십시오.

버퍼 소유권은 실제 전송 경로를 따라야 합니다. 패널 메모리로 전송하는 경우, 하드웨어가 읽기를 마친 뒤에만 드로우 버퍼를 해제하십시오. 연속 스캔아웃의 경우 프레임 인터럽트만으로는 활성 프레임버퍼가 해제되지 않습니다. 컨트롤러가 더 이상 이전 버퍼를 읽지 않음을 의미하는 버퍼 전환이 확인될 때까지 기다리십시오. 전송 완료와 눈에 보이는 패널 리프레시는 별개의 이벤트입니다. 필요한 경우 패널의 TE 또는 프레임 타이밍을 사용하여 티어링을 방지하십시오.

캐시 가능한 공유 메모리의 경우, 하드웨어가 읽기 전에 CPU가 쓴 소스 데이터에 캐시 clean을 수행하십시오. 하드웨어가 쓰기 전에는 플랫폼의 캐시 관리 규칙에 따라 대상 영역을 준비하여, 더티 캐시 라인이 나중에 결과를 덮어쓰지 못하게 하십시오. 하드웨어 작업이 완료된 후 CPU가 읽기 전에 대상 영역에 캐시 invalidate를 수행하십시오. 같은 캐시 라인에 있는 인접 데이터를 포함하여 캐시 라인 정렬과 소유권을 지키십시오.

<div align="center" markdown>

| 결정 사항 | 검증할 방향 |
|:---|:---|
| 플러시 영역 | 패널과 드라이버가 지원하는 경우 변경된 영역만 전송합니다. |
| 버퍼링 | 지연 시간과 메모리 요구 사항에 따라 부분, 전체 프레임, 단일 또는 더블 버퍼링을 선택합니다. |

| 픽셀 포맷 | 패널, 드라이버, 렌더러, 가속기 경로를 일치시켜 핫 패스의 변환을 피합니다. |

</div>

## 부분 리프레시와 더티 영역 { #partial-refresh-and-dirty-regions }

부분 렌더링과 부분 패널 전송은 서로 다른 최적화입니다. 연속적인 RGB/DPI 또는 DSI 비디오 스트림은 작은 메모리 영역만 바뀌어도 전체 프레임을 계속 전송할 수 있습니다. EPD의 경우 파형 지원, 온도 의존성, 잔상(ghosting), 필요한 전체 리프레시 간격을 확인하십시오. 더 작은 업데이트 영역이 항상 유효하다고 가정하지 마십시오.

대부분의 임베디드 UI는 매 프레임마다 전체 화면을 다시 그릴 필요가 없습니다. LVGL은 무효화된 영역을 추적하며, 드라이버는 변경된 영역만 플러시할 수 있습니다. 이는 SPI/QSPI 패널, 배터리로 동작하는 웨어러블, 작은 값만 바뀌는 정적 페이지, EPD, JDI 디스플레이에서 특히 유용합니다.

전체 화면 리프레시는 애니메이션이 많은 화면, 전환 효과, 또는 본래 전체 프레임버퍼에서 스캔하는 패널에 적합합니다. 선택은 UI 프레임워크 설정만이 아니라 디스플레이 인터페이스 대역폭, 패널 동작, 메모리 예산에 따라 달라집니다.

## 패널 브링업 순서 { #panel-bring-up-sequence }

위젯이나 애플리케이션 동작을 디버깅하기 전에 패널을 단계별로 브링업하십시오.

1. 전원 레일, 리셋 타이밍, 백라이트/인에이블 핀, 기본 소비 전류를 확인합니다.
2. 패널 벤더가 제공한 초기화 시퀀스를 그대로 전송합니다.
3. 단색을 채워 바이트 순서, 픽셀 포맷, 인터페이스 배선 오류를 드러냅니다.
4. 단순한 도형 패턴을 그려 스트라이드, 윈도우 주소 지정, 좌표를 확인합니다.
5. 이미지 에셋과 텍스트를 추가하여 색상 변환, 폰트, 에셋 배치를 확인합니다.
6. 부분 리프레시, DMA, TurboPixel, 그래픽 가속을 한 번에 하나씩 활성화합니다.
7. 슬립, 디스플레이 끄기, 웨이크업, 재초기화 경로를 테스트합니다.

먼저 의도한 패널 인터페이스의 최소 구성으로 채우기와 패턴을 검증하십시오. DMA, 압축 또는 가속을 추가한 후에는 전체 LVGL UI를 테스트하기 전에 새로 추가한 각 경로에서 이 테스트를 반복하십시오.

## 패널별 지침 { #panel-specific-guidance }

### SPI 및 QSPI AMOLED/TFT { #spi-and-qspi-amoledtft }

부분 리프레시, 적합한 경우 RGB565, 적당한 크기의 애니메이션 영역을 사용하는 것이 좋습니다. 작은 변경에 전체 화면을 다시 그리지 마십시오. 변경된 영역을 플러시하기 전에 렌더링과 합성을 수행하십시오.

### RGB / DPI 패널 { #rgb-dpi-panels }

CPU, ePicasso, DMA 및 기타 메모리 트래픽과 함께 지속적인 스캔아웃 대역폭을 예산에 포함하십시오. 필요한 리프레시율에 맞는 프레임버퍼 전략을 선택하고, 메모리가 허용하면 더블 버퍼링을 고려하며, PCB 설계에서 타이밍과 신호 무결성을 반영하십시오.

### MIPI DSI 패널 { #mipi-dsi-panels }

부품을 확정하기 전에 패널 모드를 선택하십시오. **SF32LB55x는 MIPI DSI 커맨드 모드만 지원**하므로, 패널 컨트롤러가 업데이트된 이미지를 보관할 내부 SRAM/GRAM을 제공해야 합니다. **SF32LB58x는 커맨드 모드와 비디오 모드를 모두 지원**합니다. 커맨드 모드 패널에는 컨트롤러 RAM이 필요하고, 비디오 모드는 연속 픽셀 스트림으로 RAM이 없는 패널 컨트롤러를 구동할 수 있습니다. 초기화를 일찍 검증하고, 저전력 상태와 웨이크업 타이밍을 테스트하며, 프로토콜 오버헤드, 타이밍 제약, 다른 메모리 트래픽을 감안하여 필요한 데이터 속도를 인터페이스의 사용 가능한 처리량 이하로 유지하십시오.

### EPD 디스플레이 { #epd-displays }

업데이트가 드물다는 전제로 설계하십시오. 부분 업데이트 모드는 지원되고 시각적으로 허용될 때에만 사용하십시오. 애니메이션을 전제로 하지 말고, 디스플레이 PMIC, VCOM, 파형 요구 사항을 계획하십시오.

### JDI 및 Memory-in-Pixel 패널 { #jdi-memory-in-pixel-displays }

여기서 JDI는 직렬 또는 병렬 패널 인터페이스 모드를 가리키고, Memory-in-Pixel은 패널 기술을 설명합니다. 일부 저전력 디스플레이 설계에서는 둘을 결합할 수 있지만, 두 용어는 서로 바꿔 쓸 수 없습니다. MIP 패널에서는 작은 업데이트 영역과 적절한 UI 레이아웃을 통해, 패널에 전원이 공급되는 동안 픽셀 상태 유지의 이점을 활용할 수 있습니다. 이것이 비휘발성 이미지 저장이나 시스템 대기 전력 0을 의미하지는 않습니다. COM 반전과 기타 유지 관리 작업은 선택한 패널의 데이터시트를 따른 다음, 제품 조건에서 리프레시 동작, 야외 가독성, 전력을 측정하십시오.

## 양산 인계 체크리스트 { #production-handoff-checklist }

디스플레이 경로를 완료된 것으로 간주하기 전에, 다른 엔지니어가 재현해야 하는 선택 사항을 기록하십시오.

- 정확한 SF32 디바이스, 패키지, SDK 릴리스, 보드 리비전, 패널 부품 번호, 패널 컨트롤러 리비전
- 인터페이스 모드, 핀 할당, 픽셀 포맷, 바이트/색상 순서, 목표 리프레시 동작, 패널 초기화 소스
- 드로우 버퍼와 프레임버퍼의 위치, 크기, 정렬, 캐시 관리 소유권, DMA/컨트롤러 완료 신호
- 부분 리프레시 정책, 패널 윈도우 규칙, 아티팩트를 피하기 위해 함께 리프레시해야 하는 영역
- 대표적인 UI 상태에서 측정한 렌더링 시간, 전송 시간, 해당하는 경우 PSRAM 트래픽의 최대/평균값, 전류
- 실패하거나 중단된 전송 이후의 동작을 포함한 슬립, 디스플레이 끄기, 웨이크업, 복구 테스트 결과

이 기록은 디스플레이 지원을 일회성 브링업 결과에서 반복 가능한 제품 통합으로 바꿔 줍니다. 패널, SDK, 메모리 레이아웃, 픽셀 포맷 또는 디스플레이 드라이버가 바뀔 때마다 다시 검증하십시오.

## 핵심 요약 { #key-takeaways }

- 디스플레이 컨트롤러는 패널 출력을 담당하며, ePicasso의 픽셀 합성이나 eZip의 에셋 압축 해제와는 별개입니다.
- 인터페이스 선택이 대역폭, 버퍼, 전력, 핀, PCB 설계의 상당 부분을 결정합니다.
- 플러시 경로, 동기화, 캐시 관리, 패널 초기화를 핵심 펌웨어 작업으로 취급하십시오.
- 상위 수준 UI, DMA, TurboPixel 또는 가속 기능을 활성화하기 전에 단순한 패턴으로 패널을 검증하십시오.
- 디스플레이 경로의 경계를 하나씩 짚어 가며 장애를 진단한 다음, 검증된 구성과 측정값을 양산 인계를 위해 보존하십시오.
