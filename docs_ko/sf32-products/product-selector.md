# SF32 제품 선택기 { #sf32-product-selector }

회로도를 확정하기 전에 SF32 칩과 모듈의 후보를 추리십시오. 나중에 바꾸기 비싼 제약 조건, 즉 전원 아키텍처, 패키지, 디스플레이, 오디오, 메모리, GPIO, 연결성, 소프트웨어 검증 경로를 먼저 설정한 다음 남은 후보를 비교하십시오.

첫 단계 후보 선정에는 대화형 선택기를 사용하십시오. 이 선택기는 칩과 모듈만 나열하며, 통합 수준, PSRAM 및 GPIO 용량, 패키지, 메인 전원, 디스플레이 인터페이스와 목표 해상도, SDIO 개수, 오디오 인터페이스 개수, 특수 하드웨어 기능으로 필터링합니다. 각 결과는 해당 제품 소개로 연결됩니다. 개발 보드는 선택기 항목이 아니라 별도의 검증 플랫폼입니다.

## 제품 선택기 { #product-selector }

!!! info "용어와 오디오 인터페이스 개수"
    약어와 인터페이스 정의는 [용어집](../about/glossary.md)을 참고하십시오. PDM 인터페이스 하나에는 디지털 마이크를 최대 2개까지 연결할 수 있으므로, PDM 인터페이스의 개수가 마이크의 개수는 아닙니다. 사용할 수 있는 마이크 입력의 개수와 핀 라우팅은 디바이스에 따라 다르므로, 해당 부품의 문서를 확인하십시오.

필터는 논리곱으로 적용됩니다. 결과는 활성화된 모든 조건을 충족해야 합니다. 통합 수준, 패키지, 전원, 디스플레이는 단일 선택 컨트롤입니다. PSRAM과 GPIO 값은 애플리케이션의 요구 사항을 나타내므로, 후보는 이 값을 충족하거나 초과해야 합니다. 여기서 "필요한 최대값"은 부품의 상한이 아니라 애플리케이션의 최대 요구 사항을 의미합니다. 목표 해상도, SDIO, 각 오디오 인터페이스 개수도 최소 임계값입니다. 기능 체크박스는 필요한 기능(SDIO를 통한 외부 Wi-Fi, DCMI 카메라 인터페이스, AI/ML 가속기, FreeIO, PTM)을 추가합니다. SDIO 개수 필터는 외부 Wi-Fi 체크박스와 별개입니다.

</noscript>

결과 표에는 정확한 파트 넘버와 패키지, 메모리 용량, 최대 GPIO 개수, 전원 및 I/O 전압 정보, 디스플레이 기능, 오디오 인터페이스 개수(DAC/ADC/PDM/I2S), 디지털 주변 장치 인터페이스/채널 개수(UART/I2C/SPI/CAN/GPADC), USB 속도, 카탈로그 기능 플래그가 표시됩니다. `n/a`로 표시된 개수나 값은 카탈로그가 명시한 상세 수준에서는 문서화되지 않았다는 뜻이며, 0을 의미하거나 해당 부품에 그 기능이 없음을 증명하지는 않습니다. 기능 열의 대시는 카탈로그 레코드에 해당 기능이 표시되어 있지 않다는 뜻이므로, 대상 부품의 문서에서 확인하십시오. 디스플레이 인터페이스 목록은 선택용 데이터이며 전체 핀 멀티플렉싱 목록이 아닙니다.

## 선택 요소 { #selection-factors }

선택기는 자동 추천이 아니라 필수 조건을 적용하는 수단으로 취급하십시오. 나중에 발견하면 보드나 회로도를 다시 설계해야 하는 제약 조건부터 시작하고, 나머지 요소로 유효한 후보를 가려내십시오.

### 통합 수준 { #integration-level }

일정, RF 작업, 보드 소유권이 이미 정해져 있다면, 세부 사양을 비교하기 전에 통합 수준부터 선택하십시오. 칩은 가장 큰 제어권을 주지만, 전체 전원, RF, 클럭, 레이아웃, 양산 경로에 대한 책임도 져야 합니다. 모듈은 모듈 수준의 설계 및 통합 작업을 줄여 주지만, 캐리어 보드는 여전히 설계해야 합니다. 개발 보드는 펌웨어, 주변 장치 동작, 시스템 가정을 가장 빠르게 검증하는 방법이지만, 그 자체가 양산용 하드웨어로 적합한 것은 아닙니다.

### 전원 공급과 패키지 { #power-supply-and-package }

전원 공급 구성과 패키지는 일찍 선택하십시오. 선택기는 리튬 이온 배터리 직결 레일(3.2~4.7 V), 해당 옵션이 문서화된 경우의 외부 레귤레이션 3.3 V 전원, 메인 전원이 약 1.8 V까지 동작을 지원하는 부품(일부 사양은 하한을 1.71 V로 설정)을 구분합니다. 이 필터는 메인 전원 옵션을 설명하는 것이며 GPIO I/O 전압이 아닙니다. 결과에는 I/O 전압이 보장된 동작 한계가 아니라 공칭 레벨로 별도 표시됩니다. 정확한 부품의 전기적 사양을 확인하십시오. 패키지 선택도 마찬가지로 구조적인 문제입니다. 패키지는 보드 면적, 이스케이프 라우팅의 난이도, 열 경로, 사용 가능한 핀 예산을 결정합니다. 패키지 필터는 넓은 범주를 사용하므로, 결과에서 정확한 패키지 명칭을 확인하십시오. 공개된 최대 GPIO 개수가 더 큰 패키지라 해도, 전원, 클럭, 디버그, 디스플레이, 메모리, 필수 주변 장치용 핀을 확보하고 나면 충분하지 않을 수 있습니다.

### 메모리와 GPIO 여유 { #memory-and-gpio-headroom }

PSRAM과 GPIO 필터는 최소 임계값으로 사용한 다음, 선택한 등급의 메모리 구성과 핀 할당을 점검하십시오. PSRAM 용량은 그래픽 버퍼, 오디오 버퍼링, ML 모델, 애플리케이션 작업 공간에 영향을 주지만, 총 용량만으로 연속된 하나의 메모리 풀이 보장되지는 않습니다. GPIO 여유에는 첫 프로토타입의 인터페이스뿐 아니라 생산 테스트, 디버그, 인터럽트, 향후 센서, 보드 제어 신호도 포함해야 합니다.

### 디스플레이와 그래픽 { #display-and-graphics }

패널이 실제로 요구하는 디스플레이 인터페이스로 필터링한 다음, 목표 해상도 설정을 첫 용량 점검으로 사용하십시오. 가로 × 세로 프리셋은 총 픽셀 수 임계값이며, 정확한 화면비나 패널 타이밍을 점검하지는 않습니다. 표시된 해상도 값은 카탈로그의 스크리닝 수치로 취급하고, 보장된 패널 모드나 모든 SKU에 대한 공식 최대값으로 취급해서는 안 됩니다. 정확한 부품과 패널 요구 사항은 SiFli 문서에서 확인하십시오. 선택기는 병렬 디스플레이 인터페이스에 보드 설계에서 흔히 쓰는 약칭인 RGB를 사용하며, 정식 명칭은 DPI(Display Pixel Interface)입니다. 나열된 인터페이스는 전체 핀 멀티플렉싱 목록이 아닙니다. 정확한 인터페이스 모드, 메모리 예산, 핀 라우팅, 패널 전원 시퀀스, 소프트웨어 드라이버 경로는 대상 부품의 문서에서 확인하십시오.

### 오디오 인터페이스 { #audio-interfaces }

선택기에는 오디오 DAC, ADC, PDM 인터페이스, I2S 인터페이스에 대한 독립적인 최소 개수 필터가 있습니다. 각 값은 하한이며, 묶음 오디오 프로파일이 아닙니다. 그런 다음 다른 주변 장치와의 리소스 공유와 보드 수준의 아날로그 설계를 검토하십시오.

### 연결성과 특수 하드웨어 { #connectivity-and-specialist-hardware }

Wi-Fi, 카메라, AI 가속기, FreeIO, PTM 필터는 해당 기능이 제품 요구 사항일 때만 적용하십시오. 외부 Wi-Fi 체크박스는 문서화된 SDIO 기반 경로를 나타내며, 내장 Wi-Fi를 의미하지 않습니다. 별도의 SDIO 개수 필터는 문서화된 SDIO 인터페이스의 개수를 확인합니다. 외부 Wi-Fi에는 적절한 보드 수준의 전원, 라우팅, 소프트웨어 지원도 필요합니다. 카메라와 AI 요구 사항은 인터페이스, 메모리 대역폭, 처리 부하, 소프트웨어 스택을 처음부터 끝까지 검토해야 합니다. FreeIO와 PTM은 유연한 신호 할당이나 결정적인 주변 장치 태스크 처리가 설계의 핵심일 때 가치가 있으며, 더 기본적인 전원, 메모리, 패키지 제약 조건보다 우선해서는 안 됩니다.

### 검증 근거 { #validation-evidence }

확정하기 전에 결과 링크를 따라 제품 소개로 이동한 다음, 정확한 파트 넘버, 패키지, 전기적 한계, 레퍼런스 디자인, 사용 가능한 설계 가이드나 체크리스트를 확인하십시오. 가능하면 대상 부품과 하드웨어가 가장 가까운 지원 개발 보드에서 의도한 펌웨어 흐름을 검증하십시오. 선택기는 후보 선정 도구이며, 설계의 기준은 대상 부품의 SiFli 문서입니다.

## 통합 수준 선택 { #choose-an-integration-level }

대화형 카탈로그는 칩과 모듈만 나열합니다. 개발 보드는 소프트웨어와 시스템 가정을 검증하기 위한 별도의 경로로 아래에 표시됩니다.

<div align="center"><em>하드웨어 시작점</em></div>

<div align="center" markdown>

| 시작점 | 선택하는 경우 | 다음 단계 |
|:---------------|:---------------|:----------|
| 칩 | 커스텀 PCB와 인터페이스 및 전원 설계에 대한 직접적인 제어가 필요합니다. | 제품군을 선택한 다음, 회로도 작업 전에 해당 양산 설계 가이드를 검토합니다. |
| 모듈 | 커스텀 캐리어 보드를 유지하면서 RF 및 모듈 통합 작업을 줄이려 합니다. | 모듈 소개, 인터페이스 정의, 모듈 설계 가이드를 확인합니다. |
| 개발 보드 | 소프트웨어, 주변 장치 또는 제품 콘셉트를 빠르게 검증해야 합니다. | 목표 제품에 가장 잘 맞는 보드로 시작하여 검증된 예제를 실행한 다음, 해당 회로도는 양산 설계가 아니라 참고 자료로 취급합니다. |

</div>

## 후보 확정 { #confirm-the-shortlist }

1. **정확한 부품을 점검합니다.** [SF32 제품군](family/SF32_family.md), 결과의 제품 소개, [SF32 명명 규칙](family/SF32_namingrule.md)을 사용하여 주문 가능한 파트 넘버, 패키지, 전원 토폴로지, 메모리 구성, 인터페이스 할당, 레퍼런스 하드웨어를 확인합니다. 하나의 대표 기능만 보고 부품을 선택하지 마십시오. 필요한 디스플레이, 오디오, 스토리지, 센서, Bluetooth, 저전력 기능이 선택한 패키지와 보드 설계에서 함께 사용될 수 있는지 확인합니다.
2. **소프트웨어 경로를 검증합니다.** 하드웨어를 확정하기 전에, 의도한 하드웨어에 가장 잘 맞는 사용 가능한 보드에서 [시작하기 개요](../getting-started/index.md), [튜토리얼 개요](../getting-started/tutorials/overview.md), [개발 개요](../develop/index.md)를 사용합니다.
3. **양산 제약 조건을 확인합니다.** 회로도, 레이아웃, BOM, 디스플레이와 스토리지 선택을 확정하기 전에 [양산 설계](../hardware/design-for-production.md)로 이동합니다.
