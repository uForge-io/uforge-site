# Обзор раздела «Разработка» { #develop }

Этот раздел поможет превратить работающую плату SF32 в прошивку продукта, которую удобно сопровождать. После первого успешного запуска `hello_world` здесь можно выбрать конфигурацию платы, настроить повторяемую сборку и прошивку, адаптировать подходящий пример, интегрировать функции продукта, диагностировать сбои и спланировать обновление и восстановление.

Для первого запуска платы используйте раздел [Начало работы](../getting-started/index.md); для выбора устройства и отладочной платы — [Продукты SF32](../sf32-products/index.md); для схем и аппаратуры, готовой к производству, — [Аппаратная часть](../hardware/index.md); для основ архитектуры — [База знаний](../learn/index.md). Этот раздел предназначен для инженерного процесса и практических рекомендаций по реализации конкретных задач.

!!! info "SiFli-Solution"
    SiFli-Solution — отдельный программный пакет компании SiFli, который μForge.io пока не документирует. Здесь рассматриваются только SiFli-SDK и перечисленные ниже альтернативные пути сообщества. Если продукту требуется более комплексное решение для устройств с дисплеем, изучите официальную [документацию SiFli Solution](https://docs.sifli.com/projects/solution/index.html) и обратитесь непосредственно в SiFli. Для сложного продукта на этой основе может потребоваться углублённое непосредственное участие SiFli.

## Подготовьте базовую конфигурацию SiFli-SDK { #establish-a-sifli-sdk-baseline }

[SiFli-SDK](platforms/sifli-sdk/overview.md) — официальный программный пакет SiFli на базе RT-Thread и основной путь разработки прошивки для SF32. Начните с него, если нет конкретной причины оценивать другую экосистему: для него доступна наиболее полная документация по поддержке плат, Bluetooth, графике, аудио, хранению данных, управлению питанием и подготовке к производству.

До реализации функций продукта настройте и зафиксируйте воспроизводимую базовую конфигурацию:

1. Выберите точную конфигурацию платы SDK в разделе [Конфигурация платы](platforms/sifli-sdk/board-configuration.md).
2. Убедитесь, что штатный цикл [Сборка, прошивка и мониторинг последовательного вывода](platforms/sifli-sdk/build-flash-monitor.md) выполняется успешно.
3. Сохраните версию SDK или коммит, имя платы, команды сборки и прошивки, параметры последовательного порта и журнал загрузки.
4. Начните с наиболее подходящего [примера](examples/index.md), особенно если он уже задействует самую сложную подсистему продукта.

Эти записи станут точкой отсчёта при изменениях приложения, переносе на другие платы, анализе ошибок тестирования и восстановлении устройств в полевых условиях.

## Взвешенно оценивайте экспериментальные пути сообщества { #evaluate-community-paths-deliberately }

Группа [Эксперименты и сообщество](platforms/zephyr/overview.md) предназначена для команд, которым по конкретной причине требуется выйти за рамки основного пути с SDK. Это не означает, что уровень поддержки серийного производства сопоставим с SiFli-SDK.

<div align="center"><em>Таблица: соответствие путей сообщества задачам</em></div>

<div align="center" markdown>

| Путь | Рассматривайте, если | Учитывайте, что это |
|:-----|:-----------------|:------------|
| [Zephyr](platforms/zephyr/overview.md) | Нужны API Zephyr, devicetree, Kconfig или доработка поддержки платы в downstream-ветке. | Путь оценки downstream-разработки с поддержкой конкретной платы. |
| [Arduino](platforms/arduino/overview.md) | Нужны скетчи или быстрый прототип периферии на поддерживаемой плате. | Бета-путь, ограниченный одной поддерживаемой платой. |
| [MicroPython](platforms/micropython/status.md) | Оценивается возможность запуска скриптов в будущем. | Информационная страница до появления воспроизводимого общедоступного порта. |
| [Rust](platforms/rust/overview.md) | Есть возможность оценить работу с HAL/PAC и предложить исправления в исходный проект. | Проект сообщества, который ещё находится в разработке. |

</div>

Прежде чем строить продукт на одном из этих путей, проверьте на конкретной плате всю требуемую периферию, разметку флеш-памяти, методы отладки и процедуру восстановления. Зафиксируйте проверенную ревизию, конфигурацию, команды и результаты вместе с исходным кодом продукта.

## Проверьте готовность прошивки к применению в продукте { #product-ready-development-evidence }

Прежде чем считать выбранный путь разработки прошивки пригодным для применения в продукте, убедитесь, что можете ответить на вопросы:

- Для какого чипа и какой ревизии платы или собственной аппаратуры проводились испытания и какая конфигурация использовалась?
- Какая версия SDK, пакет, ветка или коммит использовались для сборки прошивки?
- Какие команды сборки, прошивки, мониторинга и полного восстановления проверены?
- Какой пример или тест подтверждает работу каждой необходимой периферии и подсистемы продукта?
- Проверены ли разметка разделов, поведение при обновлении, целевое энергопотребление и процедура декодирования данных о сбоях?

Если на какой-то вопрос нет ответа, результат всё ещё может быть полезным прототипом, но воспроизводимой базовой конфигурацией продукта он пока не является.
