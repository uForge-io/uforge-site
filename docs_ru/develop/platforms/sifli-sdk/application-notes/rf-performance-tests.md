# RF-тестирование с SiFli SDK { #run-sifli-sdk-rf-tests }

SDK разделяет проверку Bluetooth RF на тесты с сигнализацией, без сигнализации и индивидуальные RF-тесты. До загрузки тестовой прошивки выберите сценарий в соответствии с целью измерений.

<div align="center" markdown>
<em>Таблица: Область применения материалов по RF-тестированию для семейств</em>

| Материал | Семейства и область применения |
|---|---|
| Сравнение режимов тестирования и последовательность измерений | Общий рабочий процесс для SF32LB52x, SF32LB55x, SF32LB56x, SF32LB57x и SF32LB58x. |
| Поддержка тестов Bluetooth Classic | Требуется целевой чип с поддержкой Bluetooth Classic. SF32LB55x поддерживает только BLE и не поддерживает тесты Bluetooth Classic; для этого семейства используйте BLE-сценарии. |
| Поддержка SF32LB57x тестовым ПО | В [руководстве по RF-тестированию](https://docs.sifli.com/projects/sdk/latest/sf32lb55x/app_note/rf_test_guide.html) указаны выводы UART для SF32LB57x, но в списке платформ [руководства SiFli_RfTool](https://docs.sifli.com/projects/sdk/latest/en/sf32lb52x/tools/SiFli_RfTool/SiFli_RfTool_UM.html) семейства 57x нет. Рассматривайте эти сведения только как распиновку и проверьте, какой путь тестирования поддерживает целевая версия SDK. |
| Схемы подключения и таблица команд HCI | Примеры для SF32LB52x из исходного руководства; при реализации используйте документацию по командам и выводам целевого семейства. |
| Настройка `CONFIG_BT_RF_TEST` | Применяется к описанному пути для семейств, отличных от 55x; путь `bt_rftest` на SF32LB55x этот символ не использует. |
| Выводы UART, значения параметров пакетов и синтаксис команд | Зависит от семейства и версии SDK; проверьте конфигурацию проекта и справку `bt_rftest help`. |

</div>

!!! warning "В официальных руководствах расходятся назначения UART1 для SF32LB58x"
    В [общем руководстве по RF-тестированию](https://docs.sifli.com/projects/sdk/latest/en/sf32lb58x/app_note/rf_test_guide.html) для UART1 TX/RX указаны PA31/PA32, а в [Bluetooth Individual RF Test Guide](https://docs.sifli.com/projects/sdk/latest/en/sf32lb58x/app_note/bt_individual_test_guide.html) — PA32/PA31. Перед подключением проверьте тестовый сценарий целевой прошивки и pinmux платы: назначения в этих руководствах противоречат друг другу.

## Выбор режима тестирования { #select-the-test-mode }

<div align="center" markdown>
<em>Таблица: Выбор режима Bluetooth RF-тестирования</em>

| Режим | Назначение | Команда SDK | Путь управления |
|---|---|---|---|
| Испытания BT с сигнализацией | Квалификация BQB/QDID и проверка характеристик в соответствии с протоколом | `bt_cm dut`, `gap_enb_dut_mode_req()` | Радиоинтерфейс тестера и управление тестом LMP |
| BT без сигнализации | Настройка RF при разработке и проверка устройств на производстве | `bt_rftest`, `bt_enter_no_signal_dut_mode()` | Локальный HCI производителя |
| BLE без сигнализации (SIG DTM) | Проверка BLE RF и тестовые сценарии SIG DTM | `bt_rftest bletx/blerx`, `ble_enter_dut_mode()` | Локальный HCI или стандартный HCI, передаваемый через `bt_cm uart_dut` |
| Индивидуальные RF-тесты | Настройка RF на уровне платы и предварительные испытания FCC/CE | `bt_cm uart_dut` + `SiFli_RfTool` | Программа на ПК отправляет по одной низкоуровневой команде |

</div>

При тестировании с сигнализацией устанавливается реальное Bluetooth-соединение; этот режим используют для квалификационных испытаний. В режиме без сигнализации RF-тракт напрямую настраивают на заданные канал и уровень мощности и удерживают в состоянии передачи или приема — этот режим обычно используют при разработке и производственном контроле. Для индивидуальных RF-тестов программа на ПК позволяет точно задавать несущую или параметры модуляции, а измерения выполняют анализатором спектра или измерителем мощности. BT без сигнализации и индивидуальные RF-тесты — фирменные сценарии SiFli, а не испытания BQB.

## Выбор прошивки и настройка проекта { #choose-firmware-and-configure-the-project }

`rf_test.bin` — внутренняя сборка SiFli для RF-тестирования; она не распространяется как обычный артефакт SDK. `User.bin` — любое приложение, собранное с помощью SDK. RF-функции встроены в стек протоколов и запускаются командами FinSH, например `bt_cm dut`, `bt_cm uart_dut` и `bt_rftest`.

Для пользовательской сборки включите необходимые параметры:

```kconfig
CONFIG_RT_USING_FINSH=y
CONFIG_BSP_BT_CONNECTION_MANAGER=y
CONFIG_BT_RF_TEST=y
```

Путь `bt_rftest` для SF32LB55x не использует `CONFIG_BT_RF_TEST`. `CONFIG_BT_FINSH` предназначен для трассировки и не требуется для выполнения тестовых команд. Если для управления используется собственный IPC UART SDK, задайте `CONFIG_IPC_USE_OWN_DEVICE=y` и `CONFIG_IPC_OWN_DEVICE_NAME="uart2"` в соответствии с конфигурацией платы. В качестве отправной точки подойдут примеры SDK `example/bt/spp/` и `example/bt/HCI_over_uart/`.

## Испытания BT с сигнализацией { #bt-signaling-test }

1. Выведите на DUT сигналы `VBAT`, `GND` и TX/RX UART1. Распиновка UART1 по умолчанию зависит от корпуса; сверяйтесь с конфигурацией проекта.
2. Для испытаний BLE с сигнализацией подключите UART1 к ПК и отправьте `bt_cm uart_dut`. Убедитесь, что получен ответ `04 0E 04 XX 03 0C 00`, затем переключите UART на тестер.
3. Для испытаний BT с сигнализацией не допускайте перехода DUT в сон. Отправьте `bt_cm dut`, проверьте ответ `Write scan enable success` и подключите RF-коаксиальный кабель к тестеру.
4. В Bluetooth Signaling для BLE используйте USB-to-RS232 для управления EUT со скоростью 1 000 000 бод. Для BT выберите `None (EUT Control off)` и найдите DUT по радиоканалу.
5. Запустите TX в `Bluetooth 1 Multi Eval.`, а RX — в `Bluetooth 1 RX Meas.`. Для Classic BT используйте BER, для BLE — PER; снижайте уровень TX тестера, чтобы определить чувствительность.

## Команды BT/BLE без сигнализации { #btble-non-signaling-commands }

После включения пути RF-тестирования используйте оболочку FinSH:

```text
bt_rftest enter
bt_rftest bttx <channel> <packet_type> <power> <length>
bt_rftest btrx <channel> <packet_type> <power>
bt_rftest btstop
bt_rftest exit
```

Порядок аргументов и допустимые значения параметров пакета зависят от версии SDK. Используйте синтаксис, показанный командой `bt_rftest help` в целевой версии SDK. Статистика принятых пакетов RX имеет практический смысл; счетчик переданных пакетов TX не является измерением принятых пакетов. Для BLE DTM используйте `bt_rftest bletx`/`blerx` либо стандартные команды HCI `LE_Transmitter_Test`, `LE_Receiver_Test v2` и `LE_Test_End`. Номера каналов BLE — 0–39, значения PHY — 1M/2M/Coded; каналы Classic BT — 0–78. На чипах с поддержкой обоих режимов BT и BLE используют общий RF-тракт, поэтому их следует тестировать раздельно.

## Индивидуальные RF-тесты с SiFli_RfTool { #single-item-testing-with-sifli_rftool }

Подключите UART1 DUT к ПК со скоростью 1 000 000 бод. RF-порт соедините коаксиальным кабелем с тестером, анализатором спектра или измерителем мощности.

Отправьте `bt_cm uart_dut` и проверьте ответ `04 0E 04 XX 03 0C 00`. Затем в `SiFli_RfTool.exe` выберите семейство, режим BLE или BT без сигнализации и COM-порт.

Перед изменением канала, PHY, типа пакета или мощности остановите TX/RX. Для BLE RX тестер может передать 1 500 пакетов; вычислите `PER = (1500 - received) / 1500 × 100%` и запишите RSSI.

Для Classic BT RX используйте сигнал GPRF генератора CMW500 и фиксируйте RSSI, число ошибок пакетов/битов и BER/PER. Компенсируйте потери в кабеле и укажите, выполнены ли измерения по кабелю или по радиоканалу.

## Фиксация результатов { #record-the-result }

В исходном руководстве также приведена полная таблица команд HCI и возвращаемых значений. Используйте ее, если команда отправлена, но DUT не переходит в ожидаемое состояние. Не считайте каждый тестовый вектор из таблицы переносимым API; команды необходимо сверять с целевым семейством микросхемы и версией SDK.

<div align="center" markdown>

| Режим тестирования | Каналы | Центральные частоты |

| BLE | 0 / 19 / 39 | 2402 / 2440 / 2480 МГц |
