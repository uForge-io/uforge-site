# Конфигурация платы { #board-configuration }

Конфигурация платы связывает прошивку с реальной аппаратурой и определяет разметку флеш-памяти, PSRAM, выводы, интерфейс дисплея, аудиотракт, тактирование, линии питания и периферию по умолчанию.

В SiFli-SDK значение `--board=<board_name>` — важнейший параметр сборки. Оно выбирает пакет поддержки платы, который использует пример.

На двухъядерных платах, если суффикс ядра не указан, по умолчанию выбирается конфигурация HCPU. Чтобы собрать прошивку для LCPU, добавьте к имени платы суффикс `_lcpu`; суффикс `_hcpu` явно выбирает HCPU. Убедитесь, что пример поддерживает выбранное ядро.

## На что влияет выбор платы { #what-the-board-name-controls }

Выбранная плата может влиять на:

- Вариант микросхемы и корпуса.
- Конфигурацию Flash и PSRAM.
- Цели сборки HCPU/LCPU.
- Мультиплексирование выводов и доступность периферии.
- Настройки загрузки через UART.
- Конфигурацию дисплея и сенсорного ввода.
- Подключение аудиокодека.
- Настройки Bluetooth.
- Таблицу разделов и параметры загрузки.

## Практические правила { #practical-rules }

- Не определяйте имя платы по её маркетинговому названию.
- Не переносите в SiFli-SDK имя платы из Zephyr или Arduino.
- При выборе GPIO, ADC, PWM, I2C, SPI или ресурсов дисплея сверяйтесь со схемой платы или страницей отладочной платы.
- Начните с наиболее подходящего примера SDK для той же платы.
- После смены платы выполните чистую сборку.

## Проверка платы перед запуском { #board-bring-up-checklist }

- [ ] Проверьте вариант микросхемы и корпус.
- [ ] Проверьте тип, объём и конфигурацию флеш-памяти и PSRAM.
- [ ] Проверьте источник питания и работу зарядного устройства.
- [ ] Проверьте используемые платой источники и частоты тактирования, включая 48 MHz и 32,768 kHz, если они предусмотрены.
- [ ] Проверьте UART для загрузки и UART для журналов.
- [ ] Проверьте интерфейсы дисплея и сенсорного ввода.
- [ ] Проверьте аудиотракт, если он используется.
- [ ] Проверьте загрузочные выводы и поведение при сбросе.
- [ ] Проверьте разметку разделов.

Не переходите к отладке приложения, пока конфигурация платы не будет соответствовать имеющейся аппаратуре.

## Перенос на собственную плату { #when-porting-to-a-custom-board }

Возьмите за основу конфигурацию наиболее подходящей отладочной платы или модуля и измените:

1. Настройки Flash и PSRAM.
2. Мультиплексирование выводов.
3. UART консоли и загрузки.
4. Ресурсы дисплея, сенсорного ввода и аудио.
5. Параметры питания и зарядного устройства.
6. Разметку разделов.
7. Периферию, специфичную для продукта.

Проверяйте каждое изменение на минимальном примере, который использует соответствующий ресурс.
