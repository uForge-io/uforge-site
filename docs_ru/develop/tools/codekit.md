# CodeKit { #codekit }

SiFli CodeKit — расширение VS Code для разработки на SiFli-SDK. Оно помогает настроить SDK и проект, а также выполнить сборку, прошивку и мониторинг.

Инструкции по первому запуску приведены в статье [Начало работы с CodeKit](../../getting-started/sifli/getting-started-sifli-codekit.md). Здесь объясняется, какое место CodeKit занимает в процессе разработки.

Основной источник:

- [Начало работы с SiFli CodeKit](https://docs.sifli.com/projects/codekit/get-started/)

## Когда использовать CodeKit { #best-use-cases }

CodeKit подходит, если вам нужны:

- Работа с SDK преимущественно в VS Code.
- Пошаговая настройка проекта.
- Настройка платы и проекта прямо в редакторе.
- Сборка, прошивка и мониторинг без необходимости запоминать каждую команду.
- Более простой старт для тех, кто впервые работает с SiFli-SDK.

Используйте SDK из командной строки, когда пишете сценарии CI, устраняете проблемы с путями к инструментарию или готовите процедуры производства и выпуска. CodeKit упрощает работу разработчика, но не заменяет понимание процесса сборки SDK.

## Связь с SiFli-SDK { #relationship-to-sifli-sdk }

CodeKit предоставляет интерфейс к рабочему процессу SDK, но не заменяет сам SDK. Важно по-прежнему понимать базовые понятия:

- Корневой каталог SDK.
- Имя платы.
- Каталог проекта.
- Результаты сборки.
- Путь прошивки или загрузки.
- Последовательный монитор.

Если действие в CodeKit завершается ошибкой, по возможности повторите его соответствующей командой SDK. Так отчет об ошибке будет точнее, а проблему расширения будет проще отличить от проблемы SDK.

Используйте [SiFli-SDK](../platforms/sifli-sdk/overview.md), чтобы выбрать поддерживаемую базовую конфигурацию, а [Сборка, прошивка и мониторинг последовательного вывода](../platforms/sifli-sdk/build-flash-monitor.md) — чтобы сохранять эквивалентные команды командной строки как подтверждение. Прежде чем адаптировать проект CodeKit, начните с подходящего [примера SDK](../examples/index.md).

## Рабочая модель { #operational-model }

CodeKit наиболее полезен, когда действия в редакторе можно воспроизвести средствами SDK. Считайте расширение интерфейсом управления, а SiFli-SDK — первоисточником сведений об инструментарии, конфигурации платы, результатах сборки и файлах для загрузки.

В статье [Начало работы с CodeKit](../../getting-started/sifli/getting-started-sifli-codekit.md) описаны установка расширения и запуск `hello_world`. После успешной проверки этой базовой конфигурации используйте CodeKit, чтобы ускорить цикл «редактирование — сборка — прошивка — мониторинг». Если действие нужно автоматизировать, исследовать или воспроизвести вне VS Code, используйте командную строку SDK.

## Что фиксировать { #what-to-record }

Для каждого проекта CodeKit фиксируйте:

- Версию расширения CodeKit.
- Путь к SiFli-SDK и ветку SDK.
- Плату, выбранную в CodeKit.
- Соответствующее имя платы в SDK.
- Каталог результатов сборки.
- Способ прошивки или загрузки.
- Скорость последовательного порта в бодах.

Эти сведения позволят при необходимости повторить действие из графического интерфейса через командную строку.

## Устранение неполадок { #failure-boundaries }

<div align="center"><em>Таблица: порядок диагностики</em></div>

<div align="center" markdown>

| Проблема | Что проверить в первую очередь |
|:--------|:---------------|
| SDK не найден | Заново выберите корневой каталог SDK и убедитесь, что установка завершилась. |
| Сборка завершается ошибкой | По возможности воспроизведите проблему, собрав тот же проект командой `scons`. |
| Прошивка не записывается, хотя базовая конфигурация при первом запуске работала | Сравните выбранную плату и результаты сборки с рабочей базовой конфигурацией, затем проверьте, не занял ли другой процесс порт, и уточните режим загрузки. |
| В мониторе отображаются нечитаемые символы | Проверьте скорость обмена по последовательному порту и выбранный порт. |
| Команда отсутствует в интерфейсе | Откройте палитру команд и выполните поиск по `SiFli`. |

</div>
