# Инструменты { #tools }

Для разработки под SF32 недостаточно одного компилятора. В рабочем процессе также нужны средства прошивки, мониторинга последовательного порта, анализа сбоев, сбора трассировок, преобразования изображений, настройки радиотракта и аудио, а также заводского программирования.

В таблице ниже типовые задачи разработки сопоставлены с подходящими инструментами. Она дополняет, но не заменяет руководства: инструкции по установке, точные команды и процедуры для конкретных инструментов приведены в связанной документации.

## Инструменты прошивки { #flashing-tools }

Для первого запуска платы используйте UART-скрипты SDK: они создаются для только что собранной прошивки. Добавьте `sftool`, если вам нужны:

- Единый инструмент командной строки для прошивки в разных процессах.
- Интеграция с `west flash` в Zephyr.
- Поддержка загрузки прошивки через ArduinoCore-zephyr.
- Автоматизация в CI, на производстве или при регрессионном тестировании.

Пока команда не выбрала единый стандарт, документируйте в проекте оба способа.

## Журналы и трассировки { #logging-and-trace-tools }

Для обычной разработки достаточно терминала последовательного порта. При сложных сбоях сохраняйте структурированные журналы и данные для анализа:

- Сохраняйте полный журнал загрузки, начиная со сброса.
- Храните точные файлы ELF, map и отладочных символов, соответствующие прошитому образу.
- Записывайте, какая среда была активна: shell RT-Thread, shell Zephyr или режим отладки Arduino.
- Если доступны диагностические средства SiFli, используйте их для анализа assert-дампов и сбора трассировок.

## Инструменты для ресурсов и производства { #asset-and-production-tools }

Для продуктов с насыщенной графикой документируйте процесс преобразования ресурсов, особенно если используются сжатие eZip или аппаратное ускорение графики. Для серийного производства отдельно описывайте средства настройки RF, аудио и производственные инструменты, не смешивая их с инструментами прошивки для разработчиков: это не позволит производственным операторам зависеть от команд, предназначенных только для разработки.

## Практические рекомендации { #practical-advice }

- Освойте один надёжный способ прошивки, прежде чем добавлять второй.
- Сохраняйте проверенные журналы последовательного порта для каждой платы.
- Для первого запуска используйте скрипты, созданные SDK.
- Используйте `sftool`, если нужна воспроизводимая прошивка из командной строки для Zephyr, Arduino или автоматизированных процессов.
- Подготовьте средства анализа сбоев до того, как появится трудно воспроизводимая ошибка.
