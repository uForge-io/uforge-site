# Руководство по проектированию аппаратуры SF32LB55x — контрольный список проверки проекта и справочные материалы { #sf32lb55x-hardware-design-guide-design-review-checklist-and-references }

## 7. Контрольный список проверки проекта { #7-design-review-checklist }

- [ ] Проверьте точный корпус, распиновку, конфигурацию контактных площадок и технологический процесс изготовления PCB.
- [ ] Убедитесь, что все основные и вспомогательные линии питания PMU соответствуют ограничениям по напряжению и току из даташита.
- [ ] Разместите необходимые развязывающие конденсаторы рядом с выводами.
- [ ] Проверьте временные характеристики POR/BOR/сброса и режим загрузки.
- [ ] Убедитесь, что кварцы 48 MHz и 32,768 kHz соответствуют требованиям по CL, ppm, ESR, размещению и трассировке.
- [ ] Проверьте согласующую RF-цепь, антенну и запретную зону для земли (ground keep-out).
- [ ] Убедитесь, что группы выводов внешней памяти и дисплея соответствуют выбранному корпусу.
- [ ] Проверьте, что цепи пробуждения, GPADC, датчиков, аудио, сенсорного ввода, подсветки и двигателя соответствуют требованиям по низкому энергопотреблению.
- [ ] Зарезервируйте точки доступа для отладки, загрузки, прошивки в производстве, RF-тестирования и калибровки кварца.

## 9. Приложения { #9-appendices }

### 9.1. Приложение A. Типичное устройство на базе SF32LB55x { #appendix-a-a-typical-sf32lb55x-product }

Типичное устройство на базе SF32LB55x включает MCU, схему распределения питания, кварцы, согласующую RF-цепь и антенну, внешнюю память, дисплей и сенсорный контроллер, датчики, входы GPADC, вибромотор, необязательный Bluetooth-аудиотракт, а также точки доступа для отладки и производственных испытаний. В устройствах с батарейным питанием дополнительно проверьте токи утечки в режиме низкого энергопотребления и предусмотрите доступ к плате для испытательной оснастки.

### 9.2. Вопросы по разработке { #91-design-qa }

1. **Почему при запуске с Mode = 1 состояния некоторых GPIO по умолчанию отличаются от указанных в спецификации?** В режиме загрузки меняются состояния GPIO, связанные с внешней флеш-памятью на QSPI2 и QSPI3.
2. **Почему SMT-вибромотор может неожиданно работать во время программирования?** Может непреднамеренно включиться питание мотора или сигнал PWM. Если мотор запускается высоким уровнем, GPIO с подтяжкой вверх (PU) по умолчанию может подать на него питание. Для PWM SiFli рекомендует GPIO17 или GPIO39 с подтяжкой вниз (PD) по умолчанию.
3. **Почему пайка аккумулятора может привести к зависанию микросхемы и как этого избежать?** Плохое заземление паяльника может вызвать импульс перенапряжения. Установите защиту от импульсных перенапряжений и ESD на интерфейсе аккумулятора и обеспечьте надёжное заземление паяльника.
4. **Почему кнопка пробуждения не выводит MCU из Hibernate?** Из Hibernate MCU могут вывести только шесть входов пробуждения LCPU — GPIO43–GPIO48; GPIO0–GPIO3 со стороны HCPU для этого не подходят.
5. **Почему датчик движения или пульса может потреблять слишком много энергии либо работать неправильно при отладке низкого энергопотребления?** Прошивка датчика выполняется на LCPU, поэтому сигналы I2C, SPI, управления и прерывания должны подключаться только к интерфейсам LCPU. Подключение к интерфейсам HCPU может увеличить потребление или привести к сбоям.
6. **Почему потребление датчика остаётся высоким, хотя все сигналы подключены к интерфейсам LCPU?** Отключения питания датчика недостаточно, если остаются включёнными источники подтяжки линий I2C или прерывания. Отключите и питание этих подтяжек.
7. **Почему использование GPIO26 и GPIO27 как выходов управления может увеличить ток в режиме сна?** В режиме сна установите на обоих GPIO одинаковый уровень либо переведите хотя бы один в высокоимпедансное состояние без подтяжки вверх или вниз.
8. **Как проверить повышенное потребление SS6600 в Hibernate?** Стабилизируйте все десять входов пробуждения на высоком или низком уровне: GPIO0–GPIO3 HCPU и GPIO43–GPIO48 LCPU. Если все десять подтянуты вверх, используйте постоянно включённый источник 3,3 V для подтяжек.
9. **Может ли повышенный ток покоя компонентов питания быть причиной высокого потребления в режиме низкого энергопотребления?** Да. Преобразователи BUCK, LDO и силовые ключи с высоким током покоя (Iq) увеличивают потребление; SiFli рекомендует компоненты с Iq ниже 1 µA.
10. **Как избежать артефактов изображения при испытаниях ESD?** Установите ESD-защиту на сигналы VDD, SCL, SDA, RESET и INT сенсорной панели, а также на питание и RESET LCD.
11. **Как избежать сбоев в режиме постоянно включённого дисплея?** Эта функция в основном применяется с AMOLED-панелями, потребляющими меньше энергии, чем TFT-панели. Для LCD_EN, LCD_RST и других сигналов управления рекомендуются GPIO порта PB. Если сигнал активируется высоким уровнем через GPIO порта PA, по умолчанию должна быть включена подтяжка вверх (PU); GPIO PA с подтяжкой вниз (PD) может вызвать аномальное отключение экрана более чем на 10 ms после пробуждения.
12. **Как избежать сбоев управления питанием внешнего Bluetooth-аудиомодуля после пробуждения, если модуль должен оставаться включённым во время сна?** Управляйте его питанием через GPIO LCPU. Для ключа с активным низким уровнем выберите GPIO LCPU с подтяжкой вниз (PD) по умолчанию.
13. **Как обеспечить зарядку после глубокого разряда аккумулятора?** При слишком низком напряжении аккумулятора управление силовым трактом должно переключать питание системы на вход зарядного устройства после его подключения. Без такого управления выбранная микросхема зарядки должна обеспечивать ток капельной зарядки (trickle charge) не менее 40 mA.
14. **Почему зарядка может не начинаться после подключения зарядного устройства?** Сигнал обнаружения подключения нужно подать на один из поддерживающих пробуждение GPIO LCPU — GPIO43–GPIO48. Подключение к другому GPIO может нарушить запуск процесса зарядки.
15. **Как избежать высокого потребления при MODE = High в режиме загрузки?** Для мощных периферийных устройств, например аудиоусилителя с активным высоким уровнем, используйте GPIO с подтяжкой вниз (PD) по умолчанию и не используйте GPIO с подтяжкой вверх (PU). Иначе режим загрузки может непреднамеренно включить устройство и помешать программированию.
16. **Почему программирование может завершиться ошибкой при MODE = High и что делать с прерыванием датчика на GPIO46?** В режиме загрузки GPIO46 по умолчанию становится UART3_RX и может мешать программированию. Перенесите сигнал прерывания датчика на GPIO43, GPIO44, GPIO47 или GPIO48. Если входов пробуждения LCPU недостаточно, подключите внешнюю кнопку к GPIO45 или GPIO46 через резистор 0 Ω.
17. **Что делать, если алгоритм датчика движения и пульса требует больше памяти, чем доступно?** Проверьте, достаточно ли памяти выделено LCPU. При нехватке добавьте внешнюю NOR Flash на QSPI4.
