# Руководство по аппаратной разработке SF32LB58x { #sf32lb58x-hardware-design-guide }

## 1. Введение { #1-introduction }

В этом руководстве собраны рекомендации и справочные материалы по разработке устройств на базе высокопроизводительных микроконтроллеров AIoT семейства SF32LB58x. Оно предназначено для инженеров по аппаратной части и разработчиков устройств с питанием от аккумулятора, для которых важны развитые пользовательские интерфейсы, большой объём памяти, двухрежимный Bluetooth, аудиофункции, большое число GPIO и низкое энергопотребление в режимах ожидания.

Руководство охватывает весь процесс аппаратной разработки: PMIC и распределение питания, вывод трасс из корпуса BGA256, планирование стека HDI, тактовые цепи, RF, MIPI-DSI, USB 2.0 High-Speed, SDIO/eMMC, аудиосхемы, разводку PCB, проверку и подготовку к производству. Следование этим рекомендациям помогает снизить риски плотной компоновки BGA/HDI, сохранить целостность сигналов высокоскоростных интерфейсов и обеспечить соответствие изделия требованиям SF32LB58x к питанию, корпусу и производству.

Предполагается, что читатель знаком с основами разработки встроенных систем, создания схем и разводки PCB высокой плотности. Это руководство дополняет даташит и руководство пользователя SF32LB58x, официальное руководство по аппаратному применению и комплект эталонных проектов, а также список одобренных поставщиков SiFli (AVL). За электрическими характеристиками, мультиплексированием выводов, размерами корпуса, квалификацией компонентов и ограничениями производства следует обращаться к этим официальным материалам.

### 3.2. Варианты исполнения { #32-variants }

Перед фиксацией схемы проверьте точный код заказа SF32LB58x и конфигурацию памяти в SiP по актуальным даташиту и AVL. Семейство представляет собой платформу BGA256, требующую технологии HDI; конфигурация памяти SiP зависит от модели. Семейство поддерживает внешнюю NOR Flash или SPI NAND Flash через MPI3 или MPI4. На EVB SiFli для внешней SPI NAND используется MPI4; SD1 предназначен для eMMC или SD NAND, а SD2 — для SD-карты или Wi-Fi-устройства. Перед завершением проекта также проверьте распиновку выбранного варианта и разводку целевой платы.

### 3.4. Основные аппаратные возможности { #34-major-hardware-features }

- Корпус BGA256 с шагом 0,4 mm требует плотной разводки выводов питания и GPIO.
- Необходима PCB по технологии HDI; конструкция не совместима с PTH.
- Встроенная PMU с 2 выходами BUCK и 3 внутренними выходами LDO.
- Для распределения питания всей системы класса смарт-часов можно дополнительно использовать системный PMIC SF30147C.
- До начала разводки MIPI-DSI, USB 2.0 HS, SDIO/eMMC, RF, аудио и выводов из корпуса BGA заранее подтвердите стек слоев и правила импеданса.

### 3.5. Типичные области применения { #35-typical-applications }

SF32LB58x подходит для подключенных устройств, сочетающих развитую графику, большой объем памяти, мультимедийные функции и периферийные ИИ-нагрузки. Например:

- Смарт-часы, спортивные часы и носимые устройства для активного отдыха
- Продвинутые велокомпьютеры и автомобильные приборные панели
- Интеллектуальные дисплеи и подключенные приборные панели
- Носимые устройства с функциями ИИ
- Системы периферийного ИИ и слияния данных датчиков
- Устройства HMI с высоким разрешением на базе LVGL
- Портативные медицинские и промышленные терминалы
- Аксессуары Bluetooth + Wi-Fi с внешним Wi-Fi-устройством, подключенным через SDIO

### 4.3. Как пользоваться руководством { #43-how-to-use-this-guide }

Используйте руководство в порядке проверки платы: сначала подтвердите корпус и конфигурацию памяти SiP, затем зафиксируйте стек HDI и стратегию PMIC, проверьте загрузочную память и разводку дисплея, после чего оцените тактирование, RF, USB, аудио, отладку и доступ к производственным тестам. Раздел 5 задает требования к схеме, раздел 6 — к реализации PCB, а раздел 7 содержит критерии выпуска.

### 4.4. Комплект материалов для проверки { #44-review-evidence-pack }

До выпуска прототипа сохраните PDF схемы, стек PCB, сведения о возможностях производства и конструкции переходных отверстий, отчеты по импедансу и DRC, результаты сверки с AVL, а также снимки критических участков разводки: PMIC, дроссели BUCK, DSI, USB, SDIO/eMMC, RF, кварцы, аудио, выводы из корпуса BGA, пути возвратного тока и точки входа ESD.

### 4.5. Работа с чек-листами { #using-the-checklists }

В руководстве предусмотрены два уровня проверки. Краткие контрольные списки в разделах 5.2.1.7 и 5.7.3 содержат наиболее рискованные пункты для быстрой самостоятельной проверки на этапе разработки. [Чек-лист проверки схемы](SF32LB58x_schematic_checklist.md) (раздел 5.8) и [чек-лист проверки разводки PCB](SF32LB58x_pcb_layout_checklist.md) (раздел 6.18) полностью и по пунктам воспроизводят документ SiFli *SF32LB58x Schematic & PCB Checklist* (V1.0, 2026-01-21).

Каждый пункт относится к категории «Обязательный» (его нужно выполнить до выпуска) или «Необязательный» (рекомендуется, если используется соответствующая функция). Цветной текст и текст с <span class="flag-yellow">жёлтой заливкой</span> сохраняют выделения из исходной рабочей книги. В книге не указано, почему выделен каждый пункт, поэтому считайте такие отметки дополнительными сигналами для проверки, а не заменой остальных пунктов таблицы.

Источники расходятся в требованиях к току насыщения дросселя BUCK. Исходная рабочая книга с контрольными списками требует Isat ≥ 450 mA для дросселя BUCK, отсутствующего в AVL; официальное руководство по аппаратному применению указывает Isat ≥ 500 mA при L = 4,7 µH и DCR ≤ 0,4 Ω. В чек-листе сохранено значение из рабочей книги. Пока SiFli не прояснит расхождение, для дросселя вне AVL следует выбирать Isat не менее 500 mA.

Используйте [чек-лист схемы](SF32LB58x_schematic_checklist.md) при проверке схемы до начала разводки PCB, а [чек-лист разводки PCB](SF32LB58x_pcb_layout_checklist.md) — при проверке платы до выпуска Gerber-файлов. Обычно каждый этап проверяют дважды: сначала инженер, отвечающий за проект, затем независимый проверяющий — до фиксации конструкции или передачи данных в производство.

Используйте контрольный список для фиксации и согласования результатов проверки, а не только для чтения:

1. Сначала подтвердите точный код целевой модели и конфигурацию памяти в SiP.
2. При проверке отмечайте каждый пункт как выполненный, невыполненный или неприменимый, а не просто просматривайте таблицу.
3. Сверяйте пункты о дисплее, памяти, пробуждении и низком энергопотреблении с соответствующими разделами руководства по аппаратной разработке.
4. До выпуска зафиксируйте в отчете проверки все открытые допущения.
