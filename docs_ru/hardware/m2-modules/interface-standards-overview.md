# Стандарты интерфейсов модулей { #module-interface-standards }

В этой группе собраны правила описания интерфейсов модулей μForge. Начните с неё, прежде чем утверждать разъём платы-носителя, распиновку или заявление о совместимости. Здесь представлены два типа документов: правила именования, задающие общую терминологию, и предварительное описание интерфейсов на уровне контактов, которое полезно для планирования, но необходимо проверить для выбранного модуля и изделия.

## Именование и электрическая совместимость { #what-is-stable-and-what-must-be-verified }

Последовательно применяйте правила именования в описаниях модулей, схемах, примечаниях BOM и документации изделия. Названия описывают предполагаемый профиль интерфейса, а не окончательную электрическую или механическую спецификацию. Совпадение названия профиля или формы разъёма не подтверждает взаимозаменяемость модуля и платы-носителя.

Описание на уровне контактов не гарантирует, что каждый модуль μForge или каждый корпус SF32 поддерживает все назначенные сигналы и интерфейсы или любые варианты их одновременного использования. До фиксации проектных решений сверьте перечисленное ниже с документацией именно выбранного модуля, микросхемы, корпуса и руководства по проектированию аппаратуры:

- механический чертёж разъёма, положение ключа, нумерацию контактов и ограничения сборки;
- шины питания, домены напряжения, допустимый ток и последовательность включения;
- доступность интерфейсов, мультиплексирование выводов и функции, исключающие друг друга;
- целостность сигналов, импеданс, согласование длин, требования по ESD и запретные для трассировки RF-зоны;
- доступ к отладке, загрузке, восстановлению и производственным тестам;
- требования платы-носителя к дисплею, камере, аудиосистеме, накопителям и сопутствующей беспроводной связи.

## Порядок принятия решений для платы-носителя { #carrier-board-decision-path }

1. Выберите модуль и изучите его описание и руководство по проектированию аппаратуры.
2. Используйте [правила именования интерфейсов M2](M2%20Interface%20Naming%20Rules.md), чтобы однозначно задать нужный профиль.
3. По [описанию интерфейса M2](M2-interface-definition.md) определите возможные сигналы и конфликты при их совместном использовании.
4. Подтвердите назначение каждого используемого контакта по документации конкретного модуля и соответствующей документации SiFli.
5. До начала разводки PCB зафиксируйте при проверке схемы версии документов, ревизии модуля и платы-носителя, подтверждённые исключения и нерешённые вопросы.

Полную проверку платы-носителя продолжайте по статье [Разработка для серийного производства](../design-for-production.md). Требования к реализации конкретного модуля смотрите в соответствующем руководстве из группы **Руководства по проектированию аппаратуры**.
