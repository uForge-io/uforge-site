## Обзор { #overview }

Модуль SF32LB57 с поддержкой двух режимов Bluetooth предоставляет хосту интерфейс AT-команд через UART для работы с BLE и Classic Bluetooth (BR/EDR). С помощью AT-команд хост настраивает параметры устройства, управляет подключениями, передаёт и принимает данные, а также получает асинхронные уведомления о состоянии от модуля.

## Формат команд { #command-format }

### Описание синтаксиса { #syntax-definition }

AT-команды передаются как текст ASCII и завершаются символом возврата каретки `\r` (0x0D). Префикс команды — `AT+` для команд в формате AT или `AT>` для команд в формате PDU. На SF32LB57 для AT используется порт USART1 с форматом 8N1 без аппаратного управления потоком данных; скорость по умолчанию — 460800 bps. Длина одного кадра AT не должна превышать 512 байт.

### Команды в формате AT { #at-format-commands }

<div align="center"><em>Таблица: формы команд в формате AT</em></div>

<div align="center" markdown>

| Форма | Команда | Описание |
|:-----|:--------|:-------------|
| Запрос | `AT+<CMD>?\r` | Чтение параметра или состояния |
| Установка | `AT+<CMD>=<param>[,<param>...]\r` | Запись параметра |
| Выполнение | `AT+<CMD>\r` | Запуск действия |

</div>

<div align="center"><em>Таблица: ответы в формате AT</em></div>

<div align="center" markdown>

| Результат | Строка ответа |
|:-------|:------------------|
| Успех | `\r\nOK\r\n` |
| Ошибка | `\r\nERROR\r\n` или `\r\nFALSE\r\n` |
| Значение, возвращаемое запросом | `\r\n+<CMD>:<value>\r\n\r\nOK\r\n` |

</div>

### Формирование кадра команды PDU { #pdu-format-command-framing }

Команды PDU передают бинарные данные, когда модуль находится в режиме команд. Если не указано иное, числовые поля в кадре используют порядок little-endian, а `data` содержит исходные бинарные данные.

**Команда (хост → модуль)**

```
'A' 'T' '>' <Opcode(2 bytes)> <Total Length(2 bytes)> [Body] '\r'
```

<div align="center"><em>Таблица: структура кадра команды PDU</em></div>

<div align="center" markdown>

| Элемент | Описание |
|:--------|:-------------|
| `AT>` | Префикс команды, 3 байта ASCII |
| Opcode | Код операции размером 2 байта в порядке little-endian: `0x0101`, `0x0102` |
| Total Length | Общий размер Body в байтах, 2 байта в порядке little-endian |
| Body | Полезная нагрузка; структура зависит от Opcode |
| `\r` | Терминатор команды, 1 байт |

</div>

**Отчёт (модуль → хост)**

```
'\r' '\n' '<' <Opcode(2 bytes)> <Total Length(2 bytes)> [Data] '\r' '\n'
```

Следующие уведомления о состоянии модуль отправляет самостоятельно; хосту не нужно посылать команду, чтобы их получить. Передачей управляет переключатель событий (`AT+EVT`). Если включён режим без уведомлений, модуль ничего не отправляет.

| Ответ | Режим команд: `\r\nIM_CONN <hdl>,<addr>,<mtu>\r\n`; прозрачный режим: `\r\nIM_CONN\r\n` |
| Параметры | `hdl`: дескриптор соединения — ровно 4 шестнадцатеричные цифры в верхнем регистре, дополненные нулями слева. Для BLE отображается внешний дескриптор с нумерацией от 1 (внутреннее значение плюс 1); для остальных типов — исходное значение. `addr`: адрес удалённого устройства, 12 шестнадцатеричных цифр, начиная со старшего байта. `mtu`: MTU текущего соединения, десятичное число. |
| Примечания | В режиме команд для каждого установленного соединения передаётся уведомление с дескриптором, адресом удалённого устройства и MTU. В прозрачном режиме уведомление передаётся только при установлении первого соединения (когда их количество равно 1) и не содержит параметров. Передачей управляет `AT+EVT`; команда `AT+EVT=1` включает режим тишины и подавляет это уведомление. |

</div>

### IM_DISCONN: уведомление об отключении { #im_disconn-disconnect-indication }

<div align="center"><em>Таблица: уведомление об отключении IM_DISCONN</em></div>

<div align="center" markdown>

| Поле | Значение |
|:-----|:--------|
| Команда | Нет (прошивка отправляет уведомление самостоятельно при разрыве соединения). |
| Ответ | Режим команд: `\r\nIM_DISCONN:<hdl>\r\n` |
| Параметры | `hdl`: дескриптор разорванного соединения — ровно 4 шестнадцатеричные цифры в верхнем регистре, дополненные нулями слева. Для BLE отображается внешний дескриптор с нумерацией от 1 (исходное значение плюс 1); для остальных типов — исходное значение. |
| Примечания | Уведомление содержит только дескриптор и передаётся в режиме команд; в прозрачном режиме оно не передаётся. В любом режиме, когда все соединения разорваны и их количество возвращается к нулю, дополнительно передаётся `\r\nIM_READY\r\n`. Передачей управляет `AT+EVT`; команда `AT+EVT=1` включает режим тишины и подавляет это уведомление. |

</div>

## Команды в формате PDU { #pdu-format-commands }

### Уведомление о данных PDU (opcode 0x0101) { #pdu-data-report-opcode-0x0101 }

<div align="center"><em>Таблица: уведомление о данных PDU (модуль → хост, opcode 0x0101)</em></div>

<div align="center" markdown>

| Поле | Значение |
|:-----|:--------|
| Команда | Нет (прошивка отправляет данные самостоятельно в режиме команд). |
| Ответ | `\r\n< + opcode(2-byte little-endian) + len(2-byte little-endian) + body + \r\n` |
| Параметры | `opcode` всегда равен `0x0101`; `body` = `conn_hdl` (2 байта, little-endian) + `data`. Для BLE используется внешний дескриптор с нумерацией от 1; для SPP — исходный ACL-дескриптор. |
| Примечания | В режиме команд при записи данных в пользовательскую BLE-характеристику или получении данных через SPP Classic Bluetooth модуль передаёт их хосту в указанном формате. В прозрачном режиме данные выводятся напрямую. |

</div>

### Отправка данных PDU (автовыбор характеристики Notify, opcode 0x0101) { #pdu-mode-send-data-auto-select-notify-characteristic-opcode-0x0101 }

<div align="center"><em>Таблица: отправка данных PDU (автовыбор характеристики Notify, opcode 0x0101)</em></div>

<div align="center" markdown>

| Поле | Значение |
|:-----|:--------|
| Команда | Бинарный кадр (не текстовая строка AT): `AT>` + opcode (2 байта, little-endian) + len (2 байта, little-endian) + body + `\r`. Здесь opcode = `0x0101` (последовательность байтов 01 01); len — длина body в байтах; body = `conn_hdl` (2 байта, little-endian) + `data`. `data` — передаваемая полезная нагрузка. |
| Ответ | Текстового ответа нет. Прошивка передаёт `data` удалённому устройству в соответствии с типом соединения, без ответа `OK`/`ERROR`. |
| Параметры | `opcode`: всегда `0x0101`. `len`: длина body, диапазон 2–508 (кадры короче 2 или длиннее `AT_RX_BUF_SIZE`-4 отбрасываются; `AT_RX_BUF_SIZE` = 512). `conn_hdl`: дескриптор целевого соединения; для BLE — внешний дескриптор с нумерацией от 1, для SPP — исходный ACL-дескриптор. `data`: байты полезной нагрузки, длина = len-2; допустима длина 0. |
| Примечания | Сначала `conn_hdl` сопоставляется с BLE-дескриптором с нумерацией от 1 (то есть `conn_hdl`-1 соответствует BLE-слоту); если совпадения нет, выполняется поиск исходного значения в SPP-слоте. Если соединение не найдено, кадр отбрасывается. Для BLE прошивка перебирает пользовательские службы GATT и автоматически выбирает первую характеристику со свойством Notify или Indicate; если такой характеристики нет, данные не передаются. Для SPP (BR/EDR) `data` отправляется по каналу SPP. Сразу после кадра должен следовать `\r`; иначе текущий кадр отбрасывается. Если между кадрами в течение тайм-аута PDU не поступают новые байты, состояние приёма PDU сбрасывается. |

</div>

### Отправка данных PDU (заданные служба и характеристика, opcode 0x0102) { #pdu-mode-send-data-specify-service-and-characteristic-opcode-0x0102 }

<div align="center"><em>Таблица: отправка данных PDU (заданные служба и характеристика, opcode 0x0102)</em></div>

<div align="center" markdown>

| Поле | Значение |
|:-----|:--------|
| Команда | Бинарный кадр (не текстовая строка AT): `AT>` + opcode (2 байта, little-endian) + len (2 байта, little-endian) + body + `\r`. Здесь opcode = `0x0102` (последовательность байтов 02 01); len — длина body в байтах; body = `conn_hdl` (2 байта, little-endian) + `svc_idx` (1 байт) + `char_idx` (1 байт) + `data`. |
| Ответ | Текстового ответа нет. Прошивка отправляет `data` удалённому устройству через заданные службу и характеристику, без ответа `OK`/`ERROR`. |
| Параметры | `opcode`: всегда `0x0102`. `len`: длина body, диапазон 4–508. Общий минимум уровня приёма равен 2, но этот opcode требует не менее 4 байт с учётом `svc_idx`+`char_idx`; иначе кадр отбрасывается. `conn_hdl`: целевой внешний BLE-дескриптор с нумерацией от 1. `svc_idx`: индекс пользовательской службы GATT. `char_idx`: индекс характеристики в этой службе. `data`: байты полезной нагрузки, длина = len-4; допустима длина 0. |
| Примечания | Поддерживаются только BLE-соединения; если найденное соединение имеет тип SPP, кадр отбрасывается. `svc_idx` должен соответствовать зарегистрированной пользовательской службе, а `char_idx` должен быть меньше количества её характеристик; иначе кадр отбрасывается. Заданная характеристика должна иметь свойство Notify или Indicate; иначе кадр также отбрасывается. `conn_hdl` обрабатывается по тому же правилу, что и в `0x0101`: сначала проверяется BLE-дескриптор с нумерацией от 1, затем исходное значение. Сразу после кадра должен следовать `\r`. |

</div>

### Отключение в режиме PDU { #pdu-mode-disconnect }

<div align="center"><em>Таблица: отключение в режиме PDU</em></div>

<div align="center" markdown>

| Поле | Значение |
|:-----|:--------|
| Команда | `AT+DISCONN\r` (без параметра) или `AT+DISCONN=<conn_hdl>\r` |
| Ответ | Успех: `\r\nOK\r\n`; ошибка: `\r\nERROR\r\n` |
| Параметры | `conn_hdl`: шестнадцатеричный дескриптор соединения для отключения. Для BLE используется внешний дескриптор с нумерацией от 1; значение 0 недопустимо и вызывает `ERROR`. Для SPP используется исходный ACL-дескриптор. |
| Примечания | Без параметра разрываются все текущие соединения и возвращается `OK`. Если параметр задан, сначала ищется BLE-дескриптор с нумерацией от 1 (`conn_hdl`-1 соответствует BLE-слоту); при отсутствии совпадения ищется исходное значение в SPP-слоте. Если соединение не найдено, возвращается `ERROR`. BLE-отключение инициируется с кодом причины `0x13`; для отключения SPP используется адрес удалённого устройства. Запрос `AT+DISCONN?` возвращает `ERROR`. |

</div>

### Уведомления о состоянии PDU-соединений (IM_CONN / IM_DISCONN) { #pdu-connection-status-indication-im_conn-im_disconn }

<div align="center"><em>Таблица: уведомления о состоянии PDU-соединений (IM_CONN / IM_DISCONN)</em></div>

<div align="center" markdown>

| Поле | Значение |
|:-----|:--------|
| Команда | Модуль отправляет уведомления самостоятельно; команда хоста не требуется. `IM_CONN` передаётся при установлении соединения, `IM_DISCONN` — при его разрыве. |
| Ответ | Установление соединения в режиме команд: `\r\nIM_CONN <hdl>,<mac>,<mtu>\r\n`, где `<hdl>` — дескриптор из 4 шестнадцатеричных цифр, `<mac>` — адрес из 12 шестнадцатеричных цифр (начиная со старшего байта), `<mtu>` — десятичное значение MTU. Разрыв соединения в режиме команд: `\r\nIM_DISCONN:<hdl>\r\n` (`<hdl>` — 4 шестнадцатеричные цифры). В прозрачном режиме `\r\nIM_CONN\r\n` без параметров передаётся только при установлении первого соединения, а `IM_DISCONN` при отключении не передаётся. Оба режима передают `\r\nIM_READY\r\n`, когда все соединения разорваны. |
| Параметры | `<hdl>`: дескриптор соединения; для BLE отображается внешнее значение с нумерацией от 1 (внутреннее значение отсчитывается от 0 и увеличивается на 1), для SPP — исходный дескриптор. `<mac>`: Bluetooth-адрес удалённого устройства. `<mtu>`: согласованная MTU. |
| Примечания | Передачей управляет `AT+EVT`: при значении 0 (по умолчанию) уведомления передаются обычно, а при значении 1 подавляются `IM_READY`/`IM_CONN`/`IM_DISCONN`. Формат и состав уведомлений зависят от текущего режима работы (командного или прозрачного), как описано выше. |

</div>
