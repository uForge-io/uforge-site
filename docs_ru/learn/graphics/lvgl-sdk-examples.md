# Примеры LVGL для SiFli-SDK { #lvgl-sdk-examples }

Примеры LVGL из SiFli-SDK помогают проверить дисплей и UI, но не являются взаимозаменяемыми шаблонами продукта. Сначала подтвердите базовую работу панели и ввода демонстрацией нужной версии. Затем выберите пример для главного риска интеграции, запустите его без изменений с документированной конфигурацией платы и заменяйте по одному слою. Прежде чем считать пример работоспособной отправной точкой, проверьте статус его верификации и ограничения в README.

В этом руководстве примеры из [указателя LVGL для SiFli-SDK](https://docs.sifli.com/projects/sdk/latest/sf32lb58x/example/multimedia/lvgl/index.html) сгруппированы по инженерным задачам. Актуальный список поддерживаемых плат, конфигурацию SDK, расположение исходного кода и ресурсов, команду сборки и ограничения конкретной версии смотрите на официальной странице.

Указатель — это каталог примеров, а не матрица совместимости плат. Поддержка определяется отдельно для каждого примера; название семейства в URL документации не подтверждает поддержку этого семейства. Проверяйте раздел **Supported Boards** в README конкретного примера. Общая команда сборки или наличие платы в матрице сборки репозитория сами по себе не доказывают, что работа проверена на устройстве. Если источники расходятся, явно указывайте это и сверяйте точную ревизию SDK и плату.

## Выбирайте версию LVGL осознанно { #choose-the-lvgl-version-deliberately }

В официальном указателе есть примеры как для LVGL v8, так и для LVGL v9. Используйте одну и ту же основную версию LVGL в сгенерированном UI-проекте, базовом примере и конфигурации SDK. Не переносите сгенерированный экран или пользовательский виджет из одной основной версии в другую без отдельной проверки совместимости и плана портирования.

Для первого запуска платы используйте демонстрацию или официальный пример, соответствующий версии LVGL, выбранной в конфигурации платы SDK. Так можно проверить панель, буферы, устройства ввода и планирование задач, прежде чем переходить к разработке приложения.

!!! warning "Сделайте резервную копию карты перед использованием примера SJPG для LVGL v8"
    В проекте v8 Official Examples необязательный путь загрузки SJPG с TF-карты вызывает `dfs_mkfs()` для корневой области карты, если монтирование не удалось; это может привести к потере данных. Перед включением и запуском этого пути сделайте резервную копию и проверьте код в используемой ревизии SDK. Не распространяйте это предупреждение на все примеры LVGL v8 или v9: проверяйте логику монтирования и форматирования в каждом проекте отдельно.

## Генерация UI: gui_guider, SquareLine и EEZ Studio { #generated-ui-gui_guider-squareline-and-eez-studio }

Используйте пример инструмента проектирования UI, если команде нужен визуальный редактор для создания структуры экранов, стилей и ресурсов. В указателе есть примеры для **gui_guider**, **SquareLine** и **EEZ Studio**.

Перед включением результата генерации в продукт проверьте версию сгенерированного кода, разрешение экрана, глубину цвета, пути ресурсов и ответственность за функции обратного вызова.

Исходные примеры gui_guider и EEZ Studio явно требуют LVGL v8. Для SquareLine также нужна стандартная тема, используемая сгенерированным кодом. Включите созданные подкаталоги в сборку и выполните документированные шаги необязательного преобразования eZip: одного копирования файлов недостаточно.

Сгенерированный код ускоряет создание UI, но не заменяет драйвер дисплея, планирование буферов, драйверы устройств ввода, политику энергопотребления и интеграционные тесты. Храните сгенерированные файлы отдельно от написанной вручную логики приложения, чтобы повторный экспорт не перезаписал изменения продукта незаметно.

## Виджеты и шаблоны взаимодействия { #widget-and-interaction-patterns }

Используйте специализированные примеры LVGL v8 для проверки отдельных функций UI. Их объём различается: Multlist представляет полноценную демонстрацию прикладного фреймворка, а не минимальный тест виджета.

- **Basechart** строит графики рядов данных; **Baselabel** связывает источники данных с периодически обновляемым текстом.
- **Follow** показывает меню значков, движущихся под действием гравитации; **Select** — состояние выбора; **Sector** связывает значение с видимым угловым сектором изображения.
- **Imgarray** собирает числовые показания из изображений символов; **Imgbar** обрезает изображение переднего плана для отображения прогресса.
- **Mulroller** — настраиваемый через функции обратного вызова роликовый селектор; **Multroller** — более простой вариант для текстовых опций.
- **Multlist** охватывает списки, перелистывание, переходы, кэш ресурсов и жизненный цикл страниц; **Multslider** выводит значение или короткую подпись на бегунке.
- **Multanim** демонстрирует переходы, часть которых зависит от поддержки GPU/VGLite; **Timeline** координирует анимации на общей временной оси.

Поддержка плат у этих примеров также различается. Например, в явных списках **Supported Boards** для Multanim и Multlist указаны `sf32lb52-lcd_n16r8` и `sf32lb52-lchspi-ulp`, тогда как в общих инструкциях ниже упоминаются более широкие цели 52x/56x/58x и `eh-lb563` приводится как пример сборки. Это разные по охвату сведения. Сверяйтесь с README конкретного примера и текущей конфигурацией проекта; не делайте вывод о совместимости остальных виджетов по указателю или URL.

Выбирайте один из этих примеров, если конкретный элемент управления представляет риск для продукта. Первую адаптацию проводите поэтапно: запустите исходный элемент, подставьте данные продукта, измерьте стоимость перерисовки и потребление памяти и только потом добавляйте его на более сложный экран. Даже несколько визуально простых элементов вместе могут создать чрезмерную нагрузку на буфер кадра (framebuffer), пропускную способность чтения графических ресурсов или планирование обработки событий ввода.

## Ресурсы, анимация и мультимедиа { #asset-animation-and-media-workloads }

Примеры Dynamic eZip доступны для LVGL v8 и LVGL v9. Выберите версию, соответствующую приложению, и проверьте динамическую загрузку сжатых ресурсов, прежде чем широко применять этот механизм. В статье [eZip](ezip.md) объясняется роль сжатия ресурсов в графическом тракте.

Для анимированных GIF/APNG SiFli также предлагает примеры [AGIF/APNG + LVGL v8](https://docs.sifli.com/projects/sdk/latest/en/sf32lb52x/example/multimedia/agif/lvgl/README.html) и [AGIF/APNG + LVGL v9](https://docs.sifli.com/projects/sdk/latest/en/sf32lb52x/example/multimedia/agif/lvgl_v9/README.html) в разделе **Multimedia > AGIF**. В обоих README указана `eh-lb525`; текущая [матрица сборки GCC](https://github.com/OpenSiFli/SiFli-SDK/blob/main/build_config_gcc.yaml) также регистрирует оба пути проекта в `devkit_lcd_boards`. Регистрация в матрице означает наличие цели сборки, но не подтверждает работу на каждой плате этой группы. Перед использованием примера как продуктовой основы проверьте конкретную плату и ревизию SDK.

Примеры динамической загрузки eZip сравнивают доступ по пути файла с предварительной загрузкой в SRAM или PSRAM. Предварительная загрузка требует дополнительной памяти и может уменьшить число повторных чтений. Создавайте ресурсы для нужной версии LVGL v8/v9. В документированном варианте v9, в отличие от v8, путь требует префикса диска, например `A:/`. Проверьте используемое хранилище и настройку буквы диска. В README v9 явно перечислены `sf32lb52-lcd_n16r8`, `sf32lb52-lcd_a128r16`, `sf32lb52-lchspi-ulp`, `sf32lb52-core_e8r16`, `sf32lb56-lcd_a128r12n1`, `sf32lb56-lcd_n16r12n1`, `sf32lb58-lcd_n16r32n1_dsi`, `sf32lb58-lcd_a128r32n1_qspi` и `sf32lb58-lcd_n16r32n1_qspi`; не переносите этот список на v8 и не делайте вывод о поддержке других плат. Только для SF32LB57 документация eZip требует опцию преобразования `-winsize 2048`.

[Lottie](https://docs.sifli.com/projects/sdk/latest/sf32lb58x/example/multimedia/lvgl/lvgl_v8_lottie/README.html), [воспроизведение локального видео](https://docs.sifli.com/projects/sdk/latest/sf32lb58x/example/multimedia/lvgl/lvgl_v8_media/README.html) и [потоковое воспроизведение](https://docs.sifli.com/projects/sdk/latest/sf32lb58x/example/multimedia/lvgl/streaming_media/README.html) проверяют разные пути обработки контента, а не образуют фиксированную шкалу сложности. README Lottie помечает пример как **непроверенный**, перечисляет `eh-lb563` и серии SF32LB52x/SF32LB56x; соответствующая запись проекта в текущей матрице сборки GCC закомментирована. Считайте список плат непроверенной документацией, а не подтверждённым набором целей. README локального видео явно указывает `eh-lb523` и `sf32lb52-lcd_n16r8`, но также содержит более общие инструкции по сборке; запись проекта закомментирована в текущей матрице сборки GCC. Перед применением этих сведений к другой цели проверьте конкретную ревизию SDK. Пример воспроизводит видео H.264 из `disk/video_example.mp4`; если TF-карта успешно смонтирована, сначала читается `video_example.mp4` в корне карты. README потокового примера указывает только `sf32lb52-lchspi-ulp`; он использует подключение телефона через Bluetooth PAN для доступа к сети и FFmpeg. Это не пример потоковой передачи видео по BLE.

Оценивайте каждый пример как системную нагрузку. При одновременной работе Bluetooth, датчиков и интерфейса дисплея измеряйте объём хранилища для ресурсов или потока, время декодирования, частоту обновления кадров, использование PSRAM/SRAM, пропускную способность дисплея и потребляемый ток. Реальные затраты зависят от контента, разрешения, настройки декодера и буферов.

Не считайте плавную короткую демонстрацию доказательством того, что система выдержит длительную анимацию. При проверке продукта используйте контент реалистичной продолжительности и фактическую политику обновления панели.

## Шрифты и переключение языка во время работы { #fonts-and-runtime-language-switching }

[Пример FreeType](https://docs.sifli.com/projects/sdk/latest/sf32lb58x/example/multimedia/lvgl/lvgl_v8_freetype/README.html) загружает шрифты TrueType из файловой системы и позволяет менять шрифт и размер во время работы. В README сказано, что пример проверен на `sf32lb52-lchspi-ulp`; для других плат нужны раздел `FS_REGION` и достаточный объём системной кучи, поэтому пример не подтверждает их работу. Он показывает переход на встроенный шрифт при ошибке загрузки, проверку свободной памяти в куче и освобождение предыдущего шрифта при переключении. Проверьте набор символов и расход памяти для реальных языков и размеров; большие шрифты CJK следует сократить до нужных символов. Документированный тракт требует контуров TrueType, а не OpenType с контурами CFF. Нельзя освобождать шрифт, пока на него ссылается виджет или стиль; изменения выполняются в потоке LVGL. После изменения поставляемых шрифтов заново сформируйте и запишите образ файловой системы `fs_root.bin`: обновление только приложения не заменяет эти файлы.

Многоязычные примеры для [LVGL v8](https://docs.sifli.com/projects/sdk/latest/sf32lb58x/example/multimedia/lvgl/multilingual/multilingual_v8/README.html) и [LVGL v9](https://docs.sifli.com/projects/sdk/latest/sf32lb58x/example/multimedia/lvgl/multilingual/multilingual_v9/README.html) охватывают встроенные языки, установку внешних языковых пакетов, переключение во время работы, повторное сканирование каталога установки и сохранение выбранного языка через `share_prefs`. В README v8 указана `sf32lb52-lchspi-ulp`; список целей в README v9 нужно проверить отдельно, не перенося эту плату по предположению. Из JSON или XLSX создаются компилируемые ресурсы для встроенных языков либо двоичные пакеты для внешних языков. Ключи перевода должны совпадать во всех языках, а шрифты должны содержать нужные символы. Проверьте переключение, сохранение выбора после перезапуска, отсутствие ресурсов и обновление файловой системы. Следуйте путям и конфигурации из документации каждой версии; не считайте их одинаковыми только из-за сходства функций.

## Компас, игры и интерфейсы часов { #compass-games-and-watch-interfaces }

Примеры электронного компаса и интерфейса часов объединяют отображение с функциями приложения. На них можно изучать организацию экранов, временные параметры ввода и анимации, а также влияние повышенной графической нагрузки. Указатель игр ведёт на пример «Сапёр». В его README указаны `eh-lb563` и серии SF32LB52x/56x, но не 58x. Перед запуском на 58x проверьте поддержку в используемой версии SDK.

В документированном примере компаса используется трёхосевой магнитометр MMC56x3, подключённый по I2C к `sf32lb52-lchspi-ulp`. Для реального продукта проверьте драйвер, подключение и калибровку: отображение направления само по себе не подтверждает точность измерения.

Примеры игр и интерфейсов часов подходят для проектирования переходов между экранами, но правила владения данными, режимы низкого энергопотребления, включение дисплея, уведомления и восстановление после сбоев нужно определить для самого продукта.

В README часов v8 перечислены LCD-серии SF32LB52x, SF32LB56x и SF32LB58x, а также `sf32lb52-lchspi-ulp`; README v9 перечисляет три LCD-серии. Оба исключают `520-hdk` и указывают, что демонстрация 3D-вращения недоступна на SF32LB55x. При добавлении шрифтов проверьте размеры разделов ресурсов: в примере v8 возможно переполнение выделенной области для шрифтов.
