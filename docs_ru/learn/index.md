# Обзор учебных материалов { #learn-overview }

Используйте раздел **Учебные материалы**, чтобы принять решения по архитектуре и подсистемам до того, как их станет сложно менять в прошивке или аппаратной части. Статьи объясняют, как взаимодействуют блоки SF32 и когда процессору общего назначения следует передать работу графическому движку, контроллеру беспроводной связи, ускорителю ИИ или другому специализированному оборудованию. Здесь также говорится, что нужно проверять, когда графика, беспроводная связь, аудио, ИИ и память используются в одном изделии с учётом ограничений по энергопотреблению.

Для первого запуска платы используйте раздел [Начало работы](../getting-started/index.md), для практических пошаговых заданий — [Руководства](../getting-started/tutorials/overview.md), для рабочих процессов разработки ПО и примеров — [Разработка](../develop/index.md), а для выбора компонентов и проектирования изделия для серийного производства — [Семейство SF32](../sf32-products/family/SF32_family.md).

## Рассматривайте материалы в комплексе { #use-the-pages-together }

В реальном изделии обычно задействовано несколько групп подсистем. Например, в носимом устройстве с дисплеем, BLE и микрофоном, где запас энергии аккумулятора ограничен, эти функции нельзя рассматривать отдельно: обновление дисплея влияет на трафик памяти и время активной работы; расписание Bluetooth — на частоту пробуждений; аудио и ИИ — на буферы и задержки. Каждое решение меняет общий бюджет энергопотребления.

Используйте статьи как цикл проектирования:

1. Начните с главного требования изделия и выбранного устройства. Убедитесь, что его документация подтверждает наличие нужных возможностей дисплея, Bluetooth, ИИ, аудио, памяти и низкого энергопотребления.
2. До интеграции приложения распределите обязанности между процессорами и спланируйте выделение памяти. Определите, где будут размещены рабочий набор данных, буферы кадров, модель и аудиобуферы; код и данные для задач, чувствительных к задержке, размещайте в подходящей памяти с малой задержкой доступа. Используйте специализированные аппаратные блоки, только если их возможности и ограничения интеграции подходят изделию.
3. Перейдите от обзора главной подсистемы к подробным материалам по её реализации. Ссылки на Bluetooth, память и низкое энергопотребление рассматривайте как проектные зависимости, а не как дополнительное чтение.
4. Проверьте всю комбинацию на целевом оборудовании. Используйте рабочие процессы из раздела [Разработка](../develop/index.md) и методики измерений из соответствующих статей раздела «Учебные материалы», чтобы совместно проверить работу функций, задержки, пропускную способность, радиочастотные характеристики и энергопотребление.
