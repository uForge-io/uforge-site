# 电源管理 { #power-management }

电源管理有助于让可运行的原型满足可穿戴设备的续航要求。在 SF32 上，功耗优化涉及系统时钟配置、睡眠模式、显示行为、蓝牙（Bluetooth）连接间隔、传感器中断和应用架构。

不要根据孤立代码片段优化功耗。应测量实际产品场景，包括启动、空闲、已连接但处于空闲状态、显示开启、音频工作、传感器唤醒、OTA 和关机。

## 实用流程 { #practical-workflow }

1. 测量未经修改的 SDK 示例。
2. 每次只启用一个子系统。
3. 初期测量时，分别测试显示、蓝牙、音频、存储和传感器活动。
4. 使用中断驱动唤醒，避免轮询。
5. 按电源模式和产品场景记录电流。

## 可用起点 { #useful-starting-points }

- SDK 电源管理示例。
- CPU 使用率分析。
- RT-Thread Shell 检查。
- 板级电流测量。

## 测量记录 { #measurement-notes }

每次测量都应记录：

- 开发板及其版本。
- 供电方式和测量点。
- 固件分支和构建版本。
- 显示状态。
- 蓝牙状态。
- 传感器状态。
- 日志级别。
- 平均电流、峰值电流和测量窗口。

## 常见功耗问题 { #common-power-problems }

<div align="center"><em>表：常见功耗问题</em></div>

<div align="center" markdown>

| 现象 | 可能原因 |
|:-----|:---------|
| 空闲电流过高 | 轮询循环、日志输出、显示屏电源轨或外设时钟仍未关闭。 |
| 无法进入睡眠 | 定时器仍在运行、设备仍处于打开状态、存在待处理任务或唤醒源未得到处理。 |
| 蓝牙电流尖峰 | 连接间隔、扫描窗口、音频路径或重传。 |
| 显示屏功耗占主导 | LCD 背光功耗、AMOLED 显示内容、刷新策略或局部更新策略。 |
| 测量结果差异很大 | 测试配置、电池状态、USB 电源路径或日志负载发生变化。 |

</div>
