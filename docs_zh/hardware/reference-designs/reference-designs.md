# 参考设计 { #reference-designs }

参考设计用于衔接产品规划与实际开发。一套可复用的软硬件基线，应明确起始硬件、软件版本、可获得的设计文件、启动调试证据和复用边界。这里列出的开发路径帮助你建立并验证这套基线；列入本节，并不代表已提供正式发布的原理图、BOM 或量产适用性验证资料。

请先使用[规划产品](../../sf32-products/family/product-planning.md)形成初步候选方案，再从下方选择最接近的路径来组织开发板验证和产品风险控制。

## 参考设计与项目的边界 { #reference-designs-and-projects }

参考设计回答的是**“可以从哪一套可复用技术基线开始？”**；[项目](../../projects/index.md)回答的是**“如何从该基线出发，完成某个具体产品的集成与发布决策？”**。

<div align="center"><em>表：参考设计与项目的边界</em></div>

<div align="center" markdown>

| 对比项 | 参考设计 | 项目 |
|:-----|:---------|:---------|
| 主要职责 | 可复用的技术基线。 | 围绕具体产品推进集成与发布决策。 |
| 核心证据 | 硬件/软件基线、设计文件或其可获得性、启动调试结果和复用边界。 | 产品决策、依赖、适配阶段、验证门槛和发布证据。 |
| 复用方式 | 读者可将基线用于多个产品，并在此基础上适配。 | 读者围绕一个具体产品按路径推进，并对该产品实施受控的专属变更。 |
| 相互关系 | 链接到采用该基线的项目。 | 适用时链接回其起始参考设计。 |

</div>

## 如何使用路径 { #how-to-use-a-journey }

1. 确认路径的产品重点和所选硬件符合你的设计约束。
2. 在所列开发板上复现软件基线，再开始适配。
3. 将准确的开发板、SDK 版本、示例、构建/烧录命令和串口日志保存在项目记录中。
4. 对每个发生变化的显示屏、存储器件、电池路径、RF 设计、外壳或接口增加产品专用验证。
5. 将结果用于[面向量产的设计](../design-for-production.md)，同时保留所选设计指南、检查清单、AVL 决策、恢复方案和剩余风险。

## 添加新的路径 { #adding-a-new-journey }

将一条路径作为可复现的参考基线介绍前，应明确目标产品和读者、支持的硬件与软件版本、前置条件、源代码仓库、里程碑、验证标准、测量结果，以及如何将结果用于产品适配。如果它仍是规划阶段的开发流程，就应明确标注状态，并列出缺少的证据，不能暗示基线已通过验证。

需要围绕具体产品完成从开发到交付的全过程时，请参阅[项目](../../projects/index.md)。项目应链接到所采用的参考设计，而不是重复列出其硬件基线、设计文件或量产资料。
